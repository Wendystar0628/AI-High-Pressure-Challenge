# 操作系统嵌套

## 一、目标总览

制作一个桌面端的嵌套图形操作系统。根系统提供日常桌面、电子表格、常见小组件和能访问真实外部网页的 Chromium 浏览器；系统内可以继续启动系统，形成有多级桌面和并行分支的系统树。子系统以三维直升机动画、飞行排演和实时数据可视化为主要内容，图表接收根系统电子表格的数据，播放器与图表可以把可交互视图投送到祖先桌面。

子系统由存放在父系统文件系统里的内核程序运行。调度、消息、文件、窗口管理和应用都是系统自己运行的程序，可以打开源文件修改，重启后按新逻辑运行；它们和普通程序一样在逐级拨付的共享资源下竞争。程序、消息、文件、显示、输入和状态保存实际参与运行；暂停一棵子树、恢复快照或从中分叉后，这些关系仍然成立。

三维直升机场景以紫黄配色的 24 号直升机为主角，既有完整的起飞与坠机演出，也能进行飞行排演：直升机靠子系统里被调度的飞控进程保持飞行，预算、调度和飞行输入共同决定飞行过程，过程可以保存回放。

各层桌面采用 Windows 的布局方式与操作逻辑，视觉风格由你设计。操作系统采用自定义的程序与设备模型，不要求兼容现有操作系统，也不要求实现硬件启动、CPU 指令集或完整的通用操作系统。

## 二、系统内容

### 2.1 递归系统树

根系统运行在桌面应用的主窗口中。每个系统都能创建和管理直属子系统。子系统作为父系统中的承载进程运行，这个进程执行子系统的内核程序（2.7），由它调度子系统自己的程序和直属子系统。支持至少四层桌面（包含根系统），同一父系统下可以同时运行多个子系统；创建和管理能力在各层都能从所属桌面使用。

每个实例有独立的进程表、程序状态、虚拟时钟、消息队列、文件系统、桌面和应用状态。根系统面向日常桌面操作，所有非根实例均提供图形与数据应用及配套工具，具体见 2.4 与 2.6；应用分工不限制继续创建子系统。

各层可以新建、启动、暂停、继续、单步、调速、重启和关闭直属子系统，也能为其创建快照、恢复和分叉。管理界面显示父子关系、运行状态与系统归属。默认打开作品时先显示根系统桌面，并提供子系统启动入口。

暂停一个实例会停止整棵子树推进；继续后，后代保留各自原有的暂停或挂起状态。停止实例或结束它的承载进程会停止整棵子树，兄弟子树与祖先系统仍可使用。重启实例时，结束子树内原有进程，重新载入内核源文件，按保留的系统树结构从各实例的初始运行状态重新启动，保留已保存的文件。关闭实例后停止其中全部程序，已保存的快照仍可重新打开。

子系统通过父系统提供的接口取得执行额度、时间推进、输入和显示服务，全部工作受祖先链上的实际拨付约束。宿主可以提供绘制与交互后端，不能在系统调度之外独立推进子系统程序。根系统的 Chromium 网页视图是宿主提供的浏览器设备，其管理要求见 2.5。

### 2.2 各层桌面与美术

每个系统都做成能够实际操作的完整桌面。采用 Windows 的布局方式：桌面上放置应用与文件图标，底部是任务栏，任务栏左侧是开始按钮与固定应用，中部显示运行中的窗口，右侧是系统托盘、时钟和通知入口；开始菜单中可以查找与启动应用。应用窗口的图标与标题在左上，最小化、最大化与关闭按钮在右上。

各实例有自己的壁纸、图标、开始菜单、任务栏、窗口、焦点和通知。子系统桌面完整位于父系统的系统窗口中，递归嵌套，不能只是一块动画画布或监控面板。按 2.15 投送的应用视图另显示为目标祖先桌面上的窗口，子系统桌面与源窗口仍保留。

Windows 只规定布局与操作逻辑，不规定视觉风格。配色、字体、图标、壁纸、材质、边框与过渡由你设计，各层有共同的设计语言，同时能辨认系统归属与层级。桌面、应用、菜单和对话框经过统一设计，图形素材由你自己制作，不直接复制 Windows 的图标、壁纸或界面贴图。根系统的默认壁纸是一张你自己制作的漂亮风景照，随项目交付。

子系统启动后的默认布局中，父桌面与子桌面都可见，动画窗口有足够大的展示面积。文字与操作目标不要过小；多层嵌套、多窗口和兄弟实例同时打开时，仍能辨认所属系统、焦点、运行状态及返回父桌面的入口。

### 2.3 窗口与输入

1. **桌面操作。** 图标单击选中、双击打开；桌面和文件项支持右键菜单，文件列表支持多选。开始菜单可以启动应用，任务栏切换、收起和恢复运行中的窗口。
2. **窗口操作。** 各层窗口支持标题栏拖动、边缘缩放、最小化、最大化、恢复和关闭，双击标题栏切换最大化与恢复，并支持左右半屏贴靠。最小化只改变可见性，程序继续运行；关闭源应用窗口结束对应应用及其协作进程，关闭系统窗口前确认是否停止整个子树。关闭投送窗口只取消该投送，具体规则见 2.15。窗口有正确的遮挡顺序，菜单和弹出框属于对应系统。
3. **嵌套显示。** 子桌面裁剪在父桌面的系统窗口显示区域内，每级嵌套均如此，其中的三维视图同样服从裁剪和窗口遮挡，菜单、对话框和上层窗口盖在它之上；改变任一祖先窗口的大小后，后代布局、绘图与输入仍正确。源窗口的拖动范围限于所属桌面，通过 2.15 的明确操作创建祖先桌面上的投送窗口。
4. **坐标与拖动。** 任意层移动、缩放窗口或调整界面缩放后，后代的二维图形和三维视图点选、窗口拖动、控件拖动和文件投放都对应指针所指的对象，被遮挡的部分不接收输入，拖动总能正常结束。
5. **焦点。** 任一时刻只有当前获得焦点的应用处理键盘输入，按键不触发其他应用或其他系统的快捷键；地址栏、网页、电子表格、编辑器、图表与播放器各自正确接收输入。投送内容的输入按 2.15 送到源应用，投送外框由目标桌面处理。切换窗口、最小化和关闭后焦点随之转移，当前焦点可辨。
6. **网页视图。** 浏览器网页内容与自制窗口一起移动、缩放、裁剪和遮挡，不能悬浮在其他应用之上或穿过菜单与对话框。最小化后网页不再显示，恢复后回到正确位置。
7. **状态反馈。** 暂停、等待、异常、内核错误、配额不足、文件未保存、操作成功和操作失败都有与实际状态对应的反馈。子树暂停时，运行中的祖先和兄弟系统仍可操作。

### 2.4 根系统桌面的常见应用

根系统桌面提供以下应用，功能实际可用，数据与窗口状态属于根系统：

- **文件管理器**：有目录导航、路径与文件列表，支持新建、重命名、复制、移动、删除和打开文件，提供文档、下载与回收站。删除的文件可以从回收站恢复，文件按类型打开到对应应用。
- **电子表格**：提供有行列标题的单工作表、单元格与区域选择、编辑、复制粘贴，以及撤销与重做。公式支持四则运算、括号、单元格与区域引用和 `SUM`；修改输入后，依赖这些输入的公式按依赖关系重新计算，除零、无效引用和循环依赖有明确反馈。可以新建、打开与保存工作簿，保存格式由你定义，重新打开后保留内容、公式和基本格式。未保存修改有标示，关闭或打开另一文件前可以保存、放弃或取消。工作簿使用根系统文件系统，文件管理器可以找到并打开。
- **桌面小组件**：提供时钟与日历、倒计时与秒表、便笺、剪贴板历史、通知中心和快捷设置。可以统一放在小组件面板中，也可以由桌面与任务栏分别打开；功能与数据实际可用，具体要求见下表。
- **文本与程序编辑器**：与 2.6 的编辑器相同，可以新建、编辑、保存并启动程序，也能打开直属子系统的内核源文件。
- **任务管理器**：显示应用、自定义进程、直属子系统承载进程及其父子关系，查看状态、实际工作量、剩余工作、内存占用与错误，执行挂起、继续和结束，调整本系统总预算、内存与存储配额、进程额度与子系统拨付上限。承载进程的读数区分子系统内核自身和它内部的工作。能够区分逻辑进程与浏览器网页视图，不把 Chromium 的工作伪装成自定义指令读数。
- **设置**：修改系统名称、壁纸、强调色和界面缩放，设置实际影响根系统桌面与应用并能保留；缩放后输入命中和窗口操作仍正确。
- **浏览器**：实现 2.5 的 Chromium 浏览器。

桌面小组件至少具备以下功能：

| 组件 | 功能 |
|---|---|
| 时钟与日历 | 显示根系统当前日期与时间，可切换月份、查看日期 |
| 倒计时与秒表 | 倒计时可设置、启动、暂停、继续与重置，到时产生通知；秒表可开始、暂停、复位与记录分段时间 |
| 便笺 | 可新增、编辑、删除多张便笺，内容能够保留 |
| 剪贴板历史 | 记录根系统实际复制的文本与表格选区，可查看、再次复制与清空；表格选区可以作为带制表符和换行的文本使用 |
| 通知中心 | 汇总实际发生的倒计时与文件操作通知，支持已读、清除和免打扰；免打扰时保留记录并抑制弹出提示 |
| 快捷设置 | 可切换主题或强调色、调整界面缩放与免打扰，与系统设置及通知中心使用一致的状态 |

根系统提供直属子系统的创建、启动、暂停、单步、调速、快照、恢复与分叉入口。常用功能从桌面、开始菜单和应用界面即可完成。提供随时可打开的简体中文操作说明。

### 2.5 根系统 Chromium 浏览器

复用现成的 Chromium 内核，浏览器界面由你自己制作，包括标签栏、地址栏、导航按钮与加载状态。浏览器是根系统桌面内的应用窗口，不能跳出作品调用宿主已有的 Chrome 或其他外部浏览器代替。

1. **正常浏览。** 输入网址后实际联网加载网页，网页的 HTML、CSS、JavaScript、链接、表单和滚动正常工作。能够访问 bilibili 等真实外部网站，进行站内浏览、搜索和页面交互，在站点与网络允许时播放普通公开视频；不要求提供账号或绕过登录、验证与站点限制。
2. **导航与标签。** 支持多标签、新建与关闭标签、前进、后退、刷新和停止加载。地址与标题随实际导航更新，切换标签保留各自页面；网页打开新页面时在浏览器内部处理，不弹到作品外。
3. **窗口与生命周期。** 网页视图遵循 2.3 的窗口、焦点与遮挡规则；关闭标签、关闭浏览器或从任务管理器结束浏览器时，释放相应网页视图，其他应用与子系统继续运行。
4. **真实内容。** 不能用网页截图、预制视频、本地仿制网站或只显示地址文字代替真实访问。网络失败和页面加载失败有明确反馈，可以重试。

浏览器的窗口、标签与导航通过根系统服务管理；网页由 Chromium 执行，不要求在自定义程序执行器里重新实现网页引擎。外部网页按真实时间与网络状态运行，不纳入自定义系统的虚拟时间、共享资源和完整快照。加载外部网页的视图不向网页开放宿主文件系统、Node.js 或系统内部对象。

### 2.6 子系统桌面的应用

每个非根系统以三维场景播放器、飞行排演、图表工作台和跨层窗口投送为主要工作入口。播放器实现 2.13 的资源装载与播放控制，运行 2.14 的直升机场景；播放器与图表均支持 2.15 的窗口投送，图表实现 2.16 的实时数据可视化。

各子系统保留文件管理器、文本与程序编辑器和进程管理器。文件管理器支持目录与文件的基本操作；编辑器可以新建、编辑、保存并启动自定义程序，也能打开直属子系统的内核源文件和本系统的飞控程序；进程管理器操作本系统自己的进程表，查看状态、工作量、内存占用、剩余工作、消息与错误，执行挂起、继续、结束和额度调整，并能设置本系统总预算、内存与存储配额和直属子系统拨付上限。程序、场景资源、排演记录与配置从本系统文件系统读取，相关应用使用同一份实际数据。

各子系统同样提供直属子系统的管理入口，可以继续递归创建系统。内核、程序、队列、时间、文件、桌面、播放器、排演与图表共同参与所属子树的暂停、单步、快照和分叉；投送内容仍由源系统的进程产生。对子树的操作不重置范围外的浏览器、电子表格、应用或其他实例。

### 2.7 程序、内核程序与系统接口

**程序。** 程序是可以创建、编辑、保存和重新加载的文件。程序格式由你定义，但要能表达变量与计算、条件与循环，以及下列系统服务：

- 读取本系统的虚拟时间，等待指定时长；
- 启动和结束进程，取得自身身份；
- 向指定进程发送消息，等待与接收消息；
- 读写本系统中的文件，报告执行结果与错误；
- 向所属应用的显示区域提交或更新二维图形和三维场景。

跨层显示、输入和表格数据连接通过明确的系统服务取得，规则见 2.15 与 2.16；子系统程序不直接取得根系统工作簿对象、祖先的可变应用对象或投送窗口的宿主对象。

程序在系统管理的执行环境中运行，其变量、运行位置和等待状态可以保存与恢复。程序通过系统接口取得服务，不能直接访问宿主 DOM、宿主计时器或其他实例的内部对象。界面的绘制方式和程序执行器的内部实现由你决定。程序格式、系统接口与运行方法写入操作说明。

预置累加计算、消息发送、消息接收和持续计算程序，能够从编辑器查看、修改和运行。持续计算程序在循环中不主动等待或让出执行权，用于检验调度。按操作说明新建的程序、改变循环次数与消息内容后的程序同样能运行，不限于预置程序或固定的几组输入。

**内核程序。** 根系统之下的每个系统都由一份内核程序运行。内核程序是存放在父系统文件系统中的普通程序文件，用同一种程序格式写成，由 2.1 的承载进程执行，受父系统调度。子系统的进程表、调度、等待与唤醒、消息投递、文件系统和系统调用分发都写在这份程序里，不是对宿主实现的转调；子系统内的程序由它载入和管理。子系统再创建子系统，就是这份内核程序再启动一份内核程序。只有根系统的内核可以由宿主实现，宿主对子系统只提供程序执行环境和显示、输入设备。

内核程序的工作和普通程序一样消耗执行预算并计入父系统读数，任务和进程管理器分别显示各层内核自身和用户程序的消耗。层数越深，到达用户程序的份额越小；默认配置下四层桌面都可以操作，第四层的程序持续运行。

**修改内核。** 每个子系统对应父系统中一份内核源文件，可以在父系统编辑器中打开、修改和保存，重启该子系统后生效：改变调度策略、增加系统调用、改变消息规则或文件行为，子系统的实际行为相应变化，其他子系统不受影响。内核写坏时该子系统显示内核错误并停止，父系统和兄弟系统照常运行，改回后可以重新启动。

**桌面与应用。** 子系统的窗口管理（窗口次序、焦点、命中判断与输入分发）和文件管理器、播放器、图表工作台是内核启动的程序，经显示接口提交画面、经消息取得输入；修改这些程序的源文件并重启相应应用或系统后，界面与行为随之变化。根系统的桌面和应用可以由宿主实现。

**显示设备。** 宿主提供的显示设备接收二维图形和三维场景。程序把场景资源（几何、材质、贴图、灯光）和每一时刻的场景状态（部件位姿、损坏、相机、粒子发射）作为可复制的数据经系统接口提交，不取得宿主的图形对象；提交和其他系统调用一样经各层内核分发，这部分工作计入相应层的读数。设备按提交的内容和时刻绘制，可以由此展开烟尘、旋翼模糊等画面细节，但不推进场景状态：相同的提交得到相同的画面，两次提交之间画面不变。设备可以用 Three.js 等图形库实现。

**编译器。** 把程序文件转成可执行形式的编译器也是系统内的程序，可以在系统内修改并编译自身，修改后的编译器用于此后启动的程序。

### 2.8 共享资源与分层调度

每个系统在一个逻辑步内有有限的总执行预算，内核、普通程序、文件与数据处理、图形取样等应用服务，以及直属子系统承载进程共同竞争这份预算。给进程设置的额度是其可用上限，不是额外增加的预算；多个进程不能各自重复取得整份总预算。

根系统的预算逐级拨付到后代。子系统本步实际可用的预算受父系统实际拨付与本系统配置共同限制，后代工作逐级计入承载进程，兄弟子树共享父系统剩余预算。调高时间速率、增加系统实例、创建应用或投送视图均不增加逻辑执行预算。调整总预算或承载额度后，固定逻辑步内各任务的实际进展相应变化。

工作量采用可重复核对的逻辑单位，例如执行指令或明确定义的计算步。计费覆盖程序和应用服务的实际工作，工作量随处理规模变化：文件处理、表格重算、图表计算、飞行物理、场景取样与显示提交，以及程序对数据的复制、比较和拼接都按实际规模计费。工作按完成进度付费，预算不足时保留未完成工作，在以后取得额度后续行，结果与完成进度、进程和承载读数对应。宿主的实际绘制与 Chromium 网页执行不计入逻辑预算，这一边界写入说明；应用计算和子系统的窗口管理归对应系统预算。

进程有与执行情况一致的就绪、运行、等待、挂起、结束或异常状态。多个可运行进程在预算较低时仍持续取得执行机会，时间或消息等待在条件满足后继续；持续计算程序即使不主动让出执行权，也受调度限制，不能阻止其他程序与系统控制。任务或进程管理器显示本系统总预算、实际拨付、各进程消耗与尚未完成的工作，计量含义写入说明。

每个系统还有有限的内存和存储配额，同样逐级拨付、兄弟共享。程序的变量、数组、字符串、消息队列，进程和应用的缓存，以及已载入显示设备的几何、贴图、实例和粒子规模占用内存，投送用到的部分计入源系统；文件占用存储，任务或进程管理器显示实际占用。配额不足时分配或载入失败，程序得到可处理的错误或被系统结束。任何程序耗尽资源时，受影响的只有它所在配额范围内的系统，范围外的操作、动画和表格照常。默认配置下第四层也能打开并播放默认场景，各层都能为直属子系统保存快照。

程序异常只影响相应进程，并留下可查看的错误；结束后不再处理消息、修改文件或更新图形。挂起保留执行状态，继续后从该状态运行；结束释放运行资源，再次启动从程序初始状态开始。承载进程停止对子树的影响按 2.1 执行。

### 2.9 虚拟时间与祖先运行状态

各系统有自己的虚拟时钟，可以暂停、继续、单步和调速。子系统时间随父系统逻辑时间与自身速率推进，多级嵌套逐级如此；时间速率与执行预算独立，调快时间不会补发预算。程序读时、等待唤醒、动画、排演、图表过渡与界面时钟均使用所属系统的时间。

暂停一个实例后，整棵子树的时钟、内核、程序、等待、消息处理与应用内容停止推进，恢复时不补进现实经过的暂停时长。祖先的暂停覆盖整棵子树，任何后代的操作都不能越过它；各实例自己的暂停状态彼此独立。单独挂起一个进程不停止本系统时钟或其他进程。

父系统可让暂停的直属子系统执行一个固定逻辑时间步，这次单步覆盖其子树，后代仍遵守各自的暂停状态、时间速率和逐级预算；父系统自身或其祖先暂停时不能发起这次执行。时间步长度在界面与说明中写明，单步后的程序状态、已完成的显示与读数对应；预算不足的图形工作保留进度，完成的各部分对应同一取样时刻。

子树暂停不影响范围外的系统，根系统表格继续编辑与重算，发往暂停子树的更新在范围外暂存，恢复后交付处理。投送到暂停范围外的窗口可以操作外框，应用内容遵循源子树的暂停状态。改变时间速率从当前状态继续，不重新执行已经发生的事件。联网网页按 2.5 的边界运行。

### 2.10 消息通信

进程通过带收件人身份的消息通信。同一发送者发给同一接收者的消息按发送顺序接收；没有消息时可以等待，消息到达后继续。接收方得到的是发送时的值。

消息只交给发送时指定的那个进程实例，身份不跨系统实例、不跨进程生命周期；目标已不存在时发送方得到明确结果。挂起接收进程时，已到达的消息保留，继续后按顺序处理。

消息要参与三维场景、跨层输入和图表数据更新的实际运行，也能够在消息小程序的输出中单独核对。跨层请求与更新带有所属系统实例、目标应用或订阅的明确身份；调用方通过接口传递独立的数据值，不共享可变的应用状态。可以在同一宿主进程内实现这些机制，不要求硬件级隔离；处理时机与状态变更仍由各层系统控制。

以上是预置内核的消息规则，修改内核可以改变它（2.7）。

### 2.11 文件与跨层传递

每个系统有独立的目录树和文件内容，不同实例的同名路径互不影响；工作簿、程序、内核源文件、三维场景资源、场景配置、排演记录与普通文本走同一套文件操作。文件管理器、电子表格、子系统编辑器和运行中的程序看到各自系统内一致的文件状态。

支持在各层文件管理器之间双向拖放文件，包括祖先与后代以及兄弟实例之间；经过多层嵌套窗口投放后，目标仍是所指的系统与目录，投放前显示目标。传递经过相应系统的接口，目标取得一份独立副本；重名时可以取消或确认覆盖，目标存储配额不足时传递失败并给出反馈。

文件复制与 2.16 的实时订阅是两种不同操作：复制的工作簿等文件保持独立；实时图表通过显式建立的数据连接接收更新。

可以把本系统文件保存到本机，再从本机导入。保存与导入通过用户操作完成，重新打开后内容与保存时一致。

### 2.12 子树快照、恢复与分叉

每层可以为运行中或暂停的直属子系统创建快照，保存为父系统文件；可以恢复到原实例，也可以从中启动独立的新子树。快照范围是选定实例及全部后代，保存这棵子树在同一逻辑时点的全部运行状态：系统树结构、内核程序及其运行位置、各进程的状态与变量、调度与未完成工作、虚拟时间、消息与计时等待、内存占用、文件、桌面与应用状态，以及使用到的随机状态。播放器、排演和图表的状态，以及场景资源和相机都在其中；显示设备里的宿主图形对象不属于快照。恢复和重启导入后第一次呈现就是保存时刻的画面，从保存位置续行，不能只重建桌面或从头播放。快照的复制和写入是父系统的工作，按规模消耗父系统的预算与存储配额。

1. **续行。** 消息处理中途、任务只完成一部分、动画形变或图表过渡中途也能保存。同一快照在相同后续输入、逻辑时间步与资源拨付下得到相同的结果，已处理事件不重做，待处理事件不丢失。
2. **范围。** 恢复和分叉只改变选定子树。范围外的文件、表格、桌面、运行状态和拨付配置保持当前值，恢复前产生的跨界画面、场景资源、输入与数据不影响恢复后的子树。跨越范围的关系按逻辑身份对应：范围外的投送外框保持当前位置并继续对应同一源窗口，源窗口不再存在时投送结束；范围内的投送随快照恢复。
3. **分叉。** 分叉子树起初状态相同，随后可分别调速、编辑、通信和操作；各节点使用新实例身份，内部关系指向分叉内的对应节点。分叉和原子树互不影响，范围外的数据连接和投送窗口仍属于原子树，可以另行连接和投送。
4. **文件重开。** 快照可以保存到本机，作品重启后导入，仍能恢复整棵子树并继续运行。

根系统实时数据源不属于子树快照。恢复或分叉后，图表用缓存和已接收的数据续行，连接处于“已恢复，待重新连接”，用户重新连接时建立新连接并取得源工作簿当前的完整选区。

### 2.13 三维场景播放器

播放器从子系统文件系统打开独立的场景资源。资源是数据，不含宿主代码，包含模型的几何与部件层级、材质与贴图、灯光、镜头，以及关键帧或飞行记录形式的时序。格式与打开方式写入说明；材质、部件变换、镜头与时序能在编辑器中修改，说明里有一个最小场景（一个物体、一盏灯、一台相机）的写法。播放器和显示设备的代码里没有这架直升机：更改资源并重新打开后，画面按实际文件内容变化；同一播放器可以打开同格式的其他合法场景，无需修改播放器源码。

1. **播放控制。** 支持播放、暂停、继续、停止并回到开头、重播、逐帧前进，以及循环开关。显示当前时间、总时长、播放速率和播放状态；播放器采用的帧率写明，逐帧操作推进对应的一帧时长，非循环播放到结尾时停在末帧。
2. **进度与调速。** 可以拖动进度条或输入时间跳到任意位置，可以在播放或暂停时调节速率。暂停后跳转仍保持暂停，播放中跳转从新位置继续；调速不让当前画面跳到另一时刻。
3. **准确取样。** 各动画进程正常运行时，同次呈现的机身、旋翼、影子、烟尘与碎片属于同一动画时刻。跳转和逐帧后的第一次呈现就是该时刻的完整画面，只由该位置及之前的过程决定，不依赖之前显示过的画面。
4. **系统驱动。** 播放位置由播放器进程根据所属系统时间推进，图形更新受所属系统调度与系统接口管理。播放速率与系统时间速率共同生效；播放器暂停期间不推进播放位置，继续时不补跑暂停期间的动画。暂停所属子树、单步或恢复快照时，播放器状态、时间读数和实际画面对应，未完成取样遵循 2.8 的预算与续行规则。不能只更新进度条，而让另一段独立动画自行播放。暂停时改变窗口大小、被遮挡后露出或从最小化恢复，画面仍是暂停时刻。
5. **多实例。** 同一场景可以在两个播放器或两个子系统实例中分别打开，各有自己的播放位置、速率、循环、相机、部件损坏和碎片，互不影响；关闭其中一个不影响另一个的画面。
6. **镜头与点选。** 视图可以切换演出镜头、跟随镜头和自由环绕，拖动和滚轮调整自由镜头。相机是应用状态，进快照，不影响飞行。点击视图中的部件，应用显示它的名称和损坏状态；排演中点击地面，可以设为目标航向。

默认演出、排演与记录回放均至少由时序、飞行场景和环境特效三个职责不同的进程协作，时序进程通过消息驱动后两者更新，排演时另有 2.14 的飞控进程。挂起其中一个进程只停止它负责的更新，其他进程继续运行；正常的播放器暂停则停住整段动画。跳转或重新载入后，画面只对应新的播放位置。

### 2.14 直升机场景与飞行排演

场景内容由你自己制作，作为独立资源随项目交付，由 2.13 的播放器运行。主题是一架直升机从停机坪起飞、飞行、失控并坠落，同时提供默认演出与飞行排演。两者使用同一套场景资源、状态演化与图形生成能力：默认演出是资源中预置的一份飞行记录，按记录的控制时序运行，结局不随预算变化；它和其他记录一样可以跳转和续演，转入排演时画面不跳变。

默认演出在 1 倍速下的总时长为 **15 秒**，包含以下完整过程；排演的后续过程由飞控、输入和已发生的状态决定。

1. **停机与启动。** 直升机停在有环境细节的停机坪上，主旋翼和尾旋翼从静止加速，机身产生轻微振动，下洗气流逐渐带起灰尘或吹动附近草叶。
2. **起飞。** 机体离地上升，起落架与地面分开；影子随高度和位置变化，下洗范围与尘土有相应变化。旋翼持续转动，机身有起飞时的倾斜与回正。
3. **飞行。** 直升机前进、转向并有高度变化，机身、尾梁、旋翼和影子的运动一致；环境与构图能够交代航向、高度与空间关系。
4. **失控与下坠。** 出现可辨认的故障征兆，随后机身倾斜、偏航或旋转并持续掉高，运动有加速和惯性，失控到撞击之间连续可见。
5. **撞击与余波。** 机体撞地，局部部件发生形变、断裂或散开，碎片与尘土分批扩散，烟雾逐渐上升并消散；机体与残骸最终停稳，保留清楚的结束画面。

**场景空间。** 场景是完整的三维空间：地形有起伏，两个停机坪、建筑或障碍、树木草地和远景都是有体积的对象。飞行接触发生在看见的这些几何上，改动资源里的地形或障碍，飞行结果相应变化。不要求飞行动力学或碰撞的科研级仿真精度。

**直升机造型。** 采用紫色与黄色配色，以紫色机身和黄色识别涂装形成清楚的主体。机身两侧印有醒目的数字 **24**，贴合机身曲面并随表面受光。模型由可独立运动和损坏的部件组成：连续曲面的机身，透过玻璃可见座椅和仪表板的驾驶舱，舱门与机身分区的接缝，发动机舱与排气口，桨毂与桨叶，尾梁、垂尾与水平安定面，尾旋翼，起落架和连接结构。旋翼围绕正确的轴转动，近距离和任意角度观看都没有缺面、漏缝或穿插。

**材质与光照。** 场景有确定的时刻和天气，决定主光方向和天空颜色。漆面、玻璃、金属、橡胶、地面和草叶的反光与粗糙度各不相同，玻璃透明并映出环境；撞击和燃烧后漆面熏黑，断口露出内部结构。直升机和碎片有实时投影，落在起伏的地面和自身上，旋翼的影子扫过机身，投影随离地高度变化。

**烟尘与碎片。** 下洗气流随旋翼高度和地面材质带起尘土、压倒草叶。碎片是有厚度的部件，沿各自轨迹翻滚、落地、弹跳后停稳，同样有投影。烟和火处在三维空间里：与机体和地形有正确的前后遮挡，随风偏移，火光照亮周围，烟遮住后面的景物。

**镜头。** 场景带一组演出镜头，默认演出按它运镜；起飞、失控和撞击时直升机处在画面主要位置，数字 24 在主要展示阶段可辨认，相机不穿过地形和机体。排演用同样的镜头规则跟随实际飞行，撞到哪里，镜头就到哪里。

**飞控进程。** 排演中的直升机是不稳定的被控对象：机体状态随所属系统的虚拟时间连续演化，不等待飞控，没有控制输入就会失去姿态。保持飞行的是子系统里的飞控进程，它是可以在编辑器中查看和修改的普通程序文件，经系统接口读取带时间戳的传感器值、写入总距与舵面，和其他进程一样竞争执行预算。控制量保持到下一次写入，错过周期的控制不补发。飞控接口写入操作说明，按说明新写的飞控程序同样能驾驶直升机；场景中有第二个停机坪，飞控可以让直升机悬停并降落在上面。

**调度影响飞行。** 预算、调度和时间速率实际影响排演中的飞行：调低任一祖先的拨付、在同一子树运行持续计算或提高时间速率，控制周期变长，机体抖动、发散直至坠毁；及时恢复时可以拉回。修改飞控程序会改变飞行。物理计算落后于虚拟时间时，画面停在已算完的时刻，补算仍按虚拟时间和当时的控制量进行，落后不会变成慢动作。

**飞行输入与结果。** 排演中可以改变风、目标航向与故障触发时机。风和航向影响正在发生的飞行，故障改变旋翼与机体后续运动；机体姿态、位置、旋翼、影子、下洗、落点、损坏与碎片从当前状态连续变化。不同的输入历史和控制时序产生不同的飞行、接触和余波结果，不能只换一条预设轨迹、平移整段动画或在固定时刻显示同一组坠毁效果。撞击与部件损坏对应实际接触的位置和状态。

**记录与回放。** 排演可以作为本系统文件保存和重新打开，记录保留场景资源、初态、实际输入和实际发生的控制时序；重新打开后可跳转到任意记录位置，回放当时的状态与画面，回放结果不随当前预算变化。从同一记录位置可以继续排演并给出不同的输入、预算或飞控程序，分别保存各自连续的后续过程，原记录仍可打开。记录回放与续演使用播放器的进度和播放控制；它是场景文件能力，系统完整快照仍按 2.12 保存整棵子树。

**绘制。** 动态画面用 WebGL 2 或 WebGPU 实时绘制，不能用视频、位图序列或预渲染画面代替；模型和贴图由你自己制作，贴图可以预先生成。几何、材质、动画数据和播放行为分别能在资源文件与播放器中对应，支持暂停、拖动进度、逐帧、调速与快照恢复；不是点击“播放”后只执行一段无法控制的固定表演。

### 2.15 跨层窗口投送

三维场景播放器和图表工作台都有窗口投送入口，可以选择任一祖先桌面，包括跨过中间层直接投送到根系统。目标桌面创建可独立移动、缩放、贴靠和最小化的投送窗口，源窗口继续保留；每个源窗口至多对应一个投送窗口，再次投送聚焦已有窗口，播放器和图表可以同时投送。

1. **执行归属。** 源应用、状态与计算始终属于源系统，工作按 2.8 逐级记入承载预算；目标桌面只承载外框、显示与输入转发，不另启播放器、图表计算或独立动画模仿同步。
2. **显示边界。** 源系统通过显示接口提交可复制的图形或场景数据，三维场景的资源和逐次提交以副本交给目标，目标接收后绘制，不直接读取源系统的可变应用对象，也不搬动源窗口 DOM。源窗口与投送显示同一应用状态：同一时刻、同一机位，不同尺寸各自取景，不拉伸；图表的二维图形在各视图、各实例中正确。
3. **输入往返。** 投送中的播放、进度、飞行输入、镜头拖动、三维点选、图表类型、数据点与数值输入，经接口进入源应用的消息队列，由源进程处理后提交新显示。投送窗口移动、缩放和贴靠后，坐标、拖动和键盘路由仍正确，一次输入只执行一次，且只作用于发出输入时对应的那个应用。
4. **暂停与可见性。** 最小化源桌面、任一中间系统窗口或源应用窗口不停止源进程，投送继续更新；暂停源系统或它的任一祖先时，应用内容冻结，投送控件禁用并提示原因。若目标桌面仍运行，其投送外框与其他应用仍可操作，恢复后从原状态继续。
5. **关闭与隔离。** 关闭投送只取消视图，源应用继续运行并可再次投送；关闭源窗口、结束源应用或停止包含源应用的子树时，对应投送结束并给出反馈。来源标识显示系统层级与应用，同名应用不串用画面或输入。
6. **快照联动。** 恢复与分叉后的投送遵循 2.12。

显示与输入可以使用自定义消息、消息通道或其他宿主传输方式；宿主负责交付数据和实际绘制，不能绕过源系统调度推进应用。投送外框归目标系统，应用内容与交互结果归源系统，这一边界写入操作说明。

### 2.16 实时数据可视化

任一深度的子系统均提供独立的“图表工作台”，从根系统电子表格显式建立实时数据连接。用户选择一个已打开的工作簿和矩形区域，指定标签列与一个或多个数值列，生成分组柱状图或折线图；两种图表可以切换，标题、坐标轴、图例、数据值与悬停或选中反馈清楚。能使用评审新建的工作簿与区域，不限于预置数据。

1. **初始数据与更新。** 建立连接先取得所选区域当前的完整值，之后每次提交单元格或区域编辑、粘贴、撤销或重做并完成公式重算后，发布该区域的新版本。图表看到的每个版本都是一次提交重算完成后的完整选区；未保存的修改同样发布。
2. **明确的数据边界。** 连接按工作簿文档身份与选区建立，数据通过系统服务以副本跨层传递，子系统保存自己的数据，不绑定根系统表格的对象或宿主 DOM。图表显示的版本只前进不后退，断开的连接不再改变图表。
3. **子系统实际处理。** 数据接收与图表更新是职责可区分的子系统进程，通过消息协作，正常取得执行机会后才处理数据、计算坐标和提交图形。图表过渡使用子系统虚拟时间，源窗口与投送窗口显示同一结果。进程状态与工作量对应实际接收、处理和绘制工作。
4. **暂停与积压。** 暂停目标系统或其祖先子树时，根系统表格仍可编辑和重算，更新在范围外按序暂存；继续后交给子系统按序处理，图表最终对应最新的已处理版本。单独挂起接收或图表进程时，其他进程继续执行，已接收的消息保留。
5. **连接生命周期。** 可以主动断开和重新连接，断开后保留最后的图表与数据。关闭源工作簿时明确提示数据源已关闭，保留已接收数据；源工作簿重新打开后由用户重新选择连接。关闭图表或停止包含它的子树时释放相应订阅。不同图表与实例的连接、数据和选择状态彼此独立。
6. **快照与分叉。** 数据缓存、已处理版本、已进入子系统的待处理消息和图形过渡参与完整快照，恢复、重新连接与分叉遵循 2.12。

### 2.17 自动化约定与录制准备

操作演示由出题人安排的外部 AI 连贯地操作和录制，把各层桌面和应用流畅地逛一遍：根桌面、文件管理器、电子表格、设置、小组件与浏览器，表格数据连到后代系统的图表并投送回根系统，再将场景文件传入深层子系统，把播放器投送到根系统，完整播放一次直升机动画。作品仍需实现题面规定的其他应用与功能，录制方按展示主线选用，不要求逐项演示，也不单独展示内核修改、飞行排演、进程表、消息队列、快照或分叉等内容。

不要求你编排自动演示、制作录屏工具、视频编码器、逐帧导出接口或交付视频文件。作品只需提供下列便于启动、定位控件和操作的约定。

录制方可以在正式镜头前通过正常界面打开窗口、定位素材和填写连接参数；正式镜头中的连接、修改数据、拖拽、投送和播放仍通过界面实际操作。无需为录制另设一套运行状态或特殊演示入口。

**启动与初态。** 启动入口支持传入 `--data-dir`、`--width`、`--height`，分别指定独立测试数据目录和作品主窗口客户区的尺寸。自动化使用的连接方式在根目录 `automation.json` 中写明；Electron 可通过 `--remote-debugging-port` 提供连接，其他承载环境提供等效方式。数据目录之间相互独立，不把运行数据写回项目源码目录。

初次启动显示正常根系统桌面，不自动播放演示。所有非根实例按全局创建顺序命名为 `inner-1`、`inner-2` 等，根系统标识为 `outer`；层级通过父系统关系表达。每层已有的示例程序和直升机场景资源实际存在，能从文件管理器找到；根系统提供示例工作簿与用于跨层传递的场景源文件，子系统可以保留一份预置场景副本。资源的逻辑名称与实际路径写入清单，文件扩展名可以按所用格式确定。

各层的内核源文件、编译器和飞控程序同样实际存在，能从文件管理器找到，路径写入清单的 `fixtures`。

示例工作簿的 `A1:D4` 为以下内容，D 列保存公式，便于打开后直接操作。图表工作台仍应支持其他工作簿、区域和数据。

| 行 | A：项目 | B：数量 | C：单价 | D：小计 |
|---|---|---|---|---|
| 1 | 项目 | 数量 | 单价 | 小计 |
| 2 | 项目 A | 24 | 6 | `=B2*C2` |
| 3 | 项目 B | 12 | 8 | `=B3*C3` |
| 4 | 项目 C | 18 | 4 | `=B4*C4` |

`automation.json` 使用版本号 `1`，至少记录启动命令与参数、主窗口定位方式和素材路径，例如：

```json
{
  "version": 1,
  "launch": {
    "command": "npm",
    "args": ["start", "--", "--data-dir", "{dataDir}", "--width", "{width}", "--height", "{height}", "--remote-debugging-port={port}"],
    "cwd": "."
  },
  "mainWindow": { "title": "Nested OS" },
  "fixtures": {
    "outer": { "workbook": "/Demo/sample.sheet", "chartRange": "A1:D4", "helicopter": "/Demo/helicopter-24.scene", "documents": "/Documents" },
    "inner": {
      "helicopter": "/Demo/helicopter-24.scene",
      "documents": "/Documents"
    }
  }

```

这是一份格式示例；命令、窗口标题与素材路径按实际项目填写。大括号中的值由录制方传入，子系统素材路径指新建实例中的预置路径。

**准备与状态接口。** 在主桌面渲染上下文提供以下接口；其他技术提供等效的可脚本访问接口，并在清单中说明访问方法：

```js
window.bench.version       // 1
await window.bench.ready() // 桌面已呈现并可操作
await window.bench.reset() // 在当前测试数据目录内恢复初态，完成后桌面已呈现
await window.bench.inspect() // 返回窗口、网页加载与应用状态，便于外部 AI 操作
```

`reset()` 在录制开始前关闭应用与全部子系统实例，恢复当前数据目录的预置文件、默认设置和根系统桌面，并重置实例编号。正常录制通过桌面和应用界面操作。

`inspect()` 提供以下便于操作的信息，没有对应实例时返回空数组：

| 字段 | 至少包含的实际信息 |
|---|---|
| `systems` | 系统的 `id`、`parentId`、`name`、`state`；根系统的 `parentId` 为 `null` |
| `windows` | 窗口的 `id`、`systemId`、`appId`、`title`、`state` |
| `browsers` | 标签的 `windowId`、`tabId`、`url`、`loadState` |
| `players` | 子系统源播放器的 `windowId`、`systemId`、`state`、`position`、`duration`、`rate`、`scene`（场景文件路径）、`frameTime`（当前画面所属的时刻）；时间单位为秒 |
| `charts` | 子系统源图表的 `windowId`、`systemId`、`sourceTitle`、`range`、`chartType`、`connectionState` |
| `projections` | 投送窗口的 `windowId`、`systemId`、`sourceSystemId`、`sourceWindowId`、`sourceAppId`、`state` |

这些信息用于找到源窗口、投送窗口、数据连接入口，等待网页加载和安排播放操作，不要求提供内核审计、数据更新日志或录制步骤日志。

**稳定控件标识。** 自制界面的关键控件具有可访问名称与稳定的 `data-testid`，原生控件使用等价的自动化标识。控件标注所属 `data-system-id`；属于应用窗口的还标注 `data-window-id`，窗口容器同时具有 `data-app-id`。标识与文字、颜色、位置无关，同一系统、窗口内的同名操作唯一。应用标识使用 `files/spreadsheet/widgets/editor/browser/tasks/settings/player/charts/projection`；根系统电子表格使用 `spreadsheet`，小组件面板使用 `widgets`，子系统文本与程序编辑器使用 `editor`，进程管理器使用 `tasks`，图表工作台使用 `charts`。

根系统的编辑器同样使用 `editor` 及其控件标识。

录制方通过这些约定操作整个桌面，按熟练使用者操作电脑的速度制作一段完整的操作演示。鼠标轨迹、简短的功能失败提示与剪辑由录制方制作。录制对象是整个根系统桌面及其中显示的子系统桌面、投送窗口和应用内容，不单独导出网页、场景或投送画面；作品适应窗口尺寸，最高可能到 3840×2160。

## 三、要做到什么

### 3.1 执行关系真实

进程管理器、预算与内存读数、暂停控制、消息输出、文件变化、图表、排演与投送反映同一套实际执行。内核、普通程序、应用服务与多级承载共同受预算限制；增加数据、文件、场景或图形规模后，计量与未完成工作仍对应。新增程序、改变循环与消息内容、连接新工作簿、修改内核或继续创建后代系统后，这些机制仍成立。

### 3.2 竞争与隔离同时成立

持续计算、计时等待、消息等待、图表与飞行场景混合运行时，各进程持续取得执行机会。暂停或停止中间节点、内核错误和资源耗尽的影响限于相应子树或配额范围，兄弟子树与祖先控制继续可用；调速不增加预算，投送不转移应用计算，宿主浏览器设备的执行边界清楚。

### 3.3 保存后的状态与因果成立

子树快照的内核、进程、消息、未完成任务、文件、桌面和画面一致，恢复与分叉不改变范围外的系统。排演记录重开与跳转还原实际输入和控制时序造成的场景状态，从同一位置续演能形成不同后续；它与系统快照是各自可用的保存能力。

### 3.4 嵌套交互对应正确对象

多级系统窗口、兄弟实例与投送经过移动、缩放、贴靠、遮挡、最小化和恢复后，坐标、焦点、文件投放与控制仍指向正确对象。快照恢复和分叉后，窗口、消息、数据连接与场景资源的引用仍对应正确的实例。

### 3.5 界面与系统行为一致

文件管理器、电子表格、小组件、编辑器、进程管理器、图表与播放器都是所属系统状态的视图，相关视图随操作更新。表格公式与发布版本一致，通知来自实际事件，播放与排演读数对应画面，投送对应源应用；关闭源窗口、取消投送、结束进程、暂停子树、内核错误和恢复实例各有自己的含义，错误提示与操作说明对应实际行为。

## 四、交付与运行环境

1. 交付一个 Windows 桌面项目，使用 Electron 45.2.1（本机已备好，`npm install electron@45.2.1` 不用另外下载）或其他可嵌入 Chromium 内核的桌面承载环境。根目录提供启动说明和一个明确的启动入口；Electron 项目提供 `package.json` 并支持 `npm start`，其他环境提供等效的单一启动命令或启动文件。交付源代码，不要求制作安装包。
2. 系统自身的代码、字体、图标、壁纸、应用、三维场景和演示资源随项目交付，断网时各层系统及本地应用仍可运行；根系统浏览器允许联网加载真实网页。可以使用现成 Chromium 内核与库（包括 Three.js 等图形库，打包进项目），不得直接套用现成的完整桌面系统或浏览器成品界面。
3. 本题只做 PC 端，不考虑手机和平板，所有操作用鼠标和键盘完成。界面使用简体中文，本机装有多种中英文字体，可以自行挑选合适的使用。
4. 评测在本机进行：CPU 为 Intel Core i7-14700KF，显卡为 NVIDIA GeForce RTX 4080，内存 64 GB。
5. 程序格式、系统接口、内核源文件的位置与修改方法、飞控接口、预算与配额计量、场景资源与工作簿格式、排演记录、数据连接、投送和操作方法写在项目内的说明中，并能从桌面打开。预置程序、内核源文件、飞控程序、示例工作簿、直升机三维场景与配置均随项目交付，根目录提供 2.17 规定的 `automation.json`。
6. 运行环境的几处限制：
   - Chromium 每个渲染线程同时活跃的 WebGL 上下文有上限（主线程约 16 个，Worker 更少），超出时最久没绘制的上下文被丢弃，对应画面消失。同时打开的三维视图超过这个数时，画面仍要全部正确。
   - 图形上下文可能丢失，丢失后画面从系统状态恢复，程序和播放位置不受影响。
   - 评分和录制时，主窗口可能被其他窗口完全盖住。Windows 下 Chromium 会把被盖住的窗口当作隐藏，`<webview>` 等独立网页内容会变空白，动画帧回调可能停止。作品不能因此停止运行、停止绘制或留下空白画面。
