## 已定的设计系统（必须遵守）

`tokens.css` 是唯一的样式来源。每张图都 `<link rel="stylesheet" href="../tokens.css">`，只用其中的变量，不另起颜色和字体。

- **主题意象：田径六项全能。** 本项目名叫 Hexathlon：6 个类别就是 6 个比赛项目，限时就是计时，评分就是记分牌。装饰和结构从这里取：
  - 跑道分道线（细横线、道次编号）；
  - 计时刻度（分钟刻度尺）；
  - 起跑线和终点线；
  - 记分牌式的数字（Bahnschrift）。

  装饰放在边缘和留白处，显著度最低，不压在内容上。不画奖杯、火炬、运动员小人，不放表情符号。
- **字体：**
  - 中文用 `var(--font-cn)`（鸿蒙黑体）；
  - 数字、英文标题和分值用 `var(--font-num)`（Bahnschrift），并加 `.num` 类，用等宽数字；
  - 字号按层级：图标题 22–28，组标题 16，正文 13–15，刻度 11–12。不要用全大写的英文眉标。
- **配色（按角色）：**
  - 结构色只有一个，就是深墨色 `--ink`，用于标题、坐标轴、焦点和主要线条。
  - 6 个类别色只表示类别，全图统一：
    - 深度推理 `--reason`，紫；
    - 算法竞赛 `--algo`，青；
    - 复杂交互应用 `--interact`，赭黄；
    - 游戏设计与开发 `--game`，玫红；
    - 物理建模与仿真 `--physics`，绿；
    - 视觉设计与渲染 `--visual`，蓝。
  - 大面积的形状用对应的 `-tint` 极浅底，再配同色的饱和描边或标记；饱和色只用在线、点、小色块和关键数字上。
  - 不承载类别含义的图（例如计分示意），只用墨色和灰阶，不借用类别色。
- **画面：**
  - 每张图是一张白色卡片（`.frame`，圆角 18，细边框），卡片外透明。这样在 GitHub 浅色和深色主题下都能看。
  - 内部块用圆角 8。
  - 不用渐变铺底，不用大片彩色，不用千篇一律的同款卡片阴影。
- **尺寸：**
  - 宽一律 960 CSS 像素，高按内容定，写在 `<meta name="size" content="960xH">` 里。
  - 渲染时放大 2 倍，README 中显示宽度约 840–900，所以正文不能小于 13px。
- **数据必须精确：**
  - 权重写 8.75%、4.375%、17.5%，不四舍五入；
  - 限时、分值、锚点都取自题面和 README，不编数字；
  - 条形长度、位置要按真实数值成比例，用位置和长度编码数量。
- **避免生成感很强的套路：**
  - 一行标题里只给一个词换色；
  - 用 “A · B · C” 拼信息串；
  - 每个标题上都加小标签；
  - 01/02/03 编号（真实的先后顺序除外）；
  - 文字后面加 “→”；
  - 千篇一律的圆角卡片网格。

## 工作方式

1. 图的源文件写在 `figs\<名字>.html`。
2. 运行 `python render.py <名字>` 渲染到 `E:\Project\AI_OneShot_Bench\assets\readme\<名字>.png`。
3. 用 Read 工具打开生成的 PNG 亲眼检查：
   - 中文是否截断；
   - 有没有重叠、溢出；
   - 对齐和留白；
   - 颜色含义是否一致。

   不满意就改，至少自审一轮再交。照 frontend-design 的要求，交之前“对镜子看一眼，摘掉一件饰品”。
4. 只写自己负责的图，不要改 `tokens.css` 和 `render.py`。确实需要新的通用样式，就写在自己的 HTML 里，并在回复中说明。
5. 不要修改仓库里除 `assets\readme\<你的图>.png`（以及要求你产出的 svg）以外的任何文件，不要提交。
