## 一、各库调研

查证方式：npm 包的 `package.json`、发布目录和类型声明（unpkg），官方 README 与更新日志，`npm view` 查版本日期。没有在本机安装这些库、实际双击运行。下载并运行第三方包需要用户在对话里同意，本次没有得到，所以 file:// 一栏是按包的内容和 Chrome 的规则推断的。

### 1. 两个主要候选

| 项目 | Jolt（`jolt-physics`） | Rapier（`@dimforge/rapier3d-compat`） |
|---|---|---|
| 版本 | 1.1.1，2026-10-23 发布；C++ 原库最新发布版为 v5.6.0，对应关系未核实 | 0.21.0，2026-09-25 发布，对应 Rust 版 0.36 |
| 包的形态 | 只有 ES 模块（`export default Jolt`），源码里引用了 `import.meta.url`。wasm-compat 版 3.23 MB，WASM 以 base64 嵌在 JS 里；wasm 版的 `.wasm` 是单独文件；另有 asm.js 版（5.48 MB）和多线程版 | 只有 ES 模块 `rapier.mjs` 和 CommonJS `rapier.cjs`，各 4.34 MB，WASM 以 base64 嵌在 JS 里，用前须 `await init()`。官方文档仍写它是 UMD 包，但现在的发布目录里已经没有 UMD 文件。另有 SIMD 版和确定性版 |

| 打包 | 需要，例如 esbuild 打成 IIFE。`import.meta` 打包后会变空，Jolt 源码对此有 try/catch，预计无碍，但未实测 | 需要，同上 |

| 关节、绳、滑轮、弹簧 | 固定、点、铰链、滑轨、距离（可设上下限和弹簧，能当绳或弹簧用）、锥、摆扭、六自由度、路径，以及**滑轮**（两物体经两个固定点相连，长度可带比例，可设松弛范围）、**齿轮**、**齿条**。另有软体（顶点与刚体相互碰撞） | 固定、球铰、铰链、滑轨（可设限位和带刚度、阻尼的马达）、**绳**（最大长度）、**弹簧**（静长、劲度、阻尼）、通用关节；另有多体关节（约化坐标）。0.21 新增软体（绳、布等，可挂到刚体上、只受拉，可撕裂），刚发布一个月。没有滑轮和齿轮 |

### 2. 其他库

| 库 | 结论 |
|---|---|
| cannon-es 0.20.0 | 2022 年后没有更新。纯 JS，只有 ES 模块和 CommonJS，同样要打包。没有锥体和胶囊，没有连续碰撞检测和滚动阻力；距离约束是刚性的，做不了松绳；高斯-赛德尔迭代求解，大质量比和堆叠表现差。不适合本题 |
| Ammo.js（Bullet 2.82） | 有滚动和自旋摩擦、连续碰撞检测、六自由度弹簧约束，还有能挂到刚体上的软体绳。但 npm 上的 `ammo.js` 停在 2016 年的 0.0.10，新构建只在 GitHub 仓库里，而本题规定不得访问 GitHub。asm.js 版用普通 `<script src>` 双击就能跑；wasm 版要单独 fetch `.wasm`，双击会被拦。需要手动管理内存，求解器较老 |
| Oimo.js / OimoPhysics | 多年未更新（OimoPhysics 1.2.2 发布于 2020 年），功能有限，没有细查 |
| Havok（`@babylonjs/havok` 1.3.14，MIT 许可） | 有 UMD 和 ES 模块，但 `.wasm` 是单独文件，双击时要自己嵌入。接口是为 Babylon.js 插件设计的底层 C 风格接口，单独使用不顺手 |
| PhysX 网页版 | `.wasm` 也是单独文件，接口繁重，没有细查 |

### 3. 选择理由

- **Jolt 在本题略占优的地方**：
  - 2.5 第 3 条要求“各材料间的静、动摩擦系数和恢复系数”，Jolt 能逐个接触改写这些系数，Rapier 的 JS 版做不到。
  - 第 4、8 环的绳经滑轮，Jolt 有现成的滑轮、齿轮和齿条约束。
  - 空中翻转有明确的开关。
- **Rapier 占优的地方**：接口好用、不用手动释放内存，整个世界一次存档恢复，有绳和弹簧关节，还有确定性版本。
- **为什么不点名**：差别都落在具体用法上，强模型看过接口就能自己选。它不像 AE 题的 WebGL 2 和 Canvas 2D 那样有数量级的差距。所以题面只写“例如 Jolt、Rapier”，不指定，Jolt 排在前面。
- **为什么不举 cannon-es、Ammo.js 作例子**：前者缺连续碰撞检测，大质量比时也不稳；后者的新版本只能从 GitHub 取得。举它们作例子，等于把模型引向不合适的库。

### 4. 库做不了、模型仍要自己做的

- **液体**：多容器之间流动的水、浮力，水量和重心并进容器，晃荡的反作用，波纹推动漂浮物。两个库都没有流体；Jolt 只有平面水面的浮力辅助函数，按新题面不能用。
- **光学**：光路、反射、折射、色散和全反射。
- **库与自写液体在同一个固定步长里推进**：存档和重放要把液体状态一起存下，否则做不到 3.2 第 4 条的“重放与连续播放一致”。
- **能量账本**：库不给分类耗散，碰撞、摩擦、液体阻力和阻尼各自的耗散，要模型从接触冲量和速度自己算。
- **连锁调校与整件作品**：交接、跨系统耦合的稳定、调参不断链，以及画面、界面和声音。

- **3.1 仿真推动**：交接由物理过程完成，不用脚本、计时器或预设动画触发；静止的物体不能是固定住等着触发；不设看不见的墙和力场。

## 六、需要出题人留意

1. **静、动摩擦和材料配对系数**（2.5 第 3 条）没改，但它和库的能力直接相关。
   - Jolt 用接触回调能做到。
   - Rapier 的 JS 版只有每个碰撞体一个系数和四种合成规则，用它的模型只能近似。
   - 指南“参数生效”一项里写着“面板值被截断、替换的不算生效”，用 Rapier 的作品会在这里失分。
   - 如果不想让库的选择在这里拉开分数，可以把要求放宽成“各材料的摩擦系数”。
2. **Jolt 自带的浮力函数按新规则不能用**。
   - 题面写了“浮力由你自己实现”，用了 `ApplyBuoyancyImpulse` 的部分，按指南算“借用现成仿真”，不计入完成份额。
   - 如果想允许用它，要改第四节第 3 条。
3. **光路求交的边界没写死**。
   - 题面只写“光路的计算”由模型自己实现。
   - 用库的射线查询找光线打到哪个刚体，算不算借用，两位评分员可能判断不一。
   - 我的理解是：反射、折射、色散和与水面的求交必须自己写，和刚体几何的求交用库查询可以接受。如果要统一口径，可以在指南里加半句。
4. **物体休眠**：两个库默认会让静止的物体休眠。我在指南“液体耦合”里加了半句：受力或接触时立即恢复的不算冻结。题面 3.7 第 1 条“能继续响应受力和接触”已经是这个标准，没有改题面。
5. **五球摆**：迭代求解器处理几颗紧贴的球时，常常不能逐颗传递撞击，用了库也不会自动做对。指南“各机制的现象”要求逐项核对，会在这里体现。
6. **空中翻转**：Jolt 默认不算陀螺力，要打开开关；Rapier 按更新日志默认就有。没打开的作品会在“各机制的现象”里失分。
7. **file:// 未实测**。
   - 建议正式跑之前花几分钟做一次双击冒烟测试：把 `jolt-physics` 的 wasm-compat 版和 `@dimforge/rapier3d-compat` 各用 esbuild 打成 IIFE，放进一个 `index.html`，双击打开，看 `init` 能否完成、能否推进一步。
   - Jolt 的多线程版在双击下确定不能用（需要 SharedArrayBuffer）。题面没有提，模型会自己碰到。
8. **新旧结果不可比**：之前 Opus 和 Fable 的作答按旧规则（禁用物理库）进行。如果要重评或横向比较，要注意“物理正确”的分项分值从 8/6/4/3/5 改成了 5/7/5/3/6。
9. **没有改的地方**：
   - 半程提醒（`orchestrator\reminders.json`）没有提到物理库，不用改。
   - 评分员提示词 `grader-prompt.txt` 已经有“双击打不开时酌情扣分，再用本地服务器评”的通用规则，不用改。
   - 限时没有动。
