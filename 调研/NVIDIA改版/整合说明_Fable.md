# NVIDIA B200 改版 · 整合说明（Fable）

2026-10-30。对应草稿：`题面草稿_Fable.md`（已覆盖现行题面）。本文只说明怎样把三份报告合成一个作品、替出题人拍板了什么，不重复题面内容。

> 出题人审后的改动：去掉《下一个词》与“章标题即回答句”的写法，章标题改为直白主题名（输入与封装、封装与双芯片、HBM3e 显存与带宽、张量核心与 FP4、注意力与 KV 缓存、NVLink 与多卡互连、训练、生成推理）；回答栏保留为画面元素，每章由模型生成一句说明本章计算的话，文字由作答者自拟；规定第 7 条换成只在剩余 10 分钟提醒一次；按第五节的三处删减把篇幅压到现行的 1.10 倍（33,341 字节）。下文第一至三节中涉及作品名和标题句的描述是审前的记录。

## 一、主线怎样串起来

主线取主线稿的「一句回答」：页面开头提问「B200 是怎样算出下一个词的？」，八章标题就是模型逐章写出的回答，每章画这一段所说的计算在 B200 的哪个部件上怎样发生。三维稿的「生成栏」并进这条主线：它的「每出一个词元，封装上走过一拍」升级为全页规则（2.2 节拍），这样 01 的封装、02 拆开的封装、03 的读取、08 的续写用的是同一套动作，AI 与芯片在每个三维画面里都同时在场。主线稿的倍率读数、字格线母题、回答栏和走线图保留，作为串联八章的结构。

八章的骨架按主线稿，三维内容按三维稿填入：02 一章容纳三维稿的爆炸图、剖析台、剖切、推近接缝、合成一颗（压平为转弯一）；03 的横向段容纳三维稿「每生成一个词」的慢放读取（打开的堆栈、扫描线、KV 缓存带）和主线稿的权重流、读一遍、带宽大字；06 保留主线稿的单卡、平台、机柜拉远；07 训练、08 续写加速按主线稿。技巧清单稿的效果按「观众看得到什么」转写后嵌在各章里，没有单独立章。

## 三、替出题人拍板的选择

| 问题 | 选择 | 理由 |
|---|---|---|
| 作品名与提问句（主线 1） | 用《下一个词》和八章标题原文；回答文字可译成作品语言 | 一句回答本身就是 AI 行为，直接满足「AI 与 B200 融为一体」 |
| 横向段放 03 还是 05（主线 2） | 03 | 保留现行「横穿两颗硅片」的定调；05 的连线在纵向版面里已能表达长上下文 |
| HGX 平台加网络，还是 NVL72（主线 3） | HGX B200 平台，服务器之间走网络 | 72 卡 NVLink 域属于 GB200 NVL72，题材不偏到 GB200 |
| 训练章保留与位置（主线 4） | 保留，放 07 | 它是高潮二，放前面后半程缺少上扬 |
| 倍率读数（主线 5） | 写进题面，只给数量级，注明示意 | 把「加速感」变成全页结构，数量级不作事实考核 |
| 全页精度（主线 6） | 保留，作用于 02 全开、03、05、06、08 和节拍 | 一处改选牵动多章，是低成本的联动 |
| 转弯的写法（主线 7） | 压成一段，保留「速度等于滚动速度、方向连续旋转、中途构图完整、原路退回」 | 这四条是观众能验证的，其余细节交给各章末尾 |
| 美术方向（主线 8） | 暗场版图，不加明场；精度三色钴紫 / 青 / 荧绿，可操作用亮白取景框 | 明场原本服务应用章，应用章已删；07 的三维机房在亮底上光照风险高 |
| 评分表连带改动（主线 9） | 已在草稿第十二节改好 | 见第四节对照 |
| 顶盖（三维 1） | 不建顶盖也不建散热器，爆炸图 6 层从显存堆栈开始 | 顶盖有无尚无定论；散热器属于模块不属于封装，少一层也省工时 |
| 显存排布（三维 2） | 只写「每颗硅片配 4 个」，不写上下排 | 排布只来自图片印象 |
| 生成栏（三维 3） | 采用并升为全页主线，与「一句回答」合并；三组问答不单独用，「每词一拍」全页通用 | 两份报告的核心设计正好互补 |
| 固定段数量（三维 4） | 三处：02 剖析台、04 精度对比、06 平台；操作台并入剖析台 | 四处固定段会拖慢节奏，拖开接缝放进剖析台不损失内容 |
| 推近方式（三维 5） | 滚轮始终滚动页面，推近靠双击和键盘；不开 Ctrl 滚轮 | 避免滚轮语义冲突 |
| 剖切（三维 6） | 随滚动推进，不做交互 | 减少选得准的边界情况，剖析台已有足够操作 |
| 精度对三维段的反应（三维 7） | 写进题面：权重格大小密度、方块数量、节拍长短 | 都是观众看得到的变化 |
| 数字（三维 8） | 确定的写死：片间互连每秒 10 TB、2080 亿晶体管、NVLink 每颗 GPU 每秒 1.8 TB、FP4 值域与三种位格划分；容量、带宽、算力峰值写「用公开资料中的数值」 | 按「不确定的数字不写死」 |
| 贯穿对象（Sol 1） | 不单独用「数据块与连接关系」做主线，由字格线母题吸收；取消唯一光粒与徽记 | 一句回答已是过程线，再加一条物体线会回到被意象牵着走 |
| 剖切与检查窗二选一（Sol 2） | 两者各留一处：剖切随滚动在 02，检查窗即 03 的放大镜；不做任意剖切 | 各自只出现一次，不叠加 |
| 08 生成回路还是 MoE（Sol 3） | 逐词生成回路，与主线稿的续写加速合并 | 与 05、03 的联系更直接 |
| 取消对雾、粒子的普遍强制（Sol 4） | 同意：全页无雾；景深、运动模糊只在用到处要求 | 这些强制会把作答推回重型渲染 |
| 「多种技巧」是否设硬性数量（Sol 5） | 不设数量，用定位句和各章具体画面 | 按项目规则，题面不写抽象数量要求 |

## 六、自查

- 六条改版要求：1 定位句与各章效果种类（无百万粒子、无雾、无 20 万微粒名字）；2 每章至少一处悬停与一处点击，见各章末及 2.8 光标；3 爆炸图（02）、其他双芯片三维（剖切、推近接缝、合成一颗、拖开接缝、03 打开的堆栈、06 拉远）及配合的滚动；4 八章每章一对「模型概念 ↔ 硬件部件」，无应用章；5 三种感觉落在节拍、同拍逐级亮起、读一遍、按住计数、三级连线、汇合总和条、梯度同步、倍率读数、生成加速；6 篇幅见第五节。
- 残留检查：全文无「一粒光」「光粒」「徽记」「应用场景」「百万」「光刻」「雾」（第一节「不是……光雾的数量」是定位句）。
- 实现手段：正文无库、API、着色器算法；「WebGL」「着色器」只出现在约束第 1 条与注意事项，均为现行题面原文。
- 主观形容词与罚则：无「震撼」「温暖」「像站在」；无零分、扣分条款；评分部分保留「对提交格式很宽容」。
- 事实：72 卡 NVLink 域未用于 HGX B200；未写顶盖；未写显存上下排布；不确定数字未写死。
