# NVIDIA B200 网页改版：低资源炫技技巧清单与可行性

日期：2026-10-30。范围：给出可采用的画面设计、36 项效果目录及本机小实验。只交付本报告；题面和评分资料未修改。下文第一节是可用于改题面的设计文字，后面的技巧名称、实现风险和测量方法供出题人取舍，不直接抄入题面。

实测结论：8 项代表性效果同屏运行时，三轮 GPU 进程显存峰值为 221–226 MiB，相对静态基线的中位数增量约 161 MiB；这支持以多种局部技巧替代堆数量的方向。冷启动与其余技巧的性能不在这组结论内。

## 一、结论：用数据的形态与路径串起九章

建议保留九章、纵向长卷中插入一段横向、暗场与工程图版的基本结构。贯穿全页的对象改为同一组有编号的数据块、计算格和连接线，分别在输入、权重、计算与输出位置出现；取消唯一光粒、逐章徽记和复制光粒的要求。计算的规模由阵列的组织、同时发生的运算和跨尺度的连接呈现，信息传递由有起止位置的脉冲与往返路径呈现，加速由处理时间带缩短、输出间隔收紧呈现。

### 1.1 可直接进入题面的定位与总要求

> 以 NVIDIA B200 与大模型计算为题材，制作一个纵向长滚动网页，中间插入一段横向浏览。作品将排版、动态图形、三维造型、滚动转场与鼠标交互组合在同一条计算流程中：输入形成数据块，数据进入双芯片与显存，在计算阵列和互连间传递，最后逐步形成输出。
>
> 在下述画面中组合尽可能多的不同视觉变化：让文字、图形、三维部件、数据路径和交互反馈相互接续，增加效果应带来新的可观察变化；不以粒子数量、场景物件数量或全屏光雾的密度作为完成要求。同一处悬停或点击须同时改变相关部件、路径和图表，滚动前进、后退与跳转后都能看清它们的对应关系。

第二段已是“一两句话要求技巧多而不靠堆资源”的建议版本。它没有规定库、接口、渲染方法或资源配额；更换实现后仍成立。“不同视觉变化”按观众看见的作用区分，同一批光点改颜色不能算新增一类效果。

### 1.2 九章的具体落点

| 章 | 画面、滚动与衔接 | 悬停和点击 |
|---|---|---|
| 01 输入与封装 | 一行输入文字按词段分开，重排成有编号的数据块；块下的基线延伸到暗场中的双芯片封装。滚动时标题的字逐个沿基线落定，封装由正俯视转为斜视，基线留作数据入口。 | 指向一个词段，该块及其入口同时亮起；点击后，一组有间距的脉冲沿入口进入计算阵列。 |
| 02 计算阵列 | 镜头从晶体管依次退到交错互连、计算单元与硅片表面的阵列。每级保留前一级的取景框；输入行、权重列在交点汇合，计算格按波前顺序亮起，结果沿另一方向送出。退远后波前仍连续跨过阵列。 | 指向一个计算格，展开其输入、权重与输出三条引线；点击锁定该格，页边的小矩阵同步显示同一次示意计算。 |
| 03 封装爆炸图 | 基板、中介层、两颗硅片及周围 HBM3e 显存堆栈沿分解轴分层升起，彼此的厚度和间隙可见，部件编号跟随移动；继续滚动依次合拢。它是整套封装的三维爆炸图。 | 悬停部件时轮廓与目录同亮；点击可锁定、推近或返回。拆解过程中引线保持套准，选中部件始终能与说明对应。 |
| 04 双芯片协作（横向前半） | 合拢后的两颗硅片保持三维，不再重复拆解。镜头降到接缝上方并沿片间连接横移；两侧计算阵列分批接收数据，跨缝的脉冲分别抵达另一侧，完成的一组结果沿汇出线离开。旁边的俯视图显示镜头当前所在位置。 | 指向跨缝连接，两端端口、对应路径和旁栏图同步亮起；点击一组数据，单独重放它从入片、跨缝到汇出的过程，其余路径保留轮廓。 |
| 05 权重、显存与缓存（横向后半） | 镜头沿上一章汇出线转向显存堆栈。有限组有宽度的流带连接显存与两颗硅片，带内短线标出方向；近处一组显存层分开，流带显露层间入口。权重块与 KV 缓存块分区排列，随处理步骤取出、返回或追加；离开时流带落到平面时间带上。 | 指向权重区或缓存区，只展开该区的读取和写回路径；点击一段路径，相关显存入口、芯片端口和时间带共同响应。数据块标明是概念示意，不把每个点说成一个真实参数。 |
| 06 精度与矩阵 | 时间带的分格展开为位格、数轴和小型权重矩阵。切换精度时，位格重排、量化值落到刻度、误差段与输出柱同步变化，处理时间带在同一基线下对照。 | 点击格式、修改少量输入或权重；悬停一个值，同时标出原值、量化值和误差。精度示意保留缩放信息；时间带注明示意，不宣称固定的端到端加速倍数。 |
| 07 多 GPU 交换 | 当前封装缩到平台的一格，其余 GPU 围绕同一拓扑逐个进入；计算块沿连接交换并汇合，平台旁的拓扑图和各节点的阶段时间条同步推进。远景以整齐的模块阵列展开，无须逐台制作可打开的机柜。 | 点击任一节点发起一次示意交换；指向链路时，相关源节点、目的节点和时间条同亮，当前数据到达后才进入下一阶段。片间连接与 GPU 间连接分别标注。 |
| 08 大模型生成回路 | 浅色图版上，输入、注意力关系小矩阵、缓存更新和输出词段排列在同一闭合路径上。每一步沿路径推进一次，输出新增一段；随着示意处理时间带缩短，连续输出之间的间隔也收紧。保留训练与推理的文字区分，本章明确展示逐步生成，不再安排应用场景。 | 悬停输出词段，回查该步在矩阵、缓存和时间带上的位置；点击候选词段后，后续示意路径及输出一起更新，已确认的部分保留。标明是预设的小型流程演示。 |
| 09 汇总 | 输出的基线收成全页计算路线图，双芯片、显存和互连的缩略形体沿路线归位；关键规格与单位对齐，滚动到末尾时数字停稳。 | 点击路线节点回到相应章，悬停规格时对应部件亮起。页脚写明“本页为概念设计作品，非 NVIDIA 官方页面”。 |

全页保留深色底、细线、刻度和格子，三维与图注始终对应，一屏只展开一组主要说明。荧绿标操作与选中，数据按输入、权重、输出分色；不再保留“琥珀金只准一粒光使用”的限制。悬停只临时查看，点击锁定或触发，移开、取消与返回都有连续的画面反馈。所有进度变化支持反向滚动；点击造成的选中与改值保留。

以上是承载技巧的章节骨架，不要求逐字替换全部现行设计。控制总量的方法是原位替换：02 保留连续尺度变化，03 保留爆炸图、建模细节与观察操作，04 增强合拢状态下的双芯片三维协作，05 用有方向和端点的流带替换百万粒子，08 用生成回路替换四个应用；其余效果嵌入原章节，不另加章节或全页交互系统。把省出的重型渲染要求换成数据路径溯源、矩阵联动、时间带和可打断操作，仍保持较大的限时工作量。全页键盘操作、滚动跳转一致性、部件完整背面和反向滚动等现有完成要求继续保留。

## 二、36 项技巧目录

“低／中”是本报告的定性判断，不是所有浏览器上的承诺：低指在局部、有限元素下开销较小；中指需要三维、重绘、额外图层或中间画面，但控制作用范围后适合本作。每项最后一栏写明越界风险。目录是设计备选池，不能把 36 项全都独立增设成必做段落。第 01、05、07、08、11、12、13、17、23、24、29、30 项的部分内容有后文台架实测，其余为文档与实现经验支持的可行性判断。

### 3.2 容易互相冲突的组合

| 冲突 | 原因 | 建议的边界 |
|---|---|---|
| 滚动时间线＋点击自动动画＋拖动模型 | 三种输入同时控制同一角度或间距，容易争抢状态。 | 滚动负责章内进度；点击负责选中与重放；用户拖动时暂时拥有观察角度，离开时从当前角度连续交还。 |
| 长滚动转场＋快照式视图过渡 | 后者适合一次点击前后两个状态，未必能逐帧倒放或响应中途跳转。 | 长段要求可反滚的对象连续变化；共享快照只作为局部点击展开的备选。 |
| 爆炸图＋剖切＋重型景深＋多层透明 | 选择、遮挡、截面、模糊边界同时复杂化，还可能多次重绘场景。 | 爆炸图和完整背面是主体要求；剖切限定单组结构，焦点变化先用层次明暗表达。 |
| 细密线框＋扫描纹理＋辉光 | 三种高频细节叠加后，线路会闪、边缘发糊。 | 远处显示轮廓与分区，近处才展开细线；辉光只留在当前端口。 |
| 磁吸按钮＋模型拖动＋模型推近 | 目标移动和指针捕获重叠，可能拖完误点或滚轮失效。 | 磁吸只改变视觉附着物或小幅装饰，不移动真实命中区；拖动、点击和滚动各有明确边界。 |
| 可变字宽＋每帧数字文本＋图表布局变化 | 同时触发排版，主线程开销会高于纯位置或比例变化。 | 文字变化只在局部；固定单位和读数位置；静止后不继续刷新同一个值。 |
| 多章节各持三维上下文＋全屏检查窗 | 上下文和场景资源重复，旧上下文还可能被浏览器回收。 | 开发资料中建议复用渲染资源、只运行当前章；题面只要求跳转无残留、返回正常，不规定具体实现。 |
| 点击改值＋反向滚动 | 若滚动负责撤销数值，用户改动会不知何时消失。 | 已修改的输入、格式和选择作为保留状态；反滚倒放的是展示进度。脉冲、光标等空闲循环另列。 |

### 5.2 性能判断的文档依据

- 改变位置与比例通常比反复改变布局尺寸更容易控制开销；字宽、路径形变、剪切和滤镜仍可能重绘，所以目录没有将它们统一标成“免费”。依据：[Google：高性能动画指南](https://web.dev/articles/animations-guide?hl=en)。
- 滚动可驱动正向和反向的展示进度，适合把多条变化绑定到同一章；本报告要求的是这种行为，不指定接口。依据：[Chrome：滚动驱动动画](https://developer.chrome.com/docs/css-ui/scroll-driven-animations?hl=en)。
- 共享视图过渡会保存旧、新状态的快照，适合局部展开；这不能自动解决滚动倒放与中断。依据：[Chrome：View Transitions](https://developer.chrome.com/docs/web-platform/view-transitions/)。
- 三维的实际开销与画面像素、绘制批次、纹理、缓冲、编译和同步等待有关；低面数本身不保证低开销。依据：[MDN：WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)。以上四条是文档支持的方向性判断，具体结果以本次测试为限。
- GPU 内存有专用与共享之分，进程关联的内存也可能包含共享分配；本报告按计数器名称报告，不宣称它是页面对象的唯一独占总量。依据：[Microsoft DirectX：Task Manager 的 GPU 统计口径](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/)。采集接口参见 [CDP Performance](https://chromedevtools.github.io/devtools-protocol/tot/Performance/) 与 [SystemInfo](https://chromedevtools.github.io/devtools-protocol/tot/SystemInfo/)。

### 5.3 B200 与 AI 的事实边界

1. **双芯片是一颗 GPU 内的两颗硅片。** 片间高速连接与 GPU 间 NVLink 属不同层级；03、04、07 的图例要分开。B200 与 HBM3e、Transformer Engine 和 FP4 的主题结合有事实基础，但不应把本作示意阵列当成官方物理版图。依据：[NVIDIA Blackwell 架构](https://www.nvidia.com/en-us/data-center/technologies/blackwell-architecture/)、[NVIDIA HGX B200 组成与规格](https://docs.nvidia.com/enterprise-reference-architectures/hgx-ai-factory-h100-h200-b200/latest/components.html)。
2. **不把容量、显存层数与带宽数字写死在设计稿。** 官方资料会涉及不同产品和配置，B200、GB200、B300 也不能混用。只有选定实际型号与口径后，规格表才填入经核对的值；本报告只要求堆叠结构及其与两颗硅片的关系，不指定堆栈内部层数。
3. **FP4 不能只演成 FP16 删除若干格。** 若展示 NVFP4，应把 E2M1 数值与块级缩放的作用说明清楚；可用少量权重演示实际量化和误差，而不用复现完整 Transformer Engine。不同精度也不能保证所有大模型都按同一倍数加速、保持同样输出。依据：[NVIDIA：NVFP4 推理介绍](https://developer.nvidia.com/blog/introducing-nvfp4-for-efficient-and-accurate-low-precision-inference/)、[Transformer Engine：NVFP4 格式与缩放](https://docs.nvidia.com/deeplearning/transformer-engine/features/low_precision_training/nvfp4/nvfp4.html)。
4. **注意力、权重、激活、缓存与词段不要混为同一种点。** 用标签与分区区分，联动图展示的是本作的小型示例；脉冲的数量、速度和流带宽度若无真实数据，只能标为示意。08 是大模型逐步生成的内部流程，未承诺在页面里加载真实大模型、调用服务或推断真实注意力。

## 六、需要出题人拍板的问题

1. **是否采用“数据块与连接关系”作为贯穿对象，取消唯一光粒与徽记？** 建议采用；这样 03 爆炸图、04 双芯片协作和 08 大模型生成可以直接接续。
2. **03 的剖切与检查窗要保留哪一个？** 建议爆炸图、完整部件、套准图注为主，受限剖切作为增强项；不同时强制任意剖切、透镜检查、全场景深。
3. **08 选择逐词生成回路还是 MoE 路由？** 建议前者，输入、缓存、输出与 05、06 的联系更直接；两者只选一个，维持九章总量。
4. **是否取消现行第四节对全场光雾、反射、景深和运动模糊的普遍强制，并同步改掉评分中的粒子数量目标？** 建议取消这些普遍强制，改验收结构、遮挡、关联、转场和交互；仅删除百万粒子条文不足以实现本次定位。
5. **“多种技巧”采用画面完成要求，还是另设硬性数量？** 建议采用第一节两句话与各章具体画面，不给 36 项逐项配分、不以技术名词计数。本次实测可作为设计可行性证据，暂不把内存或帧率阈值写进题面。
