# 复现与文件说明

本目录只包含研究用必要组件，不是完整编辑器。大体分为普通对象场景、WebGL2 合成、视频导出、数据编辑四部分。题面、评分和受测作品均只读。

## 环境与启动

- Windows 11；Node.js 24.11.0；本机 Chrome 156；Python 用于工作量计算和汇总；ffprobe 用于独立解码核查。
- 浏览器控制依赖 Playwright CLI 安装所带的 `playwright-core`。本机已通过 `npx.cmd --yes --package @playwright/cli playwright-cli --help` 获取；不访问 GitHub。
- 各 `.cjs` 开头目前使用本机 npm 缓存中的 `playwright-core` 绝对路径。换机器须改为该机器可解析的路径；Chrome 路径也在脚本中明确指定。
- 脚本用 `launchPersistentContext` 创建系统临时目录作为独立配置目录，附加 `--noerrdialogs`，无窗口、file://，结束时 `context.close()`。不要用按进程名杀进程的命令。

在本目录的上一级执行：

```powershell
node .\bench\strict-runner.cjs
python .\bench\workload.py
python .\bench\summarize.py
```

`strict-runner.cjs` 为一次完整的严格触发口径复核，正常和优化两种导出各 4 次，并跑原规模编辑任务；视频写到系统临时目录 `ae-sol-performance-media`。`practical-runner.cjs` 跑三轮，当前版本也将视频保存在该临时目录。重新运行会覆盖对应结果文件；现有三轮数据采用早一版预热后计时，重新跑当前代码会包含入口处的编码配置探测与构造时间。

**不要同时启动多个基准进程。** 工作量计算不是浏览器性能测试，汇总不会启动浏览器。基准页也能双击打开，在 DevTools 里执行 `p=createPractical()`、`await p.exportTask('C',180,false)` 等，但会改变运行环境，报告只引用脚本控制的无窗口测试。

## 数据文件

| 文件 | 用途 |
|---|---|
| `practical-results.json` | 三轮正式组件测量，导出计时从编码准备到文件 Blob 完成；场景已预览/预热 |
| `strict-results.json` | 最后额外复核一次，导出计时从 `encode` 入口开始，含配置探测与编码器构造；不在函数内预热 |
| `summary.json` | 三轮结果中位数、范围、画质、旧阈值得分；由 `summarize.py` 生成 |
| `workload.json` | 按题面逐层逐时间采样累加的工作量，不是秒数实测 |
| `fourk-results.json` | 4K 编码配置探测及前 160 帧补测；整段时间只能外推 |
| `extra-results.json` | 软件 VP9 编码补测等；含 4K 硬件配置不支持的记录 |
| `existing-results.json` | Haiku 三场景单帧、Fable 启动检查，仅附注 |
| `results.json`、`practical-pilot-results.json` | 早期探索，包含不合格画质与不同内核，不能用于最终评分或替换主表 |
| `媒体文件清单.json` | 媒体临时路径、长度；截图也在系统临时目录，未放入本目录 |
| `ffprobe-results.json` | 代表 MP4 的独立帧数与时长核对 |

`practical.js` 定义真实图层与关键帧数据和操作；`bench.js` 提供实例化绘制、合成目标、8 样本累积、读回、H.264 MP4/VP9 IVF 封装和抽样 PSNR 检查。`index.html` 使用的算式生成内核只属于早期关键路径探索；主测使用 `practical.html` 与普通对象数据。

## 计时边界

编辑计数据更新加一次画面重绘，各操作分别计时再求和，选择、步间停顿与场景生成不计。`gl.finish()` 后再同步读回 1 个像素，避免只记录 CPU 提交 GPU 指令的时间。

导出计配置/编码处理、帧读回或浏览器帧传递、队列背压、编码 flush、MP4/IVF 封装和完整 Blob 物化。解码抽查 PSNR、把文件拷到磁盘、浏览器启动、场景生成在计时外。普通对象三轮主测前做过预热；严格触发复核去掉函数内预热，并把计时移到入口。最终判读须保留两种边界的区别。

编码画质取第 0、150、450 帧解码后与同帧 GL 像素比较。4K 只编码 160 帧，所以仅检查 0、150。普通原始 RGBA 帧直接喂编码器的探索曾出现颜色偏差，最终常规版改用 2D 画布承载读回的像素后编码，PSNR 合格。

本目录没有任意路径、通用效果、三维或完整界面；父子仿射变换有组件检查，性能场景本身没有添加父级。蒙版为本场景的圆形羽化近似，不承诺与商业软件某一滤波核逐像素一致。
