## 3. 实测协议与计时口径

```text
python orchestrator\bench\bench.py MathNew-<19…24> 数学竞赛原创试题 codex gpt-6.1-sol --effort xhigh --until-done --statement <题面>
```

没有`--fast`；`run.json`均为`fast=false`。额度恰好6场，未追加或重开。题面禁止联网、程序计算/探索、数学库、其他模型和子代理；只交`答案/第01题.md`。公开工具调用另作审查，不能仅以模型自报“无工具”认定合规。

最终人工审查六场公开调用，只出现工作目录内读题／读答案、目录及AGENTS清单、写答案、git操作；没有数学探索代码、数学库、联网、子代理或越界读参考答案。六场均正常自行收卷、宿主退出0；冻结文件与复制到盲测仓库的题面逐字节相同，未被事后更改。详见[最终证据](实验/最终证据.json)、[工具调用审查](实验/audit_tool_use.json)、[计时明细](计时明细.md)和[逐题评分核查](评分核查.md)。

**与前两轮有一项题面协议差异：**为允许研究题的正常解答，本轮明确“研究题可引用已发表的数学定理，但须准确说明名称、内容和适用条件，并证明这些条件在本题中成立；不得把本题待求的数值直接当作定理引用”。前两轮仅笼统允许常见定理、其他关键结论须证。工具禁令一致，定理引用范围并非完全相同；尤其不能把24号已知径向极限定理的使用说成模型自行发现了该定理。

“git用时”取初始题面提交到答案提交的committer时间差；“交卷用时”取`run.start`到公开`turn/completed`成功事件。交卷时刻不取稍后的idle关闭时刻。各模型是新会话，计时包含读题、写解答、文件及git操作，不能当纯思考时长。单次测试的失败说明该次未完成，不证明模型绝对不会。

### 本轮对出题方法的修正

1. **基准标签不转移到任意改编。** HLE的总分、FrontierMath的Tier、论文主题只能支持题源搜寻。更换所求时必须检查是否把原题真正困难的部分删掉；22号有限化就是明显例子。
2. **允许引用的定理可能一次消掉所谓核心。** 24号正确使用径向定理后，后半很快完成；不能用术语陌生或原题答案巨大来估计难度。若要禁用某定理，必须预先明确，不能阅卷时临时扣分；也不能靠禁止一个标准结果人为造硬题。
3. **增加经典分类约束仍可被成套方法消化。** 23号的实型、忠实性、定向裂分都真正有作用，但能沿同一谱分解自然完成；20号的树和闭包则被深度阈值及单调容量归纳压缩。
4. **真正较慢的两题，模型也能重建独立证明。** 19号没有停在“标准Bellman函数”，21号没有停在“查表可得”。以后不能把参考解依赖专门资料误判为模型必须依赖资料；它可能重新构造所需证书。
5. **本轮支持的只有相对变慢，没有失败题。** 不把更多计算步骤、证明篇幅或两道13—16分钟满分解包装成一个量级。若继续追求四道硬题，应先找到有当前模型逐题失败证据、且困难部分能在新所求中保留下来的公开研究原型；这只是下一步建议，不是已授权的新试次。
