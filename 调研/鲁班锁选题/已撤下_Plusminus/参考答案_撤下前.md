## 题源与参考路线

Mini Lock、Stepping Burr 和 More Visible Moves 的数据取自 [burr_mac_tool示例档案](https://github.com/rtjelum/burr_mac_tool/tree/27323599e6951a370bfb3f55a2c6a268137aed5d/examples)，固定提交为 `27323599e6951a370bfb3f55a2c6a268137aed5d`。分别使用 `mini_lock.xmpuzzle`、`stepping_burr.xmpuzzle`、`more_visible_moves.xmpuzzle` 的指定保存装配。重编号保留其几何与路线。

另外五题从设计站的精确分层装配图还原：

- [Plusminus装配资料](https://puzzlewillbeplayed.com/4PieceBurr/Plusminus/solution.html)：Yavuz Demirhan，2012；四件，5×5×5，公开 level 为6.2.2。原始标签A—D保留；本题A为开孔十字形外件，另三件为短锁件。题源页面及装配原文存于 `调研/鲁班锁选题/实验/Plusminus/`。
- [Cubor #2装配资料](https://puzzlewillbeplayed.com/4PieceBurr/Cubor/2/solution.html)：Stéphane Chomine，2013；四件，5×5×5，公开level为6.3.2。本题A、B是相互垂直的缺口板，C、D为不同的厚块；源标签A—D保留。
- [Flat Four装配资料](https://puzzlewillbeplayed.com/664Cross/Flat/4/solution.html)：Frank Worrell，2010；四件，6×6×4，公开level为11.1.3。两枚宽的水平构件与两枚短的竖向构件形成扁平四件交扣，不含独立框架；源标签A—D保留。
- [Caged Knot装配资料](https://puzzlewillbeplayed.com/555/CagedKnot/solution.html)：Tom Jolly，2003；三锁件加框架，5×5×5。源标签B、C、D、X依次重映射为本题A、B、C、D，其中本题D是框架。
- [Swirls 3装配资料](https://puzzlewillbeplayed.com/888/Swirls3/solution.html)：Bram Cohen，2009；四锁件加框架，8×8×8，公开level为27.4.12.3。A、B同形，C、D同形，四枚42格锁件均沿三个维度弯折；源A—D保留，框架X映射为E。其实体双端板与四柱框架及弯曲件不同于 More Visible Moves 的小型框架和短锁件。

这些参考路线只采用轴向平移。曾考察的N-one在原始资料中注明需要旋转，与当前规则不符，因此未采用。

出题端用 [BurrTools v0.8.0](https://github.com/burr-tools/burr-tools/releases/tag/v0.8.0) 的固定拆解实现计算还原题的参考树。新增三题与 Plusminus 使用同一v0.8.0标签提交 `1a14e7319723c44c0187ac776d2a7ce129718831` 的未修改 `disassembler_0_c` 和同一已记录哈希的导出程序，经现有 `export_reference.cpp` 导出，再由 `convert_reference.py` 转换，最终用 `check.py` 独立验证。新02为6+3+2＝11步，新05为11+1+3＝15步，新08为27+4+12+3＝46步。源码版本、编译清单、输入和验证结果保存在 `调研/鲁班锁选题/实验/` 及 `实验/八题版/`。

八题均已检查零件六邻接连通、初态无重叠，并逐步验证移动扫掠区间、无限远移出与全部后续分支。原始输入与参考树在 `参考原始数据/01.xmpuzzle`—`08.xmpuzzle` 和对应 `.xml` 中。来源、标签映射、哈希、各段及完整步数见 [references.json](references.json)。公开level和参考计步分别记录；例如 Caged Knot 的公开13.2.2对应本包13+1+2＝16步，More Visible Moves 的公开19.11.4.6对应本包19+12+5+6＝42步。不同分支选择和计步口径会产生差异，不把公开数字之和当作最优证明。所有路线均是合法完整参考解，未证明全局最优。

## 纯推理规则与评分

先根据会话记录确认工具使用符合题干，再运行几何评分。允许读取题目、查看静态图片、记笔记、编辑答案，以及运行题干指定的 `题目/工具/check.py` 路线检查器和 `positions.py` 位置记账工具；运行这两个原样提供的工具不算违规。除这两个工具外，禁止程序搜索、自动模拟、计算碰撞、自动更新状态、路线优化和调用其他求解器或检查器；具体边界以最新题干为准。存在违规解题行为的作答不进入有效提交与步数基准。

简单档01—02共10分，每题5分；中档03—05共30分，每题10分；困难档06—08共60分，每题20分，总分100分。按完整路线计步，接受不同于参考答案的合法解。`references.json` 的满分基准 `best_moves` 保持未设置，待用户试测后决定，不能把参考步数自动当作满分基准。分项展示到两位小数，总分按未舍入的分项求和后再取两位小数，详见 [AI评分指南](AI评分指南.md)。

在本评分目录，可以单题复核：

```powershell
python check.py ../../../空间推理/鲁班锁拆解/03.json E:/模型作答/鲁班锁拆解/答案/第03题.json
```

批量评分将同轮全部有效作答目录一起传给 `grade.py`。`convert_reference.py` 可从原始 `.xml` 重新生成参考路线，随后由 `check.py` 独立验证；`test_grading.py` 覆盖全部参考解及关键判定边界。满分基准尚未设置时，两项依赖评分基准的测试会按预期失败；几何参考解验证与其余测试应通过。

## 发题与版本

- 发题时复制题面 `空间推理/鲁班锁拆解.md`，并把 `空间推理/鲁班锁拆解/`（八题的 JSON、分层说明、静态结构图及 `工具/`）复制为作答目录里的 `题目/`。
- 作答目录的 `题目/工具/` 带路线检查器 `check.py` 和位置记账工具 `positions.py`：前者检查提交路线的碰撞、无限远移出、完整拆解和计步，后者累加指令输出位置、不会检查碰撞；两者都不替作答者搜索路线，作答时允许运行，评分时运行这两个工具不算违规。
- 受测模型在正式工作目录自行创建 `答案/`，不提供空答案模板或自动检查器。
- 本评分目录、调研资料与旧版试测不进入作答目录。
- 上一版纯推理三档题包与评分资料归档为 `调研/鲁班锁选题/纯推理三档版_20261104.zip`，更早的编程版仍在 `编程搜索版_20261103.zip`。原试测目录保留原题与原编号，不用本批编号直接重评旧作答。

本批仍不设置限时。
