# 鲁班锁拆解 · 三档纯推理版参考答案

本批撤下题源无法核实的 Power Burr，加入有公开装配资料的简单题 Plusminus，并按难度重新编号为三档各两题。作答端提供题干、静态结构图、分层图、精确体素数据和题干允许的两个记账工具；几何检查器留在本评分目录，提交结束后使用。

排序以首次分离、完整路线长度和同时跟踪的零件数共同判断。Handshake 为最短入口；Plusminus 只有首段较长，后续各2步，低于 Mini Lock 的后续7步负担。Mini Lock 先于六件且首拆10步的 Stepping Burr；Caged Knot 与 More Visible Moves 的首拆和完整路线继续增长。该顺序是出题难度判断，尚未用本批试测结果校准。

## 题源与参考路线

Mini Lock、Stepping Burr 和 More Visible Moves 的数据取自 [burr_mac_tool示例档案](https://github.com/rtjelum/burr_mac_tool/tree/27323599e6951a370bfb3f55a2c6a268137aed5d/examples)，固定提交为 `27323599e6951a370bfb3f55a2c6a268137aed5d`。分别使用 `mini_lock.xmpuzzle`、`stepping_burr.xmpuzzle`、`more_visible_moves.xmpuzzle` 的指定保存装配。重编号保留其几何与路线。

另外三题从设计站的精确分层装配图还原：

- [Handshake装配资料](https://puzzlewillbeplayed.com/644Chain/Handshake/solution.html)：Yavuz Demirhan，2013；四件，6×4×4。原始标签A—D保留。
- [Plusminus装配资料](https://puzzlewillbeplayed.com/4PieceBurr/Plusminus/solution.html)：Yavuz Demirhan，2012；四件，5×5×5，公开 level 为6.2.2。原始标签A—D保留；本题A为开孔十字形外件，另三件为短锁件。题源页面及装配原文存于 `调研/鲁班锁选题/实验/Plusminus/`。
- [Caged Knot装配资料](https://puzzlewillbeplayed.com/555/CagedKnot/solution.html)：Tom Jolly，2003；三锁件加框架，5×5×5。源标签B、C、D、X依次重映射为本题A、B、C、D，其中本题D是框架。

这些参考路线只采用轴向平移。曾考察的N-one在原始资料中注明需要旋转，与当前规则不符，因此未采用。

出题端用 [BurrTools v0.8.0](https://github.com/burr-tools/burr-tools/releases/tag/v0.8.0) 的固定拆解实现计算还原题的参考树。Handshake 得到首次分离4步、完整8步；Caged Knot 得到首次分离13步、完整16步。Plusminus 使用 v0.8.0 标签提交 `1a14e7319723c44c0187ac776d2a7ce129718831` 的未修改 `disassembler_0_c`，经现有 `export_reference.cpp` 导出，再由 `convert_reference.py` 转换，得到6+2+2共10步，`check.py` 独立验证通过。源码版本、编译清单、输入和验证结果保存在 `调研/鲁班锁选题/实验/`。Caged Knot 公开阶段记录为13.2.2，本包以实际路线经统一检查器计算出的16步为准，不把公开阶段数字之和当作最优证明。

六题均已检查零件六邻接连通、初态无重叠，并逐步验证移动扫掠区间、无限远移出与全部后续分支。原始输入与参考树在 `参考原始数据/01.xmpuzzle`—`06.xmpuzzle` 和对应 `.xml` 中。来源、标签映射、哈希与实际步数见 [references.json](references.json)。所有路线均是合法完整参考解，未证明全局最优。

## 纯推理规则与评分

先根据会话记录确认工具使用符合题干，再运行几何评分。允许读取题目、查看静态图片、人工记笔记、编辑答案，以及运行题干指定的 `题目/工具/format_check.py` 与 `positions.py`。除这两个工具外，禁止程序搜索、自动模拟、计算碰撞、自动更新状态和调用几何检查器试探；具体边界以题干为准。存在违规解题行为的作答不进入有效提交与步数基准。

第一档01—02共20分，每题10分；第二档03—04共30分，每题15分；第三档05—06共50分，每题25分，总分100分。按完整路线计步，接受不同于参考答案的合法解。`references.json` 的满分基准 `best_moves` 保持未设置，待用户试测后决定，不能把参考步数自动当作满分基准。分项展示到两位小数，总分按未舍入的分项求和后再取两位小数，详见 [AI评分指南](AI评分指南.md)。

在本评分目录，可以单题复核：

```powershell
python check.py ../../../空间推理/鲁班锁拆解/03.json E:/模型作答/鲁班锁拆解/答案/第03题.json
```

批量评分将同轮全部有效作答目录一起传给 `grade.py`。`convert_reference.py` 可从原始 `.xml` 重新生成参考路线，随后由 `check.py` 独立验证；`test_grading.py` 覆盖全部参考解及关键判定边界。满分基准尚未设置时，两项依赖评分基准的测试会按预期失败；几何参考解验证与其余测试应通过。

## 发题与版本

- 发题时复制题面 `空间推理/鲁班锁拆解.md`，并把 `空间推理/鲁班锁拆解/`（六题的 JSON、分层说明、静态结构图及 `工具/`）复制为作答目录里的 `题目/`。
- 作答目录的 `题目/工具/` 带两个只记账的小工具：`format_check.py` 检查答案格式并按题面规则计步，`positions.py` 累加移动记录并输出零件当前位置；两者都不判碰撞和能否移出，作答时允许运行，评分时运行这两个工具不算违规。
- 受测模型在正式工作目录自行创建 `答案/`，不提供空答案模板或自动检查器。
- 本评分目录、调研资料与旧版试测不进入作答目录。
- 上一版纯推理三档题包与评分资料归档为 `调研/鲁班锁选题/纯推理三档版_20261104.zip`，更早的编程版仍在 `编程搜索版_20261103.zip`。原试测目录保留原题与原编号，不用本批编号直接重评旧作答。
