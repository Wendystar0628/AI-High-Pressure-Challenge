# 提醒机制：用户已定的要求

整治提醒机制、定稿注入文字时以本文件为准。调研文档里与本文件冲突的建议作废；本文件内部，后写的条目优先。

## 两类题分开处理（总原则）

注入提示和相关文档都按两类题分开写：

| 类 | 包含的类别 | 处理 |
|---|---|---|
| 主动设计题 | 视觉设计与渲染、游戏设计与开发、复杂交互应用、物理建模与仿真 | 敦促模型不偷懒，尽可能做到更高的完成度：每次提醒都要求重读题面，对照题面已有的设计内容逐项检查和提升 |
| 标准评判题 | 算法竞赛、深度推理 | 题干简单、目标明确，不需要上面这些提示。注入只简要说明时间，相关的其他说明也从简 |

“相关文档”包括：
- 开场提示词 `prompt-template.txt` 和续做提示词 `resume-template.txt`；
- 定时提醒；
- 题面“规定”里描述提醒的那一条；
- README 和 playbook 里对提醒的描述。

## 主动设计题

- 每次提醒都要求重读题面，避免记忆不清导致设计走偏。
- 不要每个提醒时间点都一样。90 分钟的题：
  - 前 60 分钟大多在正常开工，提醒简短；
  - 后 30 分钟侧重完成度和质量的检查与提升。
- 用户要拿这些作品做视频，所以要尽量好看、完成度尽量高。
- 结束作答前对照题面逐项检查，这一要求只对这类题。
- 题面和注入提示都要说明：个别小 bug 对分数影响不大，优先推进作品整体的完成度和质量。具体提示策略由指挥定，见下。五份设计题面和评分指南已于 2026-10-29 加好。
  - 开场提示词：一句“个别小 bug 对分数影响不大，优先推进作品整体的完成度和质量；有 git 提交兜底，可以大胆推进”。
  - 前 60 分钟的提醒：一句短话，先把题面写的内容整体推进起来，个别小 bug 先不纠缠。
  - 后 30 分钟的提醒：检查先看整体完成度和观感（题面写的内容哪些还没做、哪些做得粗糙），个别小 bug 不要拖住整体推进。
  - 立即叫醒的文字：同样带上“小 bug 影响不大，继续推进整体完成度和质量”。

- **浏览器工具**（用户 2026-10-29 批准）：主动设计题的受测会话接入本地浏览器 MCP。
  - 用的是 `chrome-devtools-mcp@1.12.0`，装在 `H:\AI_OneShot_Model\.oneshot\tools\`；参数固定为无窗口本机 Chrome，并使用显卡。
  - 题面去掉“优先使用 Agent 自带的内置浏览器”，改成如实说明环境提供的浏览器工具。
  - 开场提示词加一句平实的说明：可以随时用浏览器工具打开、操作作品和截图，按实际运行效果改进。
  - 标准评判题不接入。

## 标准评判题

- 提醒只简要说明时间（已用、剩余），不要求重读题面，不要求检查，不提醒收尾核验。
  - 此前定的“如有需要再重读题面”被这一条取代：可以保留这半句，但不展开。
- 两道数学题（形式化证明题、IMO风味难题）：全部时间都应该用于解题。
  - 形式化证明题：Lean 证明编译通过（不含 `sorry`）就一定得分。
  - IMO风味难题（2026-10-30 加）：证明详略按 IMO 竞赛标准，关键的重要步骤不能遗漏，其余推导不要无限细化。题面“作答格式与要求”第 6 条同步写入。
  - 以上几句是这类题提醒里允许出现的全部附加内容。
- 形式化证明题：先挑相对有把握的题做，选定后尽量不要做到一半临时切换题目。题面“作答建议”已于 2026-10-29 改好。提醒里不得建议“卡住就换题”；调研文档里“30 分盘点、换题”的建议作废。
- IMO风味难题：题面和注入提示里都不要求“严谨证明”，只说按 IMO 竞赛的作答规格作答。题面、评分指南和 README 已于 2026-10-29 改好。
- 六份题面“规定”里的“结束作答之前，必须对照本题面的内容逐项检查”已于 2026-10-29 删除。
- 开场提示词目前对所有题都写着“停止行动之前，对照题面的设计要求逐条检查当前作品”“收到提醒后请重读题面、检查和改进提交”，要改为只对主动设计题说。

## 去掉一切让模型停下的措辞（两类都适用，最高优先）

所有注入文字和题面里，凡是明示或暗示模型可以停下、收手、求稳的措辞，一律去掉。

现在有 git 版本兜底，应当鼓励模型大胆推进：有已提交的版本兜着，大改也不怕。

要去掉或改写的已知措辞：

- **提醒**
  - “不要开始大的改动”“剩余时间只做小的改进”“请尽快收尾”“注意收尾”；
  - “进入检查阶段时……逐条检查”（检查要作为推进和提升的手段，而不是停下前的手续）。
- **开场提示词**
  - “提前停下后，下一次时间提醒会叫醒你”；
  - “收尾完成后把最终版本也提交”；
  - “剩余 10 分钟时注意收尾”；
  - “已收尾完成的评工作目录”。
- **题面“规定”**
  - “你已经停下时，提醒会把你叫醒”；
  - “已收尾完成的，以那时工作目录中的……作为最终提交”“收尾完成后把最终版本也提交，以免时间到时停在半途”；
  - 设计题的“结束作答之前，必须对照本题面的内容逐项检查”：改成作答过程中反复对照题面检查和完善，不以“结束作答”为前提。
- **IMO 和形式化证明题题面的“作答建议”**
  - “时间用完之前提前停下时……能，就不用再改动，直接结束；不能，就继续完善。”整条删除。

评分版本的规则不变：工作目录完整可用就评工作目录，停在半途就评最近一次提交，从没提交过就评工作目录。只是写法上不再出现“收尾”。

## 主动设计题：模型主动停下时立即叫醒

- 主动设计题的模型在时限内自己停下（一轮正常结束、进入空闲）时，立即叫醒它继续推进，不等下一个 10 分钟提醒。
  - 叫醒文字遵守上面“去掉停下措辞”的原则：说明剩余时间，要求重读题面、对照设计继续提升，有 git 兜底可以大胆改。
- 标准评判题不做立即叫醒，照常每 10 分钟提醒。
- 只做防止空转的最小保护：一轮因 API 错误、额度或宿主故障结束时不连续狂叫醒，交给现有异常处理。

## 评分宽容与扣分说明（两类都适用）

- 要告诉模型：评分对提交格式很宽容，不用担心格式标准之类的问题。开场提示词和题面都要说。
- 题面里不写“白屏 0 分”这类零分说明，也不写扣分说明。扣分和零分内容只写在评分 AI 读的文档（`Grading\` 下的评分指南）里。

## 不施压，只给普通说明（两类都适用）

- 题面和注入文字里都不写给模型施加压力的话，例如“本测试是 AI 模型能力竞赛”“与其他顶级 AI 模型直接比较”“限时高压挑战赛”“以获取更高分数”。只写普通说明。
- 11 份题面开头的这类句子已于 2026-10-29 改成平实说明。
- 主动设计题仍可以敦促“用好全部时间，把完成度做高”，语气要平实。

## 两类都要有的

- 作答目录是 git 仓库。时间到时停在半途的，以最近一次提交评分。提醒里可以留一句简短的“可用的阶段用 git 提交”。

## 2026-10-30 新决定：两类题每段只提醒一次，按配置和剩余时间续做

本条取代上文两类题每 10 分钟提醒、主动设计题最后 30 分钟分档复查，以及时限内每轮结束均立即叫醒的旧规则，包含出题人当日追加的标准评判题单次提醒与立即续做要求；“标准评判题暂不唤醒”的中间决定作废。

- 两类题每段都只在剩余 10 分钟时发一次定时提醒；续做以本段剩余时间为准，不足 10 分钟的续做段立即提醒。其余各档不再发送。
- 主动设计题沿用 final 档内容：已用和剩余时间、重读题面，加该题 final 提示。10、20 等档和 60/70/80 复查档不再使用，相应 task_tips 清理。
- 主动设计题正常结束一轮时，剩余多于 10 分钟才立即发起下一轮，全文只有：“时间充足，继续对照题面的设计内容推进。”不带时间数字和其他提示。剩余不多于 10 分钟不再立即唤醒，让会话空闲到时限。
- 标准评判题定时提醒沿用原有内容：已用和剩余时间、git 提交提示；两道数学题照旧附原获准句，IMO 照旧附原证明详略句。正常结束一轮时，剩余多于 10 分钟立即发起下一轮，全文只有：“时间充足，继续解题。”不带时间数字和其他提示；不多于 10 分钟不再唤醒。标准评判题的定时与续做提示都不得含“重读、检查、核验、收尾”。两类题共用触发规则，只通过 reminders.json 的 wake 配置区分续做文字。
- 剩余 10 分钟的定时提醒照常送达：在跑就在下一次工具调用时注入，空闲就发起新一轮。
- API 错误、额度、宿主故障、到时中止和 --resume 等现有处理不变。
- 本次只更新机制、模板、说明、预览和测试；各题提醒条款由指挥修改，不改题面与 Grading 文件。

## 2026-10-30 03:5x 新决定：不向模型披露具体时长，提醒只保留简短建议与保存版本

本条取代上文关于报已用/剩余时间、重读题面与 final 分题提示、数学题附加句、模板预告提醒或唤醒的旧要求；以本条区分两类题的最终措辞为准。“两类题都建议收尾”的中间说法作废。

- 主动设计题定时提醒全文：“【提醒】建议完成收尾，把可用的版本用 git 提交。”不再附重读题面与 final 分题提示。这是对旧版“去掉停下措辞”要求的新增例外；开场与续做说明仍不暗示可以停手。
