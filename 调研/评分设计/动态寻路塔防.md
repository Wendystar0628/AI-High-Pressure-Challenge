# 动态寻路塔防 · 评分方向重设调研

> 2026-10-29 调研。本文只提方案，题面、评分指南和评分表都没有改动。依据是题面 `游戏设计与开发\动态寻路塔防.md` 全文、`Grading\游戏设计与开发\动态寻路塔防\AI评分指南.md` 和两份评分表。
> 资料标注：[已读原文] 指读过原文；[搜索摘要] 指只看到检索摘要，原页没打开；[二手] 指玩家评论、论坛等非权威来源。出处见文末。

## 结论

推荐 6 个方向，一级方向按“看的是哪一层”来切，彼此不包含：

| 代号 | 方向 | 分值 | 这一层看什么 |
|---|---|---|---|
| A | 寻路与改道 | 22 | 格子能不能走、敌人走哪条路、通行变了以后怎么改道 |
| B | 单位与战斗 | 22 | 塔、敌人、Boss、道具各做了什么，打了谁，身上有什么状态 |
| C | 关卡与经济 | 14 | 地图怎么摆，波次怎么排，资源怎么进出 |
| D | 美术 | 16 | 好不好看，像不像题面描述的那种画面 |
| E | 界面与交互 | 18 | 玩家看不看得懂局势、好不好操作 |
| F | 运行质量 | 8 | 暂停、加速、切页、重开以后还对不对，流畅与否，有无报错 |

- A、B、C 是玩法层，按子系统并列：路网、交战、对局。每个方向自己既评“做没做到”，也评“做得多好”。不再单设横切所有子系统的“系统正确性”和“策略深度”。
- D、E、F 分别是视觉层、界面层、运行层，与玩法层不相交。
- 判别时可以这样问：**行为对不对**归 A/B/C，按子系统分；**好不好看**归 D；**看不看得懂、好不好操作**归 E；**换了速度、重开、场面变大以后还稳不稳**归 F。

## 一、现行方向的问题

现行方向：玩法与策略 20 / 关卡与波次 14 / 系统正确性 28 / 画面与美术 14 / 信息呈现与反馈 12 / 操作与技术 12。

### 1. 根因：两种切法混用

现行六个方向用了两把刀：
- 一把按“看哪块内容”切，如关卡与波次、画面与美术；
- 另一把按“看哪种质量”切，如系统正确性、信息呈现、策略深度。

两把刀横竖交叉切同一块内容，交叉处必然被评两次。这和渔港题“场景内容”横穿美术、光照、动态是同一个病。下面各条都是这个根因的具体表现。

### 2. 玩法与策略 × 系统正确性：同一个机制评两遍

- **7.1 表自己就重复引用了节号。** 2.8 第 3 条同时写在两个方向的说明里：玩法与策略写“2.8 第 3 条”，系统正确性写“2.8”。2.4 也出现在玩法与策略的说明和“战斗与结算”的要点里。
- **指南的要点也重复。** “单位与道具设计”要求塔和敌人“按描述实现”；“状态、配合与资源”又要求状态和配合“按描述起作用”。实例是 2.8 第 3 条那个例子：探针一击让整串蠕虫重置，沙箱让它们可疑后当场隔离。如果做不出来，两个方向都会扣分。
- **会改变通行的敌人也评两遍。** “单位与道具设计”写“撬锁者撬开封存旧通道改变通行”“三个 Boss 的……锁死运维环等能力按描述实现”；“寻路与改道的正确性”又写“敌人改变通行的能力同样更新路线且不会封死”。

### 3. 玩法与策略 × 关卡与波次：“取舍”评两遍

- “策略深度与配合”看“是否构成真正的策略选择”；“地图与关卡设计”看“是否让改道和部署成为有意义的取舍，改道是否真的在入口之间转移压力”。
- 实例：在分段内网隔离西边界节点，A 折进业务网段与 B 同路。这既是一处地图设计，也是一个策略选择，两个方向都能评。
- 策略深度是单位、地图、资源共同作用出来的。按 MDA 的说法，它属于“动态”层，不是独立的部件。把它单列成方向，它就必然包含其他方向。

### 4. 资源一件事分在三处

- 2.9 第 2 条写在“关卡与波次”的说明里（“两种资源的节奏”）。
- 资源结算（3.3 第 2–3 条）和“情报与隔离挂钩”（2.7 第 8 条）却在“系统正确性 · 状态、配合与资源”里。
- 这个分项又把“状态”和“资源”这两件无关的事绑在了一起。

### 5. 系统正确性是一根横切的质量轴，28 分装了六类东西

- 它的说明列包括 2.7、2.8、2.9 第 5–6 条、3.2–3.5、3.7，覆盖寻路改道、战斗结算、状态配合、资源结算、暂停加速与重开、说明与实际一致。
- 其中 3.5（暂停、放慢、加速、切标签页、重新开始）是游戏时钟和状态生命周期的问题，和寻路、战斗不是一回事。
- 视频里出现“系统正确性 15/28”，观众分不出是寻路崩了，还是暂停时冷却没停。
- 题名里的“动态寻路”是全题的题眼，却没有自己的方向，只是这根轴里的一个分项。

### 6. 画面与美术 × 信息呈现与反馈：特效、动画、可区分性都评两遍

- **说明列重复引用。** 2.11 第 6 条“攻击与特效”两边都引：美术引 2.11，信息引 2.11 第 6 条。3.6 第 3 条“连续动画”两边也都引：美术引 3.6 第 1–3 条，信息引 3.6 第 3–5 条。
- **可区分性两处都评。**
  - 单位：2.11 第 4 条“仅凭外观就能区分”在美术，2.12 第 4 条“各种敌人和 Boss 一眼能区分”在信息。
  - 格子：2.11 第 2 条“各类格子不看文字也一眼可辨”在美术指南第 2 条，2.12 第 1 条在信息。
- **可读性要求被放进美术。** 2.1 第 3 条里的入口固定颜色，以及“信息元素都带一圈暗色细边，在明场和暗场上都看得清”，评的是可读性，却跟着 2.1 整节进了美术。

### 7. 操作与技术：两件无关的事绑在一起

- 界面操作（2.10）与运行性能、控制台报错（第四节）没有关系。“界面为简体中文”也放在这里。
- 它还和信息方向交叉：常驻信息（2.10 第 2 条）归操作，“常驻信息不被遮挡”（3.6 第 5 条）归信息。

### 8. 同一件事在三处评，指南只好打补丁

- **路线预览评了三次。**
  - 2.7 第 3 条在系统正确性；
  - 2.10 第 4 条在操作，要点写“确认前能预览各入口的路线”；
  - 2.12 第 2 条在信息。

  现行指南只好在一处写“路线预览只看两点”，另一处写“路线预览只看显示”。需要靠补丁区分，本身就说明边界没划清。
- **“不能进行的操作说明原因”也评了三次。** 分别是 2.7 第 3 条“给出提示”、2.10 第 4 条“说明原因”、2.12 第 6 条“说明原因”。

### 9. “创意与原创性”4 分没有对应的题面要求

题面现在已经把世界观、八塔八敌、三张地图都写定了。指南写的“题材和整体设定是否新颖”，评到的是出题人。“照搬现有游戏”已经由 7.2 处理。

### 10. 方向名看不出边界

- “玩法与策略”的“玩法”可以指全部内容。
- “系统正确性”可以指全部系统。
- “关卡与波次”实际还在评资源。
- “操作与技术”是两件事。

### 2. 各方向的维度与边界

#### A 寻路与改道（22 分）

- **评什么维度：** 路网这一子系统的行为。包括：各种格子能不能走、行程怎么计；路线怎么算；通行情况因任何原因改变后，显示的路线和场上敌人怎样改道；改道前能否预览；封死怎样被禁止；光端机的保护倒换；伪热点的航线。
- **做没做到：** 有自动寻路，有改道，有预览，会拒绝封死。
- **做得多好：** 各种来源的变化走同一套规则；路线显示与实际走法一致；边界情形和同时发生时结果正确；敌人密集时不出错。
- **不评：**
  - 敌人能力本身的触发、选位和打断，如撬锁要几秒、被重置后清零 → B2。
  - 某张图隔离某个节点后改走哪条路是否符合 2.3、单独隔离任一节点是否都改道 → C1。
  - 隔离花多少情报、守住节点产不产情报、被拒的操作扣不扣费 → C3。
  - 路线、预览和被拒原因在画面上看不看得清 → E1。
  - 收敛波、光板、旁路光桥这些特效好不好看 → D3。
  - 只在加速、暂停或切标签页时才出现的穿格、跳判定 → F1。

#### B 单位与战斗（22 分）

- **评什么维度：** 交战这一子系统的行为。包括：八种塔与四种道具的作用、部署位置、朝向、升级、分支、技能；八种敌人与三个 Boss 的能力；阻挡、选目标、伤害、治疗、护盾；明文、可疑、重置、隔离、清除、退避这条状态链和塔的状态；各种配合。
- **做没做到：** 每样东西是否按 2.4–2.6、2.8 实现，彼此作用不同。只在数值上不同的不算（3.1 第 1 条）。
- **做得多好：** 状态叠加、来源离场、带状态改道等边界情形结果一致；各种塔和道具在实战中各有用处、需要搭配，而不是一招通吃。
- **不评：**
  - 能力改变通行之后的改道与禁止封死 → A。
  - 价格、击杀回收、撤下退款、摧毁后的修复与情报计时 → C3。
  - 造型、动画、弹道与特效的样子 → D2、D3。
  - 生命条、状态标记、阻挡名额、攻击对象看不看得出 → E2。
  - 游戏内说明写得全不全、与实际是否相符 → E5。
  - 计时是否按游戏时间 → F1。

#### C 关卡与经济（14 分）

- **评什么维度：** 一局的宏观设计，即三张地图的布局、波次编排、两种资源的规则与节奏、胜负条件和一局时长。
- **做没做到：** 布局与 2.3 一致，波数与 Boss 波正确，资源按 2.9 第 2 条进出，结算不重复不遗漏。
- **做得多好：**
  - 布局是否让隔离与开路成为入口之间的真实取舍；
  - 难度是否逐步递进；
  - 两种资源是否需要反复权衡；
  - 改道是否有真实代价。
- **不评：**
  - 寻路与改道过程本身 → A。
  - 单位的能力与平衡 → B1、B2。
  - 各图的光场与环境美术 → D1。
  - 流量预报、来袭信息、资源数字在画面上的显示 → E2。

#### D 美术（16 分）

- **评什么维度：** 视觉品质，即画面和界面好不好看、像不像题面描述的那种画面。包括 3D 场景、光场、材质、环境、塔与敌人的造型和动画、特效的质感，以及战斗画面与各界面风格的统一和完成度。
- **做没做到：** 2.1、2.11 写到的场景、造型、动画和特效都做出来了，没有占位。
- **做得多好：** 质感、层次、统一程度，整体是否达到可以发行的商业游戏水准。
- **不评：**
  - 单位和格子“一眼能不能区分”、信息在混战中看不看得清、事件有没有被交代 → E。
  - 帧率与流畅度 → F2。
  - 特效对应的规则是否正确 → A 或 B。

#### E 界面与交互（18 分）

- **评什么维度：** 玩家与游戏之间的界面，包括：
  - 看：地形、路线、战局的信息是否交代清楚；各类事件是否有及时、可区分的反馈与过渡。
  - 做：镜头、部署、朝向、放慢、选中、防误操作是否完整顺手。
  - 读：游戏内说明是否齐全、与实际一致，文案语言和口吻。

  这三块合起来就是 HEP 框架里 Game Usability 的范围（界面以及鼠标、键盘、HUD 等交互元素）[已读原文]，属于同一个维度，不是两件事的捆绑。
- **做没做到：** 2.10、2.12 列出的每样信息和每个操作都有。
- **做得多好：** 一眼能读懂；混战和加速时主次分明；操作顺手。
- **不评：**
  - 控件、面板和画面好不好看 → D4。
  - 路线和预览本身算得对不对 → A。
  - 单位的行为是否符合题面 → B。
  - 暂停、加速后判定是否一致 → F1。

#### F 运行质量（8 分）

- **评什么维度：** 与具体玩法无关的运行层，包括：游戏时钟（暂停、放慢、至少 2 倍加速、切标签页）下判定是否一致；快速连续操作是否会重复结算；重新开始与返回关卡选择是否干净；流畅度（结合场面规模与画面质量综合评价）；控制台报错；性能读数。
- **不评：**
  - 正常速度下的寻路和战斗正确性 → A、B。
  - 暂停和速度按钮是否始终可见、可用 → E2。
  - 画面好坏 → D。
- 按约束，这里不评长时间运行稳定性，不做长时间等待的检查，不精确测帧率。

### 3. 边界判例

下面这些事最容易被评两次，这里写明各自只归一处。

| 可观察的事 | 归属 |
|---|---|
| 撬锁者撬开封存旧通道 | 撬锁的条件、耗时、被打断后清零 → B2；撬开后路线更新、不会封死 → A2、A3；看得出哪条路线改了 → E1；锁符碎开的样子 → D3 |
| 洪泛团冲垮节点上的网闸 | 拉成洪流冲击节点的能力 → B2；隔离解除与改道 → A2；情报计时清零、卡片进入修复 → C3；白色旁路光桥 → D3；看得出哪些敌人转向 → E1 |
| 会封死的操作 | 该拒的拒了、不该拒的没拒 → A3；被拒不扣资源 → C3；画面指出会被封死的入口或敌人 → E1 |
| 资源不足或位置不能部署 | 原因的标示 → E3；部署位置的规则本身 → B1 |
| 塔或敌人能不能一眼区分 | 能不能区分 → E2；造型做得像不像描述、精不精 → D2 |
| 改道时的收敛波 | 有没有、好不好看 → D3；路线的变化能不能被注意到、是不是一闪而过 → E1 |
| 敌人穿过刚被隔离的节点 | 正常速度下发生 → A2；只在加速、暂停或切页后发生 → F1 |
| 游戏内说明与实际不符 | 说明写错了 → E5；实际行为不符合题面 → A 或 B |
| 某种塔一家独大 | 单位强弱失衡 → B1；全局难度曲线 → C2；隔离几乎不花代价 → C3 |
| 帧率低但画面复杂 | 流畅度结合场面与画质综合评 → F2；画面本身的质量 → D |

## 三、分项与要点

- 共 20 个分项。每个分项写两三条“看什么”。
- 一般第一条看“做没做到”，即是否按题面实现；后面看“做得多好”，即边界情形、质量、取舍。
- 按现行格式，方向标题写“（共 N 分）”。

### A 寻路与改道（共 22 分）

**A1 通行与路线（6 分）**
- 敌人按 2.2 的通行规则自动寻路：哪些格子可走；旧链路按更长的行程计；暗光纤和封存旧通道在点亮或撬开之前不可走。普通链路上的阻挡型塔和其他操作不改变通行（2.7 第 1 条）。
- 画面上的路线就是敌人实际走的路线，经过特殊地形时也一致（3.2 第 5 条）。
- 伪热点沿直线飞往固定出口，不受地形、隔离、阻挡和光端机影响；它所在的位置不会让操作因封死被拒（2.7 第 6 条）。

**A2 改道过程（8 分）**
- 2.7 第 1 条列出的每种通行或行程变化，都按同一套路由收敛处理：
  - 显示的路线同步更新；
  - 场上的地面敌人从当前位置重新寻路，之后出发的走新路线；
  - 以路线或到出口的距离为依据的效果，改按新路线计算（2.7 第 2 条）。
- 改道时敌人不瞬移、不穿过不可通行的格子、不卡住、不无故来回。格子变得不可通行时，格上的和正要进入的敌人按同一种设计处理（3.2 第 4 条）。
- 几处通行变化同时发生、节点上几座塔同时被摧毁、敌人密集时，结果仍然正确（3.3 第 1 条）。

**A3 预览与禁止封死（8 分）**
- 在节点上部署塔或插入隔离器、部署或升级光端机时，确认之前能预览各入口的路线，预览与操作后的实际结果一致（2.7 第 3 条、3.2 第 3 条）。
- 任何时候，每个入口和场上每个地面敌人都有路可走。会造成封死的操作，包括让场上某个敌人无路可走的，都不能完成；不会封死的操作不被误拒（3.2 第 1 条）。
- 光端机撤下会造成封死时被拒；被摧毁时保持点亮，直到熄灭不再会封死。撬锁、伪路由、锁死运维环等敌人能力同样不造成封死（2.7 第 4–5 条、2.5）。

### B 单位与战斗（共 22 分）

**B1 塔与道具（7 分）**
- 八种塔和四种道具按 2.4、2.6 实现各自的作用、部署位置、朝向、技能和充能方式，道具有冷却。每种塔都能升到 2 级；三种塔的互斥分支作用不同，选后不能更改。
- 只在数值上不同的不算不同（3.1 第 1 条）。靠受击充能的技能只在实际受击时充能；塔离场后，持续技能和区域效果立即结束，已给出的护盾和状态保留（2.4、3.4 第 3 条）。
- 各种塔和道具在实战中各有用处、需要搭配，而不是一种塔或一招就能通吃。

**B2 敌人与 Boss（7 分）**
- 八种敌人的能力按 2.5 实现，彼此作用不同：复制、冲击节点、伪装与载荷、远程加密、撬锁、未知时穿透、劫持隔离器、分壳。
- Boss 的通用规则按描述实现：占多个阻挡名额并挤开阻挡塔、不受重置和困住、改变地形前预警 3 秒。万傀、蜃楼、蛰影各阶段的能力也按描述实现。
- 能力的触发、选位和打断前后一致。打断指被重置、困住、隔离、掉线时作废或进度清零。

**B3 交战与状态（8 分）**
- 阻挡与攻击（2.8 第 1–2 条、3.4 第 1–2 条）：
  - 阻挡名额有限，超出的敌人继续前进；阻挡者离场或失效的一刻，被挡的敌人恢复前进。
  - 塔优先打沿路线离出口最近的敌人；敌人按自己的规则选目标，不打已不存在或射程外的塔。
  - 伤害减免、治疗、护盾正确结算，生命不超过上限。
- 明文、可疑、特征扩散与重置、隔离与清除、退避，以及塔的加密、护盾、封禁，按 2.8 第 3 条起作用；列出的配合真正能触发。
- 状态重复施加、多种状态并存、来源离场、带着状态改道或换地形、敌人能力影响状态时，结果一致、合理（3.4 第 4 条）。

### C 关卡与经济（共 14 分）

**C1 地图（6 分）**
- 三张地图都能从关卡选择直接进入。入口、出口、节点、旧链路、暗光纤、封存旧通道，以及各图写明的改道关系，与 2.3 一致；三张图彼此有实质差异（3.1 第 2 条）。
- 其余节点都未被隔离时，单独隔离任意一个节点，都至少让一个入口改走另一条道路（3.2 第 2 条）。至少有一个节点能同时改变两个以上入口的路线；多出口的图能把敌人调往另一个出口（2.7 第 7 条）。
- 布局是否让这些决定成为在入口之间转移压力的真实取舍：隔离哪个节点，要不要点亮暗光纤或旧桥。

**C2 波次与难度（4 分）**
- 各图的波数、Boss 波和洪峰波与 2.9 第 1 条、2.5 一致。新敌人逐个引入；各波的敌人组合、出发入口和节奏有变化，不只是数值放大。
- 敌人进入出口扣中枢完整度，归零即失败，撑过全部波次即胜利。难度递进合理，一局时长符合 2.9 第 4 条，可按波次编排推算。

**C3 资源与代价（4 分）**
- 算力和情报按 2.9 第 2 条和 2.6 获取与花费，不能互相兑换。撤下退还一半；被摧毁不退款，进入更长的修复；节点恢复直通后有抑制期。
- 节点上的塔、光端机或隔离器离场时，资源结算与通行变化同时发生，不重复、不遗漏。被拒的操作不扣资源；不存在几乎零代价反复改道、让敌人来回折返的打法（3.2 第 1 条、3.3 第 2–3 条）。
- 两种资源在一局中都需要反复获取和权衡，改道是有代价的决定（2.7 第 8 条）。

### D 美术（共 16 分）

**D1 场景与光照（4 分）**
- 战场是实时渲染的 3D 场景，有透视和纵深，地块有厚度和高低，各类地块做成 2.1、2.2 描述的样子。三张图的光场与 2.1 第 3 条、2.11 第 2 条一致，有明暗和实时阴影，不同材质看得出区别。
- 地图以外的协议层、星团与流量、公网流、头顶的微光和深渊，与战场连成一体并有动态，背景不抢视线（2.11 第 3 条）。

**D2 造型与动画（4 分）**
- 塔、敌人和 Boss 按 2.1 第 4 条的造型语言和各自的描述建模：守方白色透光，敌方吸光暗色。升级、分支和朝向在模型上体现；Boss 换阶段时外形改变；单位处在正确的位置和高度（3.6 第 2 条）。
- 待机、行走、攻击、受击、技能、倒下和被摧毁都有连续动画，朝向随方向变化，不是静止模型平移，也不只靠缩放、闪烁（3.6 第 3 条）。守方动作干脆；敌方蠕动、改写形状、带故障抖动。

**D3 特效（4 分）**
- 各种塔和勒索者的攻击有 2.11 第 6 条描述的各自弹道。下列事件也都有相应的特效：命中、技能、治疗、护盾、状态、配合、消灭、复制、节点隔离、旁路光桥、收敛波、Boss 换阶段和道具。
- 特效有层次和质感，强弱与事件的分量相称，风格与整体统一。

**D4 风格与完成度（4 分）**
- 战斗画面与信息栏、卡片、面板、说明、关卡选择、结算画面属于同一套“协议面板”视觉语言。关卡选择、事件报告和图鉴按 2.1 第 5 条设计，素材自制。
- 没有拼凑和占位，控件不带浏览器默认样式，次要界面与战斗画面同样打磨。整体是否达到可以正式发行的商业游戏水准（2.11、3.6 第 1 条）。

### E 界面与交互（共 18 分）

**E1 地形与路线信息（4 分）**
- 地形状态（2.12 第 1 条）：
  - 各类格子不看文字一眼可辨；
  - 节点的直通、两种隔离、会造成封死、抑制中等状态，以及被改变过的格子，都看得出并实时更新；
  - 改变与恢复的那一刻有表现，有时限的看得出还剩多久；
  - 红色只表示危险、铜色只表示旧链路，信息元素带暗色细边，在明场和暗场（包括气隙深层）都看得清（2.1 第 3 条）。
- 路线与改道（2.12 第 2 条）：
  - 各入口的路线在重叠处仍能分辨归属、方向和出口，入口色贯穿路线、标识和流量预报；
  - 伪热点的航线与地面路线可以区分；
  - 改道时看得出哪些路线从哪里改到哪里、哪些敌人转向，不是一闪而过。
- 预览中的路线与当前路线可以区分，入口旁标出行程和出口的变化。操作被拒时，画面直接指出会被封死的入口或敌人。

**E2 战斗与局势信息（4 分）**
- 2.10 第 2 条的常驻信息齐全并始终显示，相应按钮始终可用。下列信息都看得出（2.12 第 3–4 条）：
  - 塔：生命、技能充能与就绪、正挡着谁、还能挡几个、受到攻击与生命危急；
  - 敌人：生命、身上的状态、正在攻击谁；
  - 洪泛团盯上了哪个节点。
- 各种塔、敌人和 Boss 一眼能区分，伪装的木马和潜伏的蛰影看得出位置。Boss 登场和它会改变通行的能力在生效前就醒目。每波开始前能看到敌人构成和出发入口；新敌人登场时能得知它的能力（2.12 第 4–5 条）。
- 混战和加速时主次分明，关键信息不被特效遮挡。被遮挡的单位仍能看出位置和生命；同一事物在各处的表示一致（3.6 第 2、5、6 条）。

**E3 反馈与过渡（3 分）**
- 2.12 第 6 条列出的各种时刻都有及时、彼此能区分的反馈。资源不足、位置不能部署等不能进行的操作，在操作之前或当时就有标示并说明原因；会封死的情形见 E1。胜负之后有写明结果和本局统计的结算画面。
- 表现出现在判定实际发生的时间和位置（3.6 第 4 条）。地形、路线、放慢、面板和画面的切换都有过渡，看得出从什么变成了什么（2.12 第 7 条）。

**E4 操作（5 分）**
- 镜头与布局（2.10 第 1 条）：
  - 战场占主体，默认视角能看全整张地图；
  - 能缩放、平移、旋转镜头，并能回到默认视角；镜头改变后，点选和拖放依然准确；
  - 界面沿画面边缘布置；选中塔时的面板不挡住这座塔和它的作用范围。
- 卡片与部署（2.10 第 3–6 条）：
  - 卡片显示外观、类型和价格，能否部署一眼可分，有等待时间的显示剩余时间，顺序稳定；
  - 拿起卡片时镜头回到默认视角；拖动时可部署的格子突出显示，悬停时预览作用范围、价格和光端机将点亮的格子；
  - 有朝向的塔能设定方向并实时预览；确认之前可以取消，不耗资源；
  - 从拿起卡片到部署完成或取消，以及选中场上的塔期间，游戏放慢。
- 选中与操作（2.10 第 7–8 条、2.9 第 3 条、3.6 第 6 条）：
  - 选中塔、敌人和地块时信息齐全，暂停时也能查看；
  - 升级、选分支、释放技能、撤下都可用，撤下和放弃本局有防误触；
  - 波次之间和进行中都能操作；可交互元素在悬停、选中、不可用时有区别。

**E5 说明与文案（2 分）**
- 游戏内能查看每种塔（含等级、分支、技能）、敌人（含攻击哪些目标）、Boss、道具、状态、特殊地形和配合效果的说明与属性。说明与实际表现一致；升级或选分支后，显示的属性随之更新（2.10 第 9 条、3.7）。
- 界面为简体中文，文案用系统日志的口吻（2.1 第 1 条、第四节第 4 条）。

### F 运行质量（共 8 分）

**F1 时钟与重开（4 分）**
- 时钟（2.9 第 5 条、2.10 第 6 条、3.5 第 1–2 条）：
  - 可以暂停，可以加速到至少 2 倍；
  - 攻击、状态、充能、冷却和资源增长都按游戏时间计，暂停时停止，放慢时放慢；
  - 加速时不穿格、不跳格、不漏扣中枢完整度；
  - 暂停期间的操作，恢复后按改道规则生效。
- 操作、切页与重开（2.9 第 6 条、3.5 第 3–4 条）：
  - 快速连续操作不会重复结算；
  - 切走标签页再切回，不瞬移、不跳判定、波次不错乱；
  - 结算后和一局进行中都能重新开始或返回关卡选择，无需刷新页面，新的一局不残留上一局的状态。

**F2 流畅与报错（4 分）**
- 在 Chrome 或 Edge 中正常运行，控制台无报错，不卡死。正常游玩和敌人很多时是否流畅，结合场面规模与画面质量综合评价，资源占用高低不直接决定得分。
- 能读出帧率、每帧耗时和场上对象数量，游戏内说明了查看方式。抽查一两处是否属实，读数不可靠的酌情扣分（第四节第 3 条）。

## 五、分值分配的理由与备选

### 1. 理由

- **玩法层 A + B + C = 58。** 题面第二、三节的大部分篇幅和最难的耦合都在 2.3–2.9 与 3.1–3.4。现行方案里对应的部分是玩法 20 + 关卡 14 + 正确性中除“速度控制与流程”以外的 25，共 59 分。去掉无题面依据的“创意” 4 分后为 55；新方案给 58，略增，因为改道与资源结算是本题最难的耦合。
- **A、B 各 22。**
  - A 是题眼：题名和第一节都以“隔离—改道—塔倒路开”为中心，最容易出错的是改道和封死判定。现行方案里它只占 12 分的一个分项，偏低。
  - B 的内容最宽：8 塔、8 敌、3 Boss、4 道具，加一条状态链。
  - 两者都是题面写得最细的部分，等分最不偏颇。
- **C 14，与现行的“关卡与波次”持平。** C 新收了资源规则（原在正确性里），交出了单位一侧的策略判断。地图已由题面写定，“做没做到”容易核对；平衡与难度是主观判断，评分时间内难以深测，所以不宜更高。
- **D 16、E 18。**
  - 篇幅大致相当，所以两者分值接近。按非空白字数统计，2.1 + 2.11 约 2300 字，2.10 + 2.12 约 1950 字；后者再加上 2.1 第 5 条的界面要求、3.6 第 4–6 条和 3.7，也约 2300 字。
  - E 略高。动态改道的塔防里，“看得懂路线和局势”直接决定能不能玩；E 还接过了 3.7（说明与实际一致）。
  - D 比现行多 2 分，但交出了可区分性等可读性要点，净范围略小。它是视频里最直观的差异，商业发行水准的门槛也在这里。
- **F 8。** 现行“速度控制与流程 3 + 性能 4”约为 7。现在全部 3.5 都在这里，但按约束性能只做综合评价、不精确测帧，所以只略高于现行。

### 2. 备选

| 备选 | 取舍 |
|---|---|
| 保留“系统正确性”作为横切方向（现行思路） | 不采纳。正确性是每个子系统都有的一种质量，单列就必然与内容方向重叠（见第一部分第 2、5 条） |
| 单设“策略深度”方向（MDA 的动态层） | 不采纳。策略来自单位、地图、资源的共同作用，单列就要重评这三者（见第一部分第 3 条） |
| 把 A、B 合为一个“玩法规则”方向，约 44 分 | 不采纳。分值过大，视频里也看不出“动态寻路”这个题眼做得怎样 |
| 把 E 拆成“信息呈现”和“操作”两个方向 | 需要 7 个方向；或者把运行质量并回别处，又回到“操作与技术”式的捆绑。HEP 也把界面与操作元素放在同一个 Usability 类里 |
| 资源规则按耦合拆分：情报归 A，算力归 B | 不采纳。一次撤塔的结算要到两处找，而且 2.9 第 2 条本来就是一个整体 |
| 分值改为 A 24 / B 20 | 更突出题眼，可行，但 B 的内容量最大，20 分略紧。供用户选择 |
| 分值改为 D 18 / F 6 | 更偏视觉，也可行。但 F 里的时钟一致性是实打实的正确性问题，6 分偏低 |

### 3. 方向名的备选

- **C**：“关卡与经济”点明了资源，推荐。“关卡与平衡”更像主观评价，但看不出它还要评资源规则。
- **E**：“界面与交互”是行业通用说法，推荐。“信息与操作”更直白，但读起来像两件事。
- **F**：“运行质量”推荐。“运行与性能”容易让人只想到帧率，忽略时钟与重开。

## 附：参考资料

- Hunicke、LeBlanc、Zubek 2004 年的论文 *MDA: A Formal Approach to Game Design and Game Research*。[搜索摘要]
  - https://users.cs.northwestern.edu/~hunicke/MDA.pdf
  - 论文分三层：机制是规则与数据，动态是机制在玩家输入下运行出来的行为，美学是玩家的情感体验；设计者只能直接控制机制。
  - 本文借这三层区分“规则做对没有”（A、B）和“运行出来的取舍与难度”（C 的质量部分、B1 的“各有用处”）。美学层即“综合体验”，按用户要求不设方向。
- Desurvire、Caplan、Toth，*Using Heuristics to Evaluate the Playability of Games*，CHI 2004。[已读原文]
  - https://hci.rwth-aachen.de/materials/conferences/CHI2004/2p1509.pdf
  - 四类启发式：Game Play（取胜要面对的挑战）、Game Story、Game Mechanics（单位与环境交互的结构）、Game Usability（界面以及鼠标、键盘、HUD 等交互元素）。
  - Usability 支持把信息呈现与操作合为 E。这套分类本身也有重叠：Mechanics 第 6–7 条讲操控，Usability 第 12 条讲美术辨识度。所以本文不照搬框架的类目，而是按可观察的事逐条划界。
- IGF 的 Excellence in Design 奖项说明。[搜索摘要，原页现已 404]
  - https://igf.com/article/here-are-your-juries-igf-2017-design-audio-and-narrative-awards
  - 该奖评游戏的“底层蓝图”，组成部分是关卡设计、机制设计和难度平衡；Visual Art、Audio 由各自的评审团分开评。
  - 本文据此让设计、美术、技术各成方向。设计部分题面篇幅过半，所以再按子系统分成 A、B、C。
- Ludum Dare 规则（2017 存档）及参赛者公布的成绩。[搜索摘要、二手]
  - https://ludumdare.com/resources/archive/rules-2017/
  - 评分类别有 Overall、Fun、Innovation、Theme、Graphics、Audio、Humor、Mood 等，各届不同。用第三方素材可以退出 Graphics、Audio 评比，说明美术是可独立评价的维度。
  - Overall 和 Fun 是整体感受类，对应用户已删去的“综合体验”，不采用。Innovation 对应现行的“创意”，因本题设定已给定而删去。
