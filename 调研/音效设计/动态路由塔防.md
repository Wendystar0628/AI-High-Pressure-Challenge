**稿子一：第二节新增，放在 2.13 之后**

### 2.14 声音

游戏有完整的声音：环境声、音乐、音效和界面的声音。所有音效和音乐都由你自己制作。

1. **声音的语言。** 声音和 2.1 的画面是同一套语言。网络空间里的声音来自信号、协议和包流；不用枪炮、爆炸、怪物吼叫和刀剑金属声。
   - 守方的声音像光和玻璃：干净、短促、音高明确，起落干脆，像端口灯亮起、继电器吸合、玻璃轻碰。守方的音效和这张图的音乐在同一个调上，许多座塔同时攻击时叠成和声。
   - 敌方的声音像坏掉的信号：颗粒、杂音、卡顿、断续、倒放和失真，音高含混，带故障般的抖动。
   - 声音的分工和颜色一致：急促的警报只用于危险（中枢受损、Boss 预警、塔的生命危急、操作会造成封死）；温暖、发闷、略带失真的“铜色”音色只用于旧链路（旧链路、协议降级、降级技能、撬开封存旧通道）。
   - 入口 A、B、C 各有一个固定的三音动机，与入口色一一对应；声音里凡是要指明入口的地方，都用这个动机。
2. **三张图的环境声与音乐。**
   - 分段内网：明亮通透的机房底噪，远处服务器风扇的轻嗡，链路里的包流像雨点落在玻璃上一样细碎地滴答，每隔几秒一声心跳包般的轻“嘀”。音乐是干净稀疏的玻璃键音，下面铺着柔和的长音，大调，每分钟约 92 拍。
   - 骨干流域：公网流自西向东奔流，宽阔的流水声从画面左侧流向右侧；南边两座数据中心各有一层温暖的低音嗡鸣，镜头靠近时更清楚。音乐是持续流动的琶音和脉冲，冷暖交替，每分钟约 104 拍。
   - 气隙深层：深渊里极低的嗡鸣和空旷的回声；控制核心按固定的周期发出扫描的“嗒、嗒”声；头顶不时透下上层网络隔着一层的模糊声响。音乐低沉、缓慢、紧张，留着大段空白，每分钟约 76 拍。
   - 主菜单和关卡选择有一段主题音乐，由三个入口的动机组成。悬停在一团网络上时，轻轻放出这张图的环境声；选中后镜头飞进去，一道穿越的呼啸之后落进这张图的环境声里。
3. **随战局变化的音乐。** 每张图的音乐分成几层，随战局增减；层次的变化在小节处衔接，不突然切断。
   - 布防（波次之间）：只有铺底和稀疏的旋律。
   - 交战（波次进行中）：加入由包流的点击声组成的节奏层。
   - 告急（中枢完整度低于 30%，或有敌人离出口很近）：再加入紧张的高音颤动和心跳般的低音脉冲。
   - 洪峰：三个入口的动机同时响起，随后节奏加倍、各层齐奏，直到这一波结束。
   - Boss 登场：画面边缘泛红时一声低沉的警报，名牌横扫过屏幕时一道横扫声，音乐转为这个 Boss 的主题；换阶段时主题随之改变（见第 6 条）；Boss 被消灭后回到这张图的音乐。
   - 胜利：主题旋律在明亮的大调上完整奏出一遍，然后进入“事件报告”。失败：音乐失真、卡顿，像断电一样沉到静默，最后一声“系统停机”。
4. **塔。**
   - 每种塔都有：部署时端口座落定的一声“咔嗒”，接着两音上行的上线提示和这种塔自己的特征音；升级时一道由低到高的扫描声，落在更饱满的和弦上，两个分支落在不同的音上；撤下时，按住期间有一个随进度升高的蓄力音，中途松开就回落，撤下完成是两音下行的下线声；受击是玻璃被敲的一声短“叮”，生命越低越尖；生命危急时每隔几秒一声短促的警示；技能充满时一声清亮的就绪音；被勒索者打中时一声锁扣，被加密时一声沉重的上锁，解除时锁链碎开；被摧毁时玻璃碎裂，接着是线段沉入地块的下行滑音。
   - 防火墙：平面脉冲是一声低沉干脆的“嗡”；敌人压在膜上时，膜绷紧的低音随压上来的敌人变多而加重；封禁时一串快速的闭合声收在一声厚重的合门声上，封禁期间低音一直在；2 级的扫描带每扫过一次响一声扫描音。
   - 蜜罐：旋转的漩涡带着甜美的、风铃般的和声；诱饵光点是轻盈的气泡声；诱捕时旋臂甩出“嗖”的一声，敌人被卷过来时一道螺旋上行音，收拢成笼时“咔”。高交互的漏斗声更深更空；蜜网是几团小和声叠在一起。
   - 网闸：部署时两块厚板合拢，一声沉重的“咚”；小方块跳过缝隙时一声轻“嘀”。单向网闸的“嘀”只朝一个方向移动。
   - 拦截器：光针是极短、极高、干净的“啾”，命中时细小的一声“嗒”。穿透的光针更锐，穿过几个敌人就连响几声“嗒”；压制的光针带一圈向外扩散的环音，打中伪热点时是信号中断的“滋—啪”。
   - 探针：检测光束扫过时有轻柔的扫频声；特征弧每跳到一个敌人响一个音，几个音依次上行，连成琶音。特征更新时一串快速的“下载”嘀声，生效期间攻击声更密；2 级双眼的攻击声是两个声部。
   - 沙箱：抛出采样立方时一声“呼”，落地展开时玻璃方格拼合的“咔嚓”；引爆舱留下的玻璃区持续发出低声的共鸣，时间到了才消散。
   - 均衡器：光环缓缓旋转的柔和摆动音；治疗是一串顺着细线流进塔身的上行小音；冗余切换是一声宽阔的和弦，每座塔套上护盾时一声“嗡”。双活的治疗是两条交替的旋律；热备的复影环飞出时“嗖”，套上时一声柔和的“叮”。
   - 光端机：光源持续发出极轻的高音；点亮暗光纤时每亮一格响一声，音高逐格升高，打通时一声开通音；熄灭时逆序下行。降级时光束变成铜色，声音随之变成铜色音色，结束后恢复清亮。
5. **敌人。** 每种敌人都有行进、攻击、受击和被消灭的声音；被消灭时碎成暗包漏下去，是一串下行的颗粒散落声。
   - 蠕虫：一伸一缩、颗粒般的蠕动节奏；复制时链节每复印一节响一声，连成一串复印机般的“嗒嗒嗒”。
   - 洪泛团：无数小包挤在一起的翻涌嘈杂声；盯上节点时一声低沉的锁定音；拉成洪流时声音变成一道急促上冲的冲刷声，撞上节点时一声沉重的冲击。
   - 木马：伪装时只发出和正常包流一样的轻“嘀”，听不出异样；外壳裂开时“咔嚓”一声，露出暗核的低音；载荷炸开时一声闷响，夹着数据碎片声。
   - 勒索者：行进时是锁链拖动的、数字化的摩擦声；甩出密文链段时“嗖—锵”。
   - 撬锁者：钥匙齿碰撞的细碎铃声；撬锁时一串越来越快的拨动声表示进度，被打断时一声下滑的失败音；撬开时锁符碎开，接着是铜色音色的旧链路接通声。
   - 零日：几乎无声，它附近的环境声被吸走一块，像真空；穿过阻挡塔时一声撕裂；成为已知时，所有改写声骤停，定格成一声清晰的“叮”。
   - 伪热点：一圈圈波纹般的颤音，听起来在空中，随它在画面上的位置移动；劫持隔离器时一阵逐渐升高的嗡声表示进度，得手时一声刺耳的信号劫持声；掉线时信号中断，跟着一道下坠的音。
   - 加壳器：几层壳转动的低沉“呼呼”声；剥壳甩出时“嘶啦”一声，壳套上同伴时“啵”，壳被打碎时一声碎裂。
6. **Boss。**
   - 万傀：成百个小设备齐声低鸣，夹着许多提线的细小“叮”。“洪峰”预警的 3 秒里蓄力声越来越密，冲击时一声巨响。细线成束断开时一串断弦声，掉下的方格化作一阵蠕虫声；主控核心越亮，主题越高、越亮。
   - 蜃楼：登场后场上的声音都带一层错位的回声，像被折射了一样。“伪路由”预警的 3 秒里，落点传出向内旋转的吸入声，黑洞形成时一声下坠的低音，消退时反向。“路由风暴”是一圈扩散的扰动声，被清掉护盾的塔各碎一声、被扣减充能的塔各一声下行音。外层线团碎裂时，大量玻璃线一齐断裂，露出的水晶内核带来清澈的高音和声，主题随之换成这一段。
   - 蛰影：“潜伏”时只有热浪般的低频颤动和心跳，几乎听不见；头冠撬开旧通道时，几根撬针同时拨动。“提权”时战术板每点亮一块响一个音，连成一条上行的音阶，甲片叠起时“咔、咔、咔”，吐出零日时一阵吸走声音的空洞。“破坏”时身体裂开，一声巨大的撕裂；锁死段预警的 3 秒里，锁纹铺开的沙沙声和越来越快的锁扣节拍，锁死时一声沉重的“咚”。它的主题分潜伏、提权、破坏三段，一段比一段满。
7. **道具。**
   - 应急隔离器：规则环落下“叮—咔”，和节点隔离的声音合在一起；到期前 3 秒有倒计时的滴答，到期时规则环解开；被冲毁时一声碎裂，被劫持时一声信号劫持。
   - 协议降级：信标落地“噔”的一声，铜色音色的嗡声从落点漫开，结束时收回。
   - 频谱干扰：干扰网张开时一阵“沙——”，持续期间范围内有一层轻微的嘶嘶声；伪热点进到网里，颤音变得断断续续。
   - 备份还原：扫描光掠过塔身的上行扫频，落在一个柔和的和弦上；解除加密时锁链碎开。
8. **系统事件。**
   - 隔离与直通：隔离时节点两侧的光板竖起，各一声“嗡—咚”，包流在光板前堆住时的嘀声渐慢、渐停；恢复直通时一道上行的“咻——”，接通的一瞬一声“叮”；节点上的塔被摧毁时，碎裂声之后紧接着旁路光桥的接通声；抑制期间节点上有一层低低的嗡声。
   - 路由收敛：收敛波扫过地图时，一道从变化处向外扫开的宽阔声浪，约 1 秒；新路线一路亮向出口时一串快速的上行音，旧路线退去时下行淡出；改了道的入口各响一次自己的动机，听得出是哪几个入口改了道。同一时刻的几次改道只响一次。
   - 状态与配合：变成明文时一阵字符显露的沙沙声；变得可疑时一声取景框锁住的快门声；特征扩散时同种敌人头上的特征符号一齐亮起，响同一个音，细线连起时依次连成琶音；关联隔离时玻璃方盒扣下，一声带共鸣的“嗒”；清除时方盒连同敌人碎成像素，一阵颗粒碎响收在一个干脆的完成音上；退避时一声下滑音。
   - 阻挡：敌人被挡住时膜上一声软软的“嘭”，阻挡解除时“啪”地松开。
   - 操作被拒：资源不足是一声空洞的“咔”；位置不能部署是一声闷“嗒”；操作会造成封死是两声低沉的“嘟—嘟”，接着被封死的入口的动机低沉地响一遍。这三种声音一听就能分开。
   - 资源：缴获或整理出情报时，一声两音上行的入库声；花费时一声轻“嗒”；卡片的端口灯因为资源够了而亮起时，一声很轻的亮灯音。算力的增长和回收不单独发声，以免太密。
   - 波次：每波开始前，这一波要出兵的入口依次响起各自的动机，随后一声低沉的“连接建立”；洪峰那一波三个动机同时响起，并带上警报；一波结束时，一个舒展的“清除”和弦。
   - 中枢：敌人进入出口时，中枢晶体一声低沉的“咚”，带着裂纹般的失真；敌人离出口很近时，一声逐渐升高的接近警示，同一时刻最多响一处；新种类的敌人第一次登场时，一声“未知特征”的提示。
   - 结算：“事件报告”逐行打印时一阵电传般的“嗒嗒”声，统计数字滚动时有轻微的计数声。
9. **界面。**
   - 悬停在按钮、卡片或格子上时，一声极轻的“嘀”，像端口灯闪一下，只在移到新的元素上时响一次；卡片悬停抬起时，一声更轻的升起音。
   - 拿起卡片时卡片收进光标，一声短促的吸入音；拖过地图时，每进入一个能部署的格子一声极轻的“嘀”，进入不能部署的格子是一声闷音；设定朝向时，每转过一个方向一声旋钮般的“咔哒”；确认部署响部署的声音；取消时卡片飞回，一声下行的“咻”。
   - 选中塔时面板展开，一声“嗖”和玻璃轻响，收起时反过来；悬停在分支卡片上时，先轻轻试响这个分支升级时的落点音；按钮按下一声清脆的“嗒”，返回和取消是两音下行。
   - 打开菜单、图鉴或暂停时，战场的声音变闷、变远，像隔着一层玻璃；关上后恢复。
   - 实战演示里光标的操作发出和玩家亲手操作时一样的声音；字幕出现时一声日志打印的“嘀”。
10. **速度、暂停与混音。**
    - 暂停：战斗的音效全部停住，正在响的尾音很快收掉；音乐和环境声变轻、变闷，界面的声音照常；恢复时回到原样。
    - 放慢（拿起卡片部署和选中塔期间）：战斗音效像慢动作一样变得低沉、拉长；音乐变闷，但不变调、不变速；放慢开始和结束时声音平滑过渡。
    - 加速：音效随事件变密，但每个声音本身的音高和长短不变，不像快放的录音那样变尖；音乐不加速。
    - 标签页切走时声音停下，切回后恢复，不会把这期间积下的声音一齐放出来。
    - 大量单位同时攻击时，同一种声音听起来是一阵密集的齐射，总音量不会成倍增大，也不破音；中枢受损、Boss 预警、操作被拒和路由收敛这几类重要的声音响起时，其他声音短暂让开，它们始终听得清。
    - 场上的声音按它在画面上的位置分在左右两侧，离镜头远的更轻；镜头拉近时细节更清楚。
11. **音量与开始出声。**
    - 菜单的“设置”里有一页声音设置：总音量，以及音乐、环境、音效、界面四类各自的音量，每一类都能单独静音；拖动时立即生效，松开时放一声这一类的样音。
    - 顶部信息栏有一个静音按钮，图标是一枚端口灯，静音时熄灭；按 M 键同样切换静音。
    - 这些设置在关闭页面后仍然保留。
    - 打开游戏时先显示开机画面“守护进程待命 · 点击接入”；玩家第一次点击或按键后，主菜单的音乐淡入。

### 3.8 声音

## 三、评分怎样落地

只回答一件事：评分 AI 怎样可靠地确认声音存在、并且在对应事件时响起。音色好不好不在范围内。

### 3.1 评分环境的事实

- 评分员用的是 `oneshot_browser`（chrome-devtools-mcp 1.12.0，配置见 `H:\AI_OneShot_Model\.oneshot\browser-mcp.json`），无窗口 Chrome 156。
- 它自带的 puppeteer 在无窗口模式下会给 Chrome 加上 `--mute-audio`：代码里写着（`build\src\third_party\index.js` 第 70683 行），实验时也在运行中的 Chrome 命令行里看到了这个参数。所以评分时页面不会有声音传出浏览器。
- 评分员是 Claude Code 和 Codex，本身也不能输入音频。所以“听”这条路不存在，只能靠看代码和测量。
- 好在 `--mute-audio` 只是在最后输出时静音，页面里的声音照样在生成、在计时。在页面内部旁听，仍然能拿到完整的声音信号。

### 3.2 方法一：看代码（先做，几分钟）

- 找到作品自己写的声音部分，列出定义了哪些声音、各在哪个事件的处理里被调用，对照 2.14 的类别，估计做了几成。
- 坑：作品里打包的 three.js（`three.min.js`）本身就含有 `AudioContext`。直接全文搜索会误以为作品有声音，只能看作品自己的代码。
- 局限：代码里有，不等于真能出声。例如音频环境一直没有恢复、音量节点是 0、声音没接到输出上，或者调用时报错。所以要再用方法二确认一次。

### 3.3 方法二：运行时的“声音探针”（本次实验验证可行）

做法：评分员打开作品时，用 `navigate_page` 的 `initScript` 参数注入一段脚本。它在作品的任何代码之前运行，只旁听，不改变作品的声音。也可以在自己的副本里把它作为 `index.html` 的第一个脚本引入，效果相同。

它做三件事：

1. 凡是接到扬声器上的声音（包括 Web Audio 和 `<audio>` 元素），都另接一路到电平表上，每约 21 毫秒记一次电平，并保留最近约 3 分钟的录音；
2. 每发出一个声音，就记下是作品代码里哪个函数、哪一行发出的；
3. 记下评分员真实的点击和按键。

读结果用四个函数：

| 函数 | 给出什么 | 回答什么问题 |
|---|---|---|
| `__snd.sites()` | 发过声的代码位置、次数、首末时刻，例如 `noise @test.html:62 ← HTMLButtonElement.<anonymous> @test.html:71` | 哪些事件挂了声音、实际响过没有（函数名基本就说明了是哪个事件） |
| `__snd.report()` | 每次点击或按键之后约 0.6 秒内，电平有没有明显升高、隔了多少毫秒 | 界面操作、部署、升级、技能、道具这些评分员亲手触发的事件有没有声音 |
| `__snd.strip(起, 止)` | 一段时间里每 0.25 秒的电平 | 暂停、静音、调音量、重新开始前后声音怎么变 |
| `__snd.wav(起, 止)` | 一段录音（WAV） | 配合 `evaluate_script` 的 `filePath` 参数直接存成文件，不进对话上下文；再画成电平图和频谱图，标上点击时刻，看一眼就知道哪里有声音 |

### 3.4 实验

- 环境：本机，用评分员同一套 `oneshot_browser` 和同样的启动参数，通过 MCP 协议驱动（`navigate_page` 注入、`click` 点击、`evaluate_script` 读结果）。
- 测试页：模拟九种情形，覆盖游戏里常见的几种发声方式（实时生成的音、预先做好的声音片段、`<audio>` 元素、载入时就建好的音频环境），并故意放进“无声”和“假出声”两种情形。
- 文件位置：`C:\Users\Administrator\AppData\Local\Temp\claude\E--Project-AI-OneShot-Bench\00229dd5-4e38-471e-895e-c1790288b388\scratchpad\td_audio_probe\`（`sound_probe.js` 探针、`test.html` 测试页、`drive.mjs` 驱动、`plot_rec.py` 画图、`rec.png` 结果图）。探针全文附在文末。

结果（“声音何时出现”从评分员点击的 pointerup 算起）：

| 情形 | 有没有判对 | 声音何时出现 |
|---|---|---|
| 点击“开始”：建立音频环境，启动持续的环境声 | 判为有声，环境声一直被记录 | 99–132 ms |
| 部署：实时生成的扫频音 | 有声 | 约 95 ms |
| 命中：预先做好的噪声片段 | 有声 | 约 105 ms |
| 波次开始：`new Audio()` 播放一段声音文件 | 有声 | 约 180 ms |
| 载入时就建好的音频环境，第一次点击后恢复，再响一声 | 有声 | 约 77 ms |
| 无声事件（只有画面变化） | 判为无声 | — |
| 假出声：发声调用照常，但音量为 0 | 判为无声，尽管调用记录里有这次发声 | — |
| 暂停（音频环境挂起）到继续 | 暂停期间电平为静音，继续后恢复 | — |
| 60 个声音同时响 | 有声，并测到破音 | 约 95 ms |

结论：

1. **静音的无窗口 Chrome 里可以可靠地确认有没有声音。** 九种情形全部判对，声音出现在点击后 0.1–0.2 秒内，0.6 秒的窗口足够用。
2. **只看调用记录不够，必须看电平。** “假出声”一例中代码确实调用了发声，但实际没有声音；只有电平能分辨出来。
3. **浏览器的出声限制在无窗口模式下同样存在。** 第一次点击之前建立的音频环境一直是挂起状态。通过 MCP 的 `click` 点击之后，作品如果恢复了音频环境，就能出声。所以：
   - 评分员要先点一次页面再检查声音；
   - 作品自己要在玩家第一次操作时恢复声音，这就是题面第四节新增那条提醒的原因。
4. **能把声音对到事件上。** `sites()` 给出的调用位置直接指向作品的函数和行号。评分员不用逐个手动触发事件，打一波下来就能看到“塔被摧毁、波次开始、Boss 登场”这些函数有没有发过声。Boss 主题、音乐层次这类变化，再配合 `strip()` 看前后的电平，或者回到代码里看一眼。
5. **录音能存成文件、画成图。** 15 秒的录音约 1 MB，经 `filePath` 直接写盘。附带的画图脚本生成电平图和频谱图，评分员可以直接看图片。

局限：

- 录音只用来判断有没有声音、什么时候响，不保证音质；页面主线程很忙时会有零点几秒的缺口。
- 探针会给主线程加一点负担。测性能要在不注入探针的另一次打开里做。
- 只覆盖 Web Audio 和 `<audio>`、`<video>` 元素。网页游戏的声音几乎都走这两条路。

试过、不采用的办法：

- 录系统声音：要开有窗口、不静音的浏览器，会录进整台机器的声音，并行评分时互相串音，也违反评分员提示词里“不要占用用户桌面”的规定。
- chrome-devtools-mcp 的录屏（`screencast_start`）：只有画面，没有声音。
- 网页的屏幕或标签页共享：需要额外的启动参数和授权，评分员用的浏览器没有这些参数。

### 3.5 评分员实际怎么做（供用户参考，不写进指南）

1. 看代码，列出声音和挂接位置，估计做了几成。
2. 带探针开一局，顺带检查声音：
   - 先点“接入”；
   - 在设置里把总音量拉到 0 再拉回，点一次静音；
   - 进一张图，部署、升级、放技能、用道具、隔离一个节点，打完一波；
   - 暂停几秒，切到 2 倍速，重新开始一次。
3. 读 `sites()`、`report()` 和暂停、静音、重开前后的 `strip()`；需要时存一段录音看图。

这一局可以和其他分项的试玩合在一起，不用另外花时间。

### 3.6 建议把探针放进评分资料

建议把探针作为测量工具放进 `Grading\游戏设计与开发\动态路由塔防\声音探针.js`，文件开头写清用法。它和性能题的 `evaluate.py` 一样，只是测量仪器，不含评分规则。评分指南只加一句指向它。

不放的话，评分员在静音的浏览器里很可能把“听不到”当成“没有声音”。要自己临时写一个录音工具也不容易：这次实验就先后踩了三个坑：

- 预先做好的声音片段有自己的播放入口，第一版没记到它的发声；
- 作品和 `<audio>` 用了不同的音频环境，第一版录出的 WAV 混在一起；
- 浏览器的出声限制让第一次点击之前建立的音频环境一直挂起。

## 六、需要用户拍板的问题

1. **分值从哪里来**：甲（推荐，美术和单位与战斗各出 1 分）、乙（信息与操作内部腾 2 分）还是丙（不设分项，并进“反馈与过渡”）。
2. **题面第七节要不要明说“不评音色”。** 建议不明说。评分表那一行已经写成“是否做出来、是否在对应事件时响起”；明说“不评好不好听”，模型可能只做几声简单的提示音应付，而用户录视频要用这些声音。
3. **第四节那条提醒要不要写“评测环境听不到声音”。** 写上能让模型别花时间去找不存在的声音输出，不写也不影响评分。建议写。
4. **要不要把声音探针放进评分资料。** 建议放，指南加一句；不放的话，评分员容易在静音浏览器里误判“没有声音”。
5. **音乐的调式和拍速（大调、每分钟约 92/104/76 拍）留不留在题面里。** 这是出题人定下的设计，留着更具体；嫌细可以只保留“明亮、流动、低沉”的描述。
6. **“设置在关闭页面后保留”留不留。** 留着工作量更足；评分员用的是临时的浏览器资料目录，只能在同一次打开里刷新页面来检查。

// 声音探针：在页面任何脚本之前注入（navigate_page 的 initScript）。
// 只旁听，不改变作品的声音：把接到扬声器的所有声音另接一路到电平表，并记录发声调用。
(() => {
  if (window.__snd) return;
  const AC = window.AudioContext || window.webkitAudioContext;
  if (!AC) return;
  const t0 = performance.now();
  const now = () => +(performance.now() - t0).toFixed(1);
  const blocks = [];          // {t, rms, peak} 每块约 21 ms
  const calls = [];           // {t, kind, detail}
  const marks = [];           // {t, label}
  const ctxs = [];
  const taps = new WeakMap(); // context -> tap gain
  const origConnect = AudioNode.prototype.connect;
  const origDisconnect = AudioNode.prototype.disconnect;
  const own = new WeakSet();

  function tapOf(c) {
    if (taps.has(c)) return taps.get(c);
    const tap = c.createGain(); own.add(tap);
    const sp = c.createScriptProcessor(1024, 2, 2); own.add(sp);
    const zero = c.createGain(); zero.gain.value = 0; own.add(zero);
    origConnect.call(tap, sp); origConnect.call(sp, zero); origConnect.call(zero, c.destination);
    sp.onaudioprocess = e => {
      const ib = e.inputBuffer; let s = 0, p = 0; const n = ib.length;
      for (let ch = 0; ch < ib.numberOfChannels; ch++) {
        const d = ib.getChannelData(ch);
        for (let i = 0; i < n; i++) { const x = d[i]; s += x * x; const a = x < 0 ? -x : x; if (a > p) p = a; }
      }
      const rms = Math.sqrt(s / (n * ib.numberOfChannels));
      let t = now();
      try { const ts = c.getOutputTimestamp(); t = +(ts.performanceTime - t0 + (e.playbackTime - ts.contextTime) * 1000).toFixed(1); } catch (_) {}
      const mono = new Float32Array(n);
      for (let ch = 0; ch < ib.numberOfChannels; ch++) { const d = ib.getChannelData(ch); for (let i = 0; i < n; i++) mono[i] += d[i] / ib.numberOfChannels; }
      blocks.push({ t, rms, peak: p, sr: c.sampleRate, pcm: mono, cid: ctxs.indexOf(c) });
      if (blocks.length > 9000) { for (let k = 0; k < blocks.length - 9000; k++) blocks[k].pcm = null; }
      if (blocks.length > 200000) blocks.splice(0, 50000);
    };
    taps.set(c, tap);
    return tap;
  }
  const isLive = c => typeof OfflineAudioContext === 'undefined' || !(c instanceof OfflineAudioContext);

  AudioNode.prototype.connect = function (dest, ...rest) {
    const r = origConnect.call(this, dest, ...rest);
    if (dest instanceof AudioDestinationNode && !own.has(this) && isLive(dest.context)) {
      try { origConnect.call(this, tapOf(dest.context)); } catch (_) {}
    }
    return r;
  };
  AudioNode.prototype.disconnect = function (...args) {
    const d = args[0];
    if (d instanceof AudioDestinationNode && isLive(d.context) && taps.has(d.context)) {
      try { origDisconnect.call(this, taps.get(d.context)); } catch (_) {}
    }
    return origDisconnect.apply(this, args);
  };

  function Patched(...a) { const c = new AC(...a); ctxs.push(c); calls.push({ t: now(), kind: 'AudioContext', detail: c.state }); return c; }
  Patched.prototype = AC.prototype;
  Object.setPrototypeOf(Patched, AC);
  window.AudioContext = Patched; if (window.webkitAudioContext) window.webkitAudioContext = Patched;

  // 发声调用来自作品代码的哪几层函数（去掉探针自身那一层），用来把声音对到事件
  const site = () => (new Error().stack || '').split('\n').slice(3, 7).map(l => l.trim().replace(/^at /, '').replace(/\(?(?:file|https?):\/\/[^)]*\/([^/):]+):(\d+):\d+\)?/, '@$1:$2')).join(' ← ');
  for (const K of [AudioScheduledSourceNode, window.AudioBufferSourceNode, window.OscillatorNode, window.ConstantSourceNode]) {
    if (!K || !Object.prototype.hasOwnProperty.call(K.prototype, 'start')) continue;
    const origStart = K.prototype.start;
    K.prototype.start = function (...a) {
      if (!own.has(this) && isLive(this.context)) calls.push({ t: now(), kind: this.constructor.name, detail: this.context.state, site: site() });
      return origStart.apply(this, a);
    };
  }
  // 记录真实的输入事件（评分员的点击、按键），用来对齐“操作 → 声音”
  for (const type of ['pointerdown', 'pointerup', 'keydown']) {
    addEventListener(type, e => { if (e.isTrusted) marks.push({ t: now(), label: type + (e.key ? ':' + e.key : '') + ' ' + ((e.target && (e.target.innerText || e.target.id || e.target.tagName)) || '').toString().slice(0, 16) }); }, true);
  }

  // 媒体元素（<audio>、new Audio()）：用 captureStream 旁听，不改变它的输出
  let mctx = null; const hooked = new WeakSet();
  const origPlay = HTMLMediaElement.prototype.play;
  HTMLMediaElement.prototype.play = function (...a) {
    calls.push({ t: now(), kind: 'media.play', detail: (this.currentSrc || this.src || '').slice(0, 60), site: site() });
    const r = origPlay.apply(this, a);
    if (!hooked.has(this) && this.captureStream) {
      hooked.add(this);
      try {
        if (!mctx) { mctx = new AC(); ctxs.push(mctx); }
        if (mctx.state !== 'running') mctx.resume();
        const go = () => { try { const src = mctx.createMediaStreamSource(this.captureStream()); origConnect.call(src, tapOf(mctx)); } catch (e) { calls.push({ t: now(), kind: 'probe.err', detail: String(e) }); } };
        if (this.readyState >= 1) go(); else this.addEventListener('loadedmetadata', go, { once: true });
      } catch (e) { calls.push({ t: now(), kind: 'probe.err', detail: String(e) }); }
    }
    return r;
  };

  const db = x => x > 0 ? +(20 * Math.log10(x)).toFixed(1) : -120;
  window.__snd = {
    mark(label) { marks.push({ t: now(), label }); return now(); },
    state() { return { contexts: ctxs.map(c => c.state), blocks: blocks.length, calls: calls.length, marks: marks.length, now: now() }; },
    // 每个标记之后 windowMs 内：电平是否明显高于标记前、几时开始、调用了哪些发声
    report(windowMs = 600, preMs = 300) {
      const sorted = blocks.slice().sort((a, b) => a.t - b.t);
      return marks.map((m, i) => {
        const end = Math.min(m.t + windowMs, i + 1 < marks.length ? marks[i + 1].t : Infinity);
        const pre = sorted.filter(b => b.t >= m.t - preMs && b.t < m.t);
        const post = sorted.filter(b => b.t >= m.t && b.t < end);
        const base = pre.length ? Math.max(...pre.map(b => b.rms)) : 0;
        const peak = post.length ? Math.max(...post.map(b => b.peak)) : 0;
        const rmsMax = post.length ? Math.max(...post.map(b => b.rms)) : 0;
        const on = post.find(b => b.rms > Math.max(base * 2, 0.003));
        return {
          label: m.label, base_db: db(base), post_rms_db: db(rmsMax), post_peak_db: db(peak),
          sounded: !!on, onset_ms: on ? +(on.t - m.t).toFixed(0) : null,
          audio_blocks: post.length,
          calls: Object.entries(calls.filter(c => c.t >= m.t - 50 && c.t < end).reduce((o, c) => (o[c.kind] = (o[c.kind] || 0) + 1, o), {})).map(([k, n]) => n > 1 ? k + '×' + n : k).join(',')
        };
      });
    },
    // 一段时间里的电平条（每格 binMs），用来看暂停后是否安静、环境声是否持续
    strip(fromMs, toMs, binMs = 250) {
      const out = [];
      for (let t = fromMs; t < toMs; t += binMs) {
        const bs = blocks.filter(b => b.t >= t && b.t < t + binMs);
        out.push(bs.length ? db(Math.max(...bs.map(b => b.rms))) : null);
      }
      return out;
    },
    clipping(fromMs = 0, toMs = Infinity) {
      const bs = blocks.filter(b => b.t >= fromMs && b.t < toMs);
      return { blocks: bs.length, clipped: bs.filter(b => b.peak >= 0.999).length, max_peak_db: db(Math.max(0, ...bs.map(b => b.peak))) };
    },
    // 导出一段录音（16 位单声道 WAV 的 base64），配合 evaluate_script 的 filePath 存成文件
    wav(fromMs = 0, toMs = Infinity, outSr = 24000) {
      const bs = blocks.filter(b => b.pcm && b.t >= fromMs && b.t < toMs).sort((a, b) => a.t - b.t);
      if (!bs.length) return '';
      const start = bs[0].t, last = bs[bs.length - 1], endT = last.t + last.pcm.length / last.sr * 1000;
      const n = Math.ceil((endT - start) / 1000 * outSr), mix = new Float32Array(n);
      // 每个声音环境的块按顺序首尾相接；挂起后出现空档时重新对时；各环境再按时间混在一起
      const runs = new Map();
      for (const b of bs) {
        const dur = b.pcm.length / b.sr * 1000, r = runs.get(b.cid);
        let at = b.t;
        if (r && Math.abs(b.t - r.next) < dur * 1.5) at = r.next;
        runs.set(b.cid, { next: at + dur });
        const off = (at - start) / 1000 * outSr, step = outSr / b.sr;
        for (let i = 0; i < b.pcm.length; i++) { const k = Math.round(off + i * step); if (k >= 0 && k < n) mix[k] += b.pcm[i] * Math.min(1, step); }
      }
      const buf = new ArrayBuffer(44 + n * 2), v = new DataView(buf);
      const w = (o, str) => { for (let i = 0; i < str.length; i++) v.setUint8(o + i, str.charCodeAt(i)); };
      w(0, 'RIFF'); v.setUint32(4, 36 + n * 2, true); w(8, 'WAVEfmt '); v.setUint32(16, 16, true); v.setUint16(20, 1, true); v.setUint16(22, 1, true);
      v.setUint32(24, outSr, true); v.setUint32(28, outSr * 2, true); v.setUint16(32, 2, true); v.setUint16(34, 16, true); w(36, 'data'); v.setUint32(40, n * 2, true);
      for (let i = 0; i < n; i++) v.setInt16(44 + i * 2, Math.max(-1, Math.min(1, mix[i])) * 32767, true);
      const u8 = new Uint8Array(buf); let bin = ''; for (let i = 0; i < u8.length; i += 0x8000) bin += String.fromCharCode.apply(null, u8.subarray(i, i + 0x8000));
      return JSON.stringify({ start_ms: start, sr: outSr, marks: marks.filter(m => m.t >= fromMs && m.t < toMs), b64: btoa(bin) });
    },
    // 按调用位置汇总所有发声：哪些函数发过声、各多少次、第一次和最后一次在什么时候
    sites() {
      const m = {};
      for (const c of calls) { if (!c.site) continue; const k = c.kind + ' | ' + c.site; (m[k] = m[k] || { n: 0, first: c.t, last: c.t }); m[k].n++; m[k].last = c.t; }
      return Object.entries(m).map(([k, v]) => ({ site: k, ...v })).sort((a, b) => b.n - a.n);
    },
    _calls: calls, _marks: marks
  };
})();
