# 果冻冲击与造浪水槽

## 一、目标总览

在网页中制作两个可独立演示的三维物理模拟场景：重球冲击果冻，以及同尺寸、多密度的小球在透明造浪水槽中的浮沉与运动。作品的内容是软体、刚体与液体之间的双向作用：果冻被砸得大幅变形、回弹，重击下开裂；小球入水激起飞溅，造浪装置推出的浪越来越陡，直到翻卷破碎。

作品内置四段演示，会剪入测评视频，要求见第五节。舞台、水槽、镜头和演示编排由你设计。

## 二、场景一：重球冲击果冻

### 2.1 舞台与主体

台上不止一块果冻，它们的软硬、结实程度或形状不同；重球用金属或石质等刚硬材质，质量和大小可以不同。果冻半透明，形变时体积轮廓和表面起伏看得清。

### 2.2 冲击中的现象

轻击只压出浅坑，果冻小幅振荡后复原。重击时果冻被大幅压扁、四周鼓出，表面包住球，随后把球弹起或吞住；变形从受击处向全身展开，各部位先后回弹，振荡逐渐衰减。整个过程中果冻的体积基本不变，不会被压瘪。

偏心或斜向的冲击使果冻倾斜、摇晃、在台面上滑移，甚至翻倒；球沿果冻表面滚落，继续和台面、其他球、其他果冻相碰。同一颗球落在软硬或形状不同的果冻上，结局明显不同，球也可以在果冻之间弹跳。后一球落在前一次振荡尚未平息的表面上时，振荡叠加放大或相互抵消。

冲击够重而果冻不够结实时，果冻开裂或被砸开，裂口从受击处出现；分开的碎块仍是有弹性的果冻，继续变形、晃动，与球、台面和别的碎块相碰。冲击不够重或果冻更结实时，果冻只变形、回弹，不开裂。

果冻调软或重球加重，凹陷更深、鼓出更大、振荡更慢。开裂由冲击轻重和果冻的软硬、结实程度共同决定：加重冲击或降低结实程度，同一落点的结局从只变形回弹，变为开裂，再到被砸开；反过来则只变形、不开裂。

### 2.3 三种冲击

三种冲击可以分别触发：

- **正中**：重球正对果冻落下。
- **偏心**：球偏离中心或斜向撞上果冻。
- **连续**：多颗球先后落下，后一球赶在前一次振荡平息之前落到果冻上。

## 三、场景二：多密度球与造浪水槽

### 3.1 水槽、小球与造浪装置

透明玻璃水槽中盛着水，水槽的形状比例和槽内地形由你设计。玻璃边缘有高光，反射不挡住槽内的运动；水透明或轻微染色，水面有反射和折射，水下的光影随水面起伏变化。

槽中放入多颗尺寸相同、密度不同的刚性小球。密度分 3～5 组，至少包含低密度、中性浮力和高密度三类，各组用颜色区分。

造浪装置可见，由它的运动推动水体；幅度可以从推出平缓长波一直调到推出破碎浪。

### 3.2 水与球的现象

小球从水面上方落入水中，砸出凹坑或空腔，激起水冠或回弹水柱，回落的水滴在水面荡出次级涟漪，球后带下气泡。球越重、落得越快，入水越猛。球沉入后水位随之上升，大批球入水时水面整体抬高并晃荡。各组球的浮沉方向和浸入深度随密度分化。

造浪开始后，浪从装置处长出，越往前越陡，浪顶翻卷、破碎成白水；白水在水面漂移，随后消散。浪在远端槽壁上爬、拍击、回落，反射回来与来波相遇；遇到槽内地形时爬升、越过或绕行。

浪中三层的球各有响应：浮球被浪峰托起、顺浪前推，在破碎处被抛起；悬在水中的球随往复的水流来回移动；槽底的重球随底流滚动，大浪时短暂离底。球与球、球与槽壁相碰后分开、转向、滚动，球群也反过来扰动局部水面。

造浪停止后，波逐次减小，白水散尽，各球重新找到各自的高度，位置可以与造浪前不同。

造浪幅度调低时是平缓长波，调高后浪变陡、翻卷、破碎，浮球被抛得更远；频率改变浪的间距；改变某组的密度，这组球的浮沉方向和浸入深度随之改变。

## 四、两个场景的共同要求

### 4.1 统一风格

两个场景采用统一的背景、灯光、材质细节、界面视觉语言和镜头语言，构成一套作品。灯光和阴影交代果冻的形变轮廓、水面起伏和球的接触位置。

### 4.2 控制与参数

两个场景都可以独立进入、触发、暂停、继续、慢放、重置和重新运行。场景一可以分别触发三种冲击；场景二可以再次释放小球，单独开始或停止造浪。界面上至少可调果冻的软硬与结实程度、重球的质量与下落高度、各组小球的密度、造浪的幅度与频率，改值后现象按 2.2、3.2 所写的方向变化。

### 4.3 音效

撞击、回弹、开裂、球体碰撞、入水和造浪等主要事件有相应的声音，与当时的动态相符，界面上可以开关。浏览器要求用户操作页面后才能播放声音。

### 4.4 动态来源

主要动态由模拟算出，改参数后随之变化。

## 五、演示与视频导出

### 5.1 四段演示

作品预置四段演示，各有主题和大致走向，具体编排由你设计：

- `jelly-center`（正中单击）：一记重球正中落下，果冻包住球、压扁、四周鼓出，再把球弹起，余振平息；果冻不裂。
- `jelly-multi`（连击）：一记比一记重的冲击接连落在尚未平息的振荡上，最后一击把果冻砸裂，碎块分开后仍在晃动。
- `jelly-offset`（偏击）：球偏离中心撞上果冻，果冻倾斜、滑移，球滚落后与台上其他物体相碰；果冻不裂。
- `tank-full`（风浪）：平静的水槽中各组小球入水、按密度分化；浪由小变大、变陡、破碎拍壁，球被托起、抛起、卷走；停机后风平浪静。水面、水中和槽底三层的运动都交代到。

观看要求：

- 开场就有动作，不空等；结尾停稳。
- 冲击、开裂、破浪等关键瞬间可以放慢；其余部分紧凑推进，不留无事发生的空档。
- 镜头可以推、跟和切换；接触区、裂口和浪峰在画面里，主体在画面中足够大，各密度组的颜色可以分辨。
- 每段时长（含慢放）有上限：正中单击和偏击各 8 秒，连击 10 秒，风浪 20 秒。片长在上限内由你决定。

### 5.2 导出接口

作品提供以下固定接口：

```js
window.videoExport.runs                          // ['jelly-center', 'jelly-multi', 'jelly-offset', 'tank-full']
await window.videoExport.begin(runId, { fps })   // 回到这一段的初始状态，返回 { frames }，总帧数
await window.videoExport.frame(i)                // i 从 0 起依次调用；完成时第 i 帧已完整显示在页面上
window.videoExport.end()                         // 回到正常的可操作状态
```

`runs` 按上述顺序只含这四个标识，对应 5.1 的四段。演示参数、触发时序和镜头都预置在作品中，导出方只按 run 调用，不另设参数、不点击释放，并按返回的帧数原速导出整段，不另外裁剪或变速。

`begin` 等场景就绪，恢复这一段的初态，返回这一段演示（含慢放）按传入的 `fps` 取样的总帧数；`fps` 可以是任意正整数，只改变取样密度，不改变演示内容和时长。随后从 `i = 0` 到 `frames - 1` 依次调用 `frame(i)`：第 `i` 帧是演示第 `i / fps` 秒的画面，第 0 帧为初始时刻；调用完成时模拟、镜头和画面都已更新，与真实时间和机器快慢无关。导出期间正常的实时循环不再推进这段演示。

导出画面只显示三维场景，没有界面元素；分辨率由调用方设置的窗口大小决定，作品要能适应，最高可能到 3840×2160。`end()` 回到正常的可操作状态。接口只管画面，不处理声音，也不用交付视频文件；在 Chrome 中以本地文件方式打开作品时，接口也要可用。

## 六、技术要求

两个场景必须使用下面的基础技术路径。它只是基础路径，不是完整方案；在此之上怎样实现、调参、保持稳定和渲染，由你决定。

- 水体：三维的粒子—网格混合方法（PIC/FLIP、APIC 或物质点法一类），在 WebGPU 计算着色器上求解；自由液面、飞溅和白水由粒子状态得出，不用高度场、浅水方程或解析波形代替。
- 果冻：体积软体，内部离散为四面体或体素，用有限元、XPBD 或物质点法求解；开裂来自材料的断裂判据，不用事先切好的碎块替换。

其余要求：

1. 交付一个网页项目，入口文件为根目录下的 `index.html`，在 Chrome 中直接双击打开（以本地文件方式，不经过网页服务器）就能完整运行。注意：以本地文件方式打开时，Chrome 会拦截以文件引入的模块脚本、用 fetch 或 XHR 读取本地文件、从文件创建的 Worker，以及把图片文件用作 WebGL 纹理或读回其像素；普通 `<script src>` 和内联脚本不受影响。
2. 使用 HTML、CSS 和 JavaScript。三维画面用 WebGL 或 WebGPU 绘制，界面可以用 HTML、CSS 和 Canvas 2D；可以使用计算着色器和 Web Worker，也可以使用渲染库（如 Three.js）。
3. 可以使用现成的物理引擎或物理仿真库来实现上述基础路径，用不用、用哪个、用在哪些部分，由你决定。评测用的无窗口 Chrome 支持 WebGPU（含计算着色器），以本地文件打开时可用。导出逐帧推进，不要求实时。
4. 所用的库随项目交付，离线时按第 1 条的方式也能完整运行，运行时不从网络加载任何内容。
5. 仿真和画面都在浏览器里运行，不借助其他进程或网络服务计算。
