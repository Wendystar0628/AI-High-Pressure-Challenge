# 鹈鹕山海竞速

## 一、目标总览

制作一个在浏览器中运行的骑行交互系统《鹈鹕山海竞速》。三只体型不同的鹈鹕驾驶不同的专业竞赛车，在同一座精细建模的山海竞赛公园中骑行、跟骑和竞争。赛道包含爬坡、弯道、碎石、台阶、泵道、跳台、补给区和隧道；选手根据实际地形、受力和操作改变动作。用户可以切换操控对象、调节骑行输出与档位，并在路段交接处配置维度门，连续切换 1D、2D、2.5D、3D 表现。

本题重点是角色动作与车辆、地面和物体之间的空间约束，以及动作、传动、地形、数据和维度表现之间的连续联动。地图采用正常重力下的山海地形，身体和车型采用三套固定配置。

## 二、系统内容

### 2.1 一张完整的山海地图

地图是一座连续的海岸山地竞赛公园，海滨起终点、林间爬坡、山腰技术路段、石阶下降、泵道和跳台连成闭环。地形有实际高差、宽度、弯曲和路面结构，路段在同一个空间中相互衔接；从高处可以看到之前经过的路段，至少一处桥或栈道跨过另一段赛道。

地图采用统一的自然环境、建筑材料和赛事设施风格，重点做精道路边缘、植被、岩石、护栏、路标、计时拱门、补给站和技术结构。骑手的世界位置、前后轮接触点、坡度和转弯关系对应这张地图。三只骑手始终处于同一个世界中。

赛道由 2.7 的 S01–S11 按顺序连接，S11 回到 S01。S02 内设一条上阶梯的扛车短线和一条较长的骑行绕坡线，两线重新汇合，属于同一圈赛道。

### 2.2 三只骑手与三辆竞赛车

三只骑手同时存在，体型、身体比例、质量、输出能力和体力参数各自独立，差异进入实际骑行计算。角色均有完整的鹈鹕特征：长喙、喉囊、颈部、躯干、翅膀、腿、蹼足和尾部。关节、身体连接、羽毛分区与装备贴合清楚，在动作和视角变化中保持完整。

| 骑手 | 固定体型特征 | 固定车型及可辨认结构 |
|---|---|---|
| 07 号 | 修长轻盈，长颈和细长四肢 | XC 硬尾竞赛车：直把、前避震、无后避震，车架轻巧 |
| 18 号 | 中等体型、比例紧凑 | XC 全避震竞赛车：前后避震，清楚可见的后避震器和连杆 |
| 36 号 | 宽胸粗壮，喙和翼端较大 | Enduro 山地竞赛车：较长轴距、较明显的避震行程、更粗的轮胎和更强壮的车架 |

三辆车都具有完整的车架、前后轮、轮胎、轮毂、辐条、车把、前叉、坐垫、曲柄、脚踏、牙盘、链条、飞轮、后拨和制动结构。轮胎花纹、车架连接、避震连接和材质有细节，前后轮与车架的空间关系正确。

三套身体与车辆的具体比例和尺寸由你设计，运行中使用固定配置，用户通过选择骑手切换当前跟随与干预对象。每只骑手至少有两套专业队服与车辆涂装可切换，配色自行设计并保持三人可辨认，保留其体型和车型差异；切换不重置动作、骑行数据、补给或赛道进度。

### 2.3 专业装备

装备按照对应竞赛类型设计，实际出现在角色或车上：

三名骑手的专业装备套装分别设计。队服、头盔与镜具、手套与鞋、补给容器及主要车载附件，都要结合各自体型和车型形成清楚可辨的造型、结构与细节差异；不能照搬同一套成品装备素材，仅换颜色、号码或整体缩放。基础建模、绑定和功能代码可以共用，最终可见的三套装备需要体现各自的设计。

- 合身队服、骑行裤、号码牌和翼端手套；服装随身体运动，号码与当前骑手对应。
- 07、18 号使用通风头盔和骑行风镜；36 号使用全盔、护目镜和适合技术下降的护具。结构适配鹈鹕的头部与长喙。
- 适配蹼足的骑行鞋与脚踏，鞋、脚和脚踏的接触关系能看清。
- 有安装位置与可见结构的功率计，以及显示实际数据的车把码表。

装备的佩戴、抓持和安装位置随所属身体或车辆变化。涂装与装备状态在切换操控、维度和路段后继续保留。

### 2.4 操作、状态与骑行数据

打开作品时完整地图已准备好，三名骑手在发车区站立扶车待命，主要画面能看清角色与车辆。开始新一轮或“演示一圈”时先执行 2.14 的赛前介绍、问候、上车和倒数，再进入骑行。提供开始、暂停、继续、重置、切换骑手、涂装、镜头和维度设置等入口。

三名骑手默认自主骑行，包括当前跟随骑手，用户可切换观察与干预对象，也可将当前骑手切为手动驾驶。用户能控制输出功率或踩踏强度、档位、制动、冲刺和补给，并能选择 S02 分线、调整行进路线或超越意图；自主补给有独立开关，默认开启，手动驾驶时仍可根据状态自行补给。可以提供目标速度模式，由控制器调节实际输出；目标值与实际值分别显示。停下时提供低速前推、后推的推行操作，供用户在维度门附近前后移动。

每名骑手分别维护并显示：实际时速、目标值或输出设置、累计里程、圈数、赛段进度、体重、实时功率 W、踏频、档位、体力、水分状态、能量储备、饮水与能量胶数量、累计爬升和名次。主要数据随实际运动与事件变化。暂停停止同一条骑行时间线，继续时从原动作与状态接续。

### 2.5 传动、受力与车辆运动

采用可解释的简化骑行模型，将以下关系实际连接起来：

1. **踩踏和传动。** 输出与曲柄扭矩、踏频有关，经当前齿比与机械连接传递到后轮。每车至少有五个不同传动比，牙盘、链条、飞轮、后拨和车轮的运动对应当前传动状态。
2. **加减速。** 车辆根据驱动、制动、坡度、滚动阻力和空气阻力更新速度与位置。选手与车辆质量、轮径和车型参数参与计算；里程根据实际前进距离累计。
3. **滑行和换挡。** 停止踩踏后，曲柄与脚踏可以停止，车轮继续旋转；换挡改变传动关系，曲柄与车轮角度连续。踩踏、滑行、制动和低速推行有不同的机械状态。
4. **风与路面。** 风向、风速、骑手姿态、草地、浅沙与碎石影响对应阻力或牵引。牵引不足时，轮速与前进速度的关系及角色反应有合理表现。
5. **机械状态。** 设置面板可切换链条完好或断开。断链后踩踏和曲柄仍可运动，但不再向后轮传递驱动力；车辆仍按当时速度与外力滑行。接回链条不重置整段骑行。

骑行时的身体姿态改变迎风表现，坡道和粗糙路面引起的动作又会改变受力或可用输出。默认参数下三辆车均能完成主线，特长在不同路段中可感知。

泵道中身体压缩与伸展的做功参与车辆运动并消耗体力，时机不同会改变通过结果；不能仅让身体循环起伏，同时让速度按无关曲线增加。

### 2.6 角色动作与接触约束

动作由地形、接触状态、输出、踏频、制动、转向和当前行为共同决定。同一速度下，平路巡航、陡坡踩踏、技术下降和腾空的姿态有明显区别。身体、颈部、翅膀、腿与脚协同运动，转换平滑，不能只让整个角色上下平移或整体旋转。

整个骑行过程构成连续的动作变化：坐姿与站姿、踩踏与滑行、制动与过弯、吸震与起跳、腾空与落地、上下车与扛车、补给与恢复骑行都从当前姿态和动作阶段接续。起身、移重、伸翼、抓取、收回与重新握把有自然的准备和收势，动作速度随当前输出、踏频和地形变化，曲柄与脚部相位连续，不能在切换行为时跳回固定初始姿态。

多个行为需要协调时，身体各部分按当前接触关系共同运动，例如踩踏中伸翼取瓶、饮水后收翼握把再起身冲刺。路段交界、切换跟随对象、暂停继续、维度过门和镜头切换均保留同一动作的进展；落地等冲击通过对应的压缩、吸收和恢复衔接后续动作。具体的动作组织与实现方法由你设计。

骑行时翼端抓持车把，双脚跟随各自脚踏，腿与翅膀保持连贯的关节结构和合理弯曲；左右脚与曲柄相位对应。站姿摇车时，车体左右摆动、身体重心与四肢动作配合，接触仍成立。转弯时转向、车体倾斜、身体位置和脚踏位置对应弯道与路面。

接触关系随行为切换：候场时双脚接地并扶车，招手时一侧翼端保持扶车，另一侧向镜头问候；上车时从扶车、跨车、落座衔接到握把和踩踏，待发车可保留一脚支地维持稳定，发车后再接入踩踏。骑行时握把踩踏，补给时一侧翼端控车、另一侧抓取物品，推行时翼端扶车且双脚接地，扛车时由翼端和肩部持车且双脚跑动。每次抓住、放下、上车和下车都有明确的交接过程。

三个体型分别适配对应车辆，不能因换视角、冲刺、地面起伏、动作混合或维度变化出现肢体消失、结构断裂、明显穿模或接触脱离。

### 2.8 起跳、腾空和落地

S07 的桌面跳台允许低速沿路面通过，高速时是否离地由进入速度、坡面和接触状态决定。离地前有准备与卸重，腾空后按初速度与重力推进，车轮和踩踏可继续独立运动；骑手通过四肢与车体的相对运动调整姿态。

落地分别处理前后轮接触，避震压缩、车架姿态和身体吸收动作对应实际落地过程，随后接续滑行或踩踏。起跳、最高点或落地前切换维度，仍处于同一次跳跃的同一时刻。

S06→S07 的交接门设在起跳坡附近，使正常预设下能观察到车头进入 3D、车尾仍处于 2D 的过程。门所在位置和路面连接在地图中清楚可见。

### 2.9 补给与体力

三名骑手分别维护体力、水分状态、能量储备与补给库存，随骑行时间、实际输出、消耗和恢复变化，并影响可持续输出或冲刺能力。饮水、吃能量胶和恢复效果通过同一套简化消耗与恢复模型关联。

骑手根据自身水分与能量状态、触发阈值、剩余补给、当前动作和路况，自主决定何时补水或吃能量胶。当前跟随骑手和另外两名骑手使用同一套决策规则。设置面板可调整自主补给开关与触发阈值，改变状态或阈值后，需求与实际取用时机相应变化。

产生补给需求后，骑手选择适合单翅操作的平顺路段执行；处于急弯、连续下阶、腾空或扛车等阶段时先保留需求，条件合适后继续。饮水与吃胶按顺序进行，一次动作完成后根据恢复后的状态和冷却间隔重新判断，避免连续重复取用。

取水壶时，水壶先固定在瓶架上，抓取后随翼端运动；饮水时头部、喙、水壶角度与身体协调，另一侧翼端继续控车；放回后水壶重新固定到瓶架。吃胶完整呈现从随身位置取出、开封、送至喙部进食及收起包装的过程。实际饮用或进食时更新水量、能量胶数量和对应状态，并反馈到后续骑行。

动作中途切换视角、维度、操控对象、暂停或继续，手持物、动作阶段和已消耗补给保持正确。物品不会同时出现在瓶架与翼端，也不会在切换后重新变满。

### 2.10 三人比赛与尾流

发车后三只骑手持续在同一赛道中运动，有各自位置、速度、踏频、车轮相位、体力、装备和补给。界面称为“当前跟随骑手”，选择不同骑手时切换镜头、仪表和手动干预对象，另外两只继续运行。

自主骑行时，三名骑手根据路线、前车、体力、水分、能量和车型自行完成踩踏、换挡、制动、分线、补给与避让；隧道中根据环境开启前灯。切换当前跟随骑手不关闭其自主能力，手动驾驶只覆盖对应驾驶指令，自主补给仍按独立开关运行。提供跟骑、超越、轮换领骑等操作意图，实际移动经过连续路径，不能交换位置或瞬移。三车避免明显互相穿入。

采用简化尾流模型，根据前后与横向距离、风向和骑手姿态改变空气阻力。处于有利跟骑位置时，同样输出下的运动结果或维持速度所需输出发生相应变化，离开后恢复；效果与真实位置关联。显示圈数、名次与间距，过线按实际位置更新。

### 2.11 四种空间表现

四种模式表达同一张赛道和同一份骑行状态：

- **1D**：把一圈赛道按累计弧长展开为单一里程轴，三名骑手是轴上可辨认的符号，路段、门、终点、间距与超越沿轴表达。参数、动作阶段与装备状态可在界面中显示，物理运行继续。
- **2D**：采用专门绘制的二维角色、车辆与赛道表达，可按路段使用侧视或平面展开布局。关节、脚踏、车轮、坡道和接触关系可见，三名骑手仍有体型与车辆区别。
- **2.5D**：具有纵深和分层遮挡的赛道空间，角色与车辆采用二维分层或平面部件参与空间布置，能表现前后关系、路面起伏和镜头变化。
- **3D**：角色、车辆与场景都有实际三维结构，绕行观察能看到不同方向的形体、连接、材质和空间关系。

各模式具有对应的空间组织和绘制方式，不能只给同一幅画面套滤镜、缩放或透视变形。模式变化保留三名骑手的运动、机械、动作与持物状态；低维模式中未直接显示的状态仍持续更新，返回后按当前时刻呈现。

### 2.12 路段交接点与维度门

每个路段入口都可设置维度门，S11→S01 的圈间入口也可配置。设置面板按 S01–S11 列出路段名称、入口门开关、进入后的目标维度，并提供“下一个路段”快捷设置；用户能在骑行中设置下一路段的 1D、2D、2.5D 或 3D，也能提前编辑后续路段。

“标准路线”加载 2.7 的维度表。相邻目标维度不同时默认开门，相同时默认不设转换；用户可改门开关。入口门关闭时，越界继续沿用当前主视图维度，直到手动切换或经过下一扇启用的门。当前段设置的修改不追溯改变已经完成的过门，新的值用于下次进入；下一段的修改在本次越界时生效。

维度是主视图的表现设置，物理世界始终连续。各骑手分别记录过门进度和有效维度，主视图以当前跟随骑手的实际位置呈现转换；同一次越门只触发一次，低速停止与继续不重复重置状态。切换跟随骑手时，主视图按该骑手已到达路段和有效维度显示，其他选手的物理状态保持。

2D、2.5D、3D 相互转换时，角色与车辆按经过门平面的部分逐步转换：车头已进入目标维度、车尾仍在原维度，两侧引用同一份骨架、车轮与曲柄状态并在门口对齐。最后一部分越过后完成转换。停在门中央时保持半过门，后推时按实际位置反向退回。可以为门附近设计共同投影和稳定镜头，保证接缝可读。

涉及 1D 的转换可以采用实体与里程轴符号之间的连续过渡，过门位置、次序和时间仍对应同一骑手状态。门体采用与赛事一致的电子拱门造型，标明当前与目标维度，不改变路面连接和重力规则。

### 2.13 界面、镜头与操作反馈

主画面占据主要面积，提供跟随镜头、自由绕行与俯瞰全图。3D 模式能观察三只骑手和车辆的侧面、前后、上方及地形接触；自由观察不停止骑行。2D 与 2.5D 构图能看清关键动作，1D 里程轴和三人标识清楚。

UI 的风格、布局、配色、控件和字体尺寸由你自行设计。按以下要求组织常驻与可展开内容，保证文字可读、操作清楚，主要动作不被界面遮挡。

**常驻呈现：**

- 当前跟随骑手的身份与选择入口，以及当前动作或补给提示。
- 当前跟随骑手的实际时速、实时功率、踏频和档位。
- 体力、水分和能量状态的简明表示；自主补给时显示对应的水量或能量胶消耗反馈。
- 圈数、名次、当前路段、当前维度和下一扇启用门的目标维度。
- 暂停／继续、镜头切换与展开设置的入口。

**可展开查看或操作：**

- 累计里程、体重、累计爬升、详细间距、补给库存、目标值等完整数据。
- 自主骑行与手动驾驶、输出与档位调整、制动、冲刺、比赛意图和分线选择。
- 自主补给开关与阈值、手动补给、队服与车辆涂装、前灯。
- S01–S11 的入口门开关与目标维度表、“下一个路段”快捷设置及标准路线预设。
- 开始、重置、演示一圈、音效开关与总音量、推行、链条状态、快捷键说明和接触观察辅助。

展开面板可以收起，收起后保留常驻信息并继续骑行。提供只读的关节或接触位置显示开关，便于观察握把、脚踏和地面关系，默认关闭。当前输出、目标值和实际速度在相应面板中容易区分。

### 2.14 标准路线演示

提供“标准路线”预设和“演示一圈”入口，使用普通运行中的同一地图、角色、动作、受力、维度门与控制机制。完整流程从赛前准备开始，发车后从 S01 连续经过 S11 并完成 07 号的一圈。三人同时骑行，07 号经过 S02 的扛车短线，另外两只走骑行绕坡线，之后仍在同一赛道互动。

赛前准备与后续比赛处于同一张地图、同一条演出时间线上，按以下顺序展开：

1. **分别特写与问候。** 第一组镜头按 07、18、36 号顺序，分别给每只鹈鹕及其自行车特写。通过机位与景别变化看清各自身体、专业装备和车体细节；三只分别面向镜头招手或配合点头打招呼，问候动作各有特点，角色与车仍在真实发车位置。
2. **三人上车。** 问候完成后，镜头交代三人的上车过程，可以依次或错峰进行。从扶车、收回招手翼端、跨车到落座、握把和准备发车连续完成，车与地面、翼端与车把、身体与坐垫、脚与地面或脚踏的关系正确。
3. **就位后倒数。** 只有三名骑手都完成上车并进入稳定待发车状态，才开始 `3 → 2 → 1`，每个数字保持一秒模拟时间，并有对应提示音。倒数完成后给出明确发车信号，三人才开始前进，比赛计时从发车信号起累计；赛前与倒数阶段的比赛计时保持为零。

赛前镜头采用 3D，便于看清三套模型与上车动作。发车后经过 S01 入口维度门，再进入该段默认的 2.5D，路段维度方案仍按 2.7 执行。暂停、继续或切换观察对象保留当前问候、上车或倒数阶段。

演示覆盖发车与跟骑、爬坡和扛车、过弯、碎石、下阶、泵道、穿门起跳与落地、饮水和吃胶、隧道灯光、1D 相对位置及最终冲线。通过路线、控制意图和镜头安排串起过程，动作结果仍由实际骑行推进；镜头可自然跟随或短暂观察另外两只骑手，不跳过关键接触和维度转换。

演示镜头按专业比赛转播组织，根据路段与动作改变拍摄角度和景别，结合连续运镜与合理切镜，保持比赛时间、人物位置和前进方向可理解。具体机位、镜头路径、切换时机与构图由你设计：

- 开场先逐一特写三名骑手、车辆和问候，再用能看清三人上车的中景或全景，全部就位后交代倒数与发车，接续能够观察骑姿的跟拍中景。
- 弯道、碎石与下阶采用适合看清转向、倾斜、车轮接触和身体吸震的侧向、前侧、后侧或斜俯角度，按需要变化景别。
- 起跳段交代跳台与落地区的空间关系，并有看清腾空、过门接缝和落地吸收的连贯镜头。
- 补给段使用能看清翼端、喙、物品与车把关系的中近景，完整保留饮水和吃胶过程。
- 1D 与 2D 镜头尊重对应表现逻辑，通过跟移和景别变化保持可读；2.5D 与 3D 段结合不同方位的机位变化，整个演示呈现多种角度、全景、中景与近景。

最后一个镜头落在 S11 的 3D 终点直道，清楚且持续地跟拍 07 号起身摇车冲刺：双脚随曲柄发力、车身左右摆动、上身与翼端协调配合，接触关系稳定。可在同一镜头中自然接上投车过线，并在完成冲线后收束；最后一镜必须保留充分可见的摇车过程。镜头切换不重启动作，也不通过跳过比赛时间拼接动作。

三名骑手开启自主骑行与自主补给。预置初始储备、输出和消耗参数，使 07 号在 S08 附近自然产生补水与能量补给需求，并由 2.9 的决策规则选择时机执行。S08 的长度与行进节奏保证镜头清楚展示 07 号完整饮水和完整吃胶各一次，包括取用、饮用或进食、收回及对应状态变化；另外两只继续按各自状态自行操作。镜头自然靠近正在补给的骑手，素材导出方无需手动触发补给。

演示开始时加载标准维度方案并将三名骑手恢复到站立扶车的赛前初态，之后连续完成介绍、问候、上车、倒数与完整骑行，不在阶段或路段之间重置。可暂停、继续、退出并回到正常操作。第 4 节接口调用同一演示，不另做一套动画或视频素材。

### 2.15 音效设计与同步

音效由你自行设计，可用 Web Audio 合成或把自行制作的采样嵌入 HTML。至少覆盖以下内容：

- 赛前问候的角色声音、脚步、扶车、上车与准备动作。
- `3、2、1` 三次倒数提示及可辨认的发车信号。
- 踩踏与链条、换挡、滑行及制动等机械声音，随当前机械状态与骑行强度变化。
- 不同路面的滚动、台阶与碎石冲击、起跳和落地，声音对应实际接触时刻和强度。
- 取放水壶、饮水、能量胶包装与进食，配合对应动作阶段。
- 风与环境、维度门、冲线及必要的界面操作反馈。

声音有主次、音色与合理的音量层次，能体现不同角色、车辆或路面的特点，持续声与瞬态声都由实际状态和事件驱动。切换镜头、维度、骑手或暂停继续时保持声画同步，不重复播放已经完成的事件。首次用户交互后启用正常声音，提供音效开关和总音量控制。

正常交互与逐帧导出共用音源设计和模拟时间上的音效事件。音轨从赛前第一帧开始，包含问候、上车、倒数、骑行和冲线，与整段画面的同一时刻对应。

## 三、系统联动

1. **同一运动状态。** 速度、里程、圈数、位置、功率、踏频、档位、动作与模型表现互相对应。修改输出、制动、链条、风或路面条件后，运动与数据按实际机制变化。
2. **同一接触关系。** 三维身体、二维角色、分层角色与维度门过渡共同使用当前关节、机械相位和接触目标。爬坡、过弯、摇车、台阶、腾空、扛车与补给各自保持正确关系，并能连续转换。
3. **同一比赛世界。** 切换操控、皮肤、镜头、维度和路段设置，不重置三名骑手的进度、体力、装备、手持物与动作。门控制显示，赛道和物理状态持续存在。
4. **可重复操作。** 默认预设可完整运行，用户修改参数与维度表后仍可继续骑行和重新运行。暂停、继续、重置、退出演示和重新开始的范围清楚。

## 四、视频导出

### 4.1 公共接口

提供与其他网页题相同的接口：

```js
window.videoExport.runs                          // ['race-tour']
await window.videoExport.begin('race-tour', { fps }) // 准备标准路线演示，返回 { frames }
await window.videoExport.frame(i)                // i 从 0 起依次调用，完成时这一帧已完整显示
window.videoExport.end()                         // 退出导出模式，恢复正常操作
```

`race-tour` 使用 2.14 的标准路线、三骑手配置、控制意图和镜头，从三人及车辆分别特写开始，完整覆盖问候、上车、倒数、发车与 07 号完成一圈。`begin` 等待资源准备好，载入标准维度表并恢复演示初态，返回 `frames = Math.ceil(T * fps)`；`T` 是包含赛前准备和比赛的完整演示模拟时长，由作品按本身的路线与过程确定。

### 4.2 时间与画面

支持调用方传入的正整数取样帧率。第 `i` 帧对应模拟时刻 `i / fps`，按 `0` 到 `frames - 1` 顺序调用。导出模式中实时循环不额外推进同一模拟；`frame(i)` 完成时，骑行、机械、角色、门、镜头与界面已更新，不按真实时间等待播放。不同取样帧率不改变骑行速度、事件顺序和动作相位。

预置控制和镜头基于正常运行安排，使用同一模拟获得画面。演示帧数从赛前第一组特写开始，覆盖问候、上车、倒数及完整一圈，准备过程可用同一模拟确定其时长。

画面保留完整网页和 2.13 的常驻信息，展开面板在主要演示中收起。导出镜头沿用 2.14 的比赛转播编排，根据动作变化角度和景别，保留连续的动作与实际比赛时间，最后一镜清楚呈现摇车冲刺。分辨率由调用方提供的窗口尺寸决定，作品适应最高 3840×2160。

### 4.3 同步音轨

本题在公共逐帧接口上增加音轨接口，调用方在完成全部 `frame(i)` 后调用：

```js
await window.videoExport.audio({ sampleRate: 48000 }) // 返回 { wavBase64 }
```

`wavBase64` 是不带 data URL 前缀的 WAV 文件 Base64，包含 48 kHz、双声道、16 位 PCM 音频；从演示时刻零开始，总时长覆盖 `frames / fps`。使用同一音源和实际模拟事件，按其模拟时间离线生成完整音轨，可采用 `OfflineAudioContext`，不依赖导出时机器实际运行了多久。逐帧导出时不向真实播放设备重复播放事件。

### 4.4 分工

接口只负责提供画面与音频数据，截图、视频编码、音画合并、文件输出和成片包装由外部素材工具完成，不要求作品提供录屏按钮或交付视频、音频文件。`end()` 后恢复正常交互，用户仍能修改门设置、操控骑手和重新演示。接口在本地文件方式打开成品时可用。
