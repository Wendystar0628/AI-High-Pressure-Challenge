# 地形改道塔防

## 一、任务

制作一款在浏览器中运行的原创塔防游戏。地图自带地形，敌人沿可通行的道路自动寻路前往出口；地图上预留了若干关键点位，玩家占用这些点位可以阻断道路，迫使敌人改道。

游戏的题材、名称、美术风格，地图布局，塔、敌人和道具的设定，以及全部数值，都由你自己设计，不得照搬现有游戏。

## 二、游戏内容

### 2.1 地图

1. 地图为网格，由以下几类格子组成：
   - **道路**：敌人可以通行；
   - **障碍**：敌人不能通行，也不能建造；
   - **建造位**：可以建塔，敌人不能通行；
   - **关键点位**：位于道路上，可以建塔或放置道具；在上面建塔或放置道具都算占用，被占用后这一格不能通行，敌人改走其他路线；
   - **入口与出口**：至少 2 个入口、1 个出口。
2. 关键点位至少 4 个。在其余关键点位都未被占用时，单独占用任意一个关键点位，都至少有一个入口出发的敌人会改走另一条道路前往出口；只在原路线旁边绕开这一格，不算路线改变。
3. 敌人自动寻路前往出口。关键点位的占用情况改变后，场上正在行进的敌人从当前位置重新寻路，之后出发的敌人按新路线行进。
4. 每个入口出发的敌人路线都在画面上可见；关键点位的占用情况改变后，画面上的路线同步更新。
5. 禁止封死道路：任何时候，每个入口和场上每个受地形约束的敌人，都必须有通往出口的路线。会造成封死的占用操作不能完成，并给出提示。
6. 除占用关键点位外，塔、道具和其他任何操作都不能让道路格变得不可通行。
7. 至少 1 张地图，布局由你设计。

### 2.2 塔、敌人与道具

1. **塔**：
   - 至少 4 种，每种塔的作用不同；
   - 每种至少可以升级一次，升级后塔的外观随之改变；
   - 塔可以出售。
2. **敌人**：
   - 至少 5 种，每种敌人有不同的能力或行为；
   - 其中至少一种不受地形和道路约束：它不沿道路寻路，可以经过障碍和建造位，关键点位的占用也挡不住它；它同样前往出口，到达后同样扣除生命值，行进路线同样在画面上可见；
   - Boss 拥有普通敌人没有的能力。
3. **道具**：
   - 至少 3 种，每种道具的效果不同；
   - 其中至少一种可以放置在关键点位上；
   - 道具是塔以外、玩家可以使用的物品，获得方式和效果由你设计。
4. **区分标准**：塔、敌人、道具之间如果只在伤害、射程、攻击速度、生命值、速度、护甲、价格、奖励等数值上不同，不算作用、能力或效果不同。
5. **说明**：玩家可以查看每种塔、敌人和道具的说明与属性。

### 2.3 波次与流程

1. **波次**：不少于 15 波，其中至少 2 波为 Boss 波。
2. **资源**：游戏有两种资源，建造、升级等操作要消耗资源，两种资源的获取方式和用途由你设计。每种资源都有另一种资源不能替代的用途，一局中两种资源都需要反复获取和花费；两种资源不能按固定比例直接互换。生命值和分数不算资源。
3. **操作时机**：波次之间和波次进行中，都可以建造、升级、出售塔和使用道具。
4. **时长**：完整一局为 10–20 分钟。时长按打开游戏时的默认速度计算，不提前开始下一波，打满全部波次；如果下一波需要玩家手动开始，按每次都立即开始计算。
5. **速度控制**：可以暂停，也可以加速到至少 2 倍；加速时规则和判定与正常速度一致。
6. **胜负**：敌人到达出口会扣除生命值，生命值归零即失败，撑过全部波次即胜利。胜负之后显示结算画面，画面上有胜负结果和本局的统计信息；重新开始无需刷新页面。
7. **界面信息**：两种资源的数量、生命值、当前波次和总波次始终显示在界面上。

### 2.4 美术设计

1. 地图地形、塔、敌人、道具和界面的美术都由你设计，整体风格统一，图形素材由你自己制作。
2. 各类格子、各种塔、敌人和道具在画面上能一眼区分。
3. 塔攻击、敌人受击与死亡、道具使用、敌人改道等关键时刻有视觉反馈。
4. 敌人移动和塔攻击都有连续的动画，不能是静止的图标在格子之间跳动。

## 三、运行环境

1. 本题只做 PC 端，不考虑手机和平板，所有操作用鼠标和键盘完成。
2. 在 Google Chrome 和 Microsoft Edge 中运行，控制台没有报错。场上敌人很多时，游戏依然流畅。
3. 游戏界面使用简体中文。

## 四、交付

交付一个网页项目，入口文件为根目录下的 `index.html`。

## 五、规定

1. 开发时间为 90 分钟，从拿到题目开始计算。
2. 开发期间运行和测试游戏时，优先使用你所在 Agent 工具自带的内置浏览器；它不可用时，使用本机的 Google Chrome；仍不可用时，使用本机的 Microsoft Edge。
3. 全程不得访问 GitHub 上的任何仓库，无论通过网页、`git`、`gh` 命令行还是 API。
4. 工作目录限定为 `H:\AI_OneShot_Model` 下你自己的模型代号文件夹：所有文件都在这个文件夹内创建和修改，不得访问本机的其他文件夹；运行所需的编译器、解释器、库和浏览器时必须访问的安装路径除外。
5. 开发期间如需启动本地网页服务器，使用 18102 端口。
6. 时间到时，你的会话会被直接强制关闭，不再给收尾的机会，以关闭时工作目录中的项目文件作为最终提交。
7. 作答期间每 10 分钟会收到一次已用时间和剩余时间的提醒。有自己认可的阶段性成果时，及时保存到工作目录中。

## 六、评分标准

### 6.1 计分方法

总分 100 分，由下表 8 个分项组成。各分项按评分要点评定，在该项分值内给分；总分为各分项得分之和，再按 6.2 处理违规。

| 分项 | 分值 | 评分要点 |
|---|---|---|
| 玩法与策略深度 | 20 | 是否满足 2.2 中塔、敌人、道具各不相同的要求；关键点位、塔、道具和两种资源的使用是否构成真正的策略选择；是否存在一招通吃的打法 |
| 地图与关卡设计 | 16 | 是否满足 2.1 的要求；地形和关键点位的布局是否让改道成为有意义的取舍；多个入口之间是否形成压力 |
| 寻路与规则正确性 | 16 | 是否满足 2.1 的寻路、改道、路线显示和禁止封死道路的要求；各项规则在各种情况下是否都正确；不受地形约束的敌人是否真正不受地形和道路约束 |
| 美术设计 | 14 | 是否满足 2.4 的要求；整体风格的完成度、统一性与美感 |
| 数值与难度曲线 | 11 | 波次难度的递进、Boss 波的设计、两种资源的节奏是否合理；一局时长是否符合 2.3 |
| 创意与原创性 | 8 | 题材以及塔、敌人、道具的设定和机制是否新颖，而不是常见套路的堆砌 |
| 性能与技术质量 | 5 | 运行是否流畅；2.3 的暂停、加速、结算与重新开始是否可用；有无报错、卡死或异常 |
| 综合体验 | 10 | 完整试玩后对整体游戏体验的主观评价 |

### 6.2 违规处理

- 页面无法打开或白屏：总分记 0 分。
- 照搬现有游戏：总分记 0 分。
