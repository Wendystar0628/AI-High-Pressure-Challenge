# 多物理连锁机关

## 一、任务

在网页中制作一套连锁机关的物理仿真：从一个起始动作开始，机关依次触发，最终完成一个目标。连锁中要用到六种物理机制，每一环都由物理仿真推动。

连锁的题材、结构、各环节的顺序与衔接方式、最终目标，以及整体视觉效果，都由你自己设计。

本题同时考察三个方面：物理仿真是否正确，视觉效果是否出色，仿真性能是否足够高。

## 二、物理机制

连锁中必须用到以下六种物理机制。每种机制下列出的现象，都必须在该机制的单项演示（见 3.3）中全部呈现。

1. **刚体碰撞与摩擦**
   - 多个刚体堆叠后能保持静止；
   - 运动能在多个刚体之间依次传递；
   - 物体能因摩擦而减速或停住。
2. **滚动**
   - 物体沿斜面或轨道滚动；
   - 能看出滚动与滑动的不同。
3. **绳索与滑轮**
   - 绳索松弛时自然下垂，绷紧时传递拉力；
   - 至少有一个滑轮；
   - 绳端挂着的物体可以摆动。
4. **弹簧与振动**
   - 弹簧压缩或拉伸后储存能量，释放后推动其他物体；
   - 有振动或摆动，并且能看出振幅的衰减。
5. **流体**
   - 液体有自由液面，能流动、倾倒或溢出；
   - 物体在液体中漂浮或下沉；
   - 液体能推动物体。
6. **光学**
   - 光路在画面上可见；
   - 光线能发生反射和折射。

## 三、内容要求

### 3.1 连锁机关

1. **环节**：连锁至少包含 8 个环节，第二节的六种机制在连锁中各至少出现一次。环节如何划分由你决定，每个环节在画面中标示时，同时标出它用到的物理机制。
2. **交接**：相邻两个环节中，前一环的物理过程触发后一环，称为一次交接。连锁中至少有 6 次交接发生在不同的物理机制之间。
3. **仿真推动**：每一次交接都必须由物理过程完成，不能用脚本、预设动画或计时器直接触发下一环。
   - 由物理过程完成，是指后一环所受的作用全部来自仿真中物体之间的力和重力，后一环的运动由仿真据此算出。约束因所受的力超过其强度而断开，也算物理过程。
   - 代码检测到某个条件后，直接改变物体的运动状态、约束或参数（例如赋予速度、施加额外的力、解除固定、开始动画），属于脚本触发。
   - 后一环的物体在被触发前如果静止，必须是被支撑、约束或受力平衡而静止，不能是被固定住等待触发。
   - 参与仿真的物体在画面上都可见；不得设置看不见的墙、导轨或力场，也不得施加帮助连锁成功的额外的力。
4. **光学**：光学机制作为连锁的最后一环，用于视觉呈现。它的启动可以不经过物理交接，也不需要触发其他环节，不计入第 2 条的交接次数；但光路必须按场景中物体当时的位置实时计算反射和折射。
5. **双向耦合**：连锁中至少有 2 处双向耦合，且两处涉及的机制组合不能相同。
   - 双向耦合，是指两种不同的物理机制在一段时间内持续地相互作用：任何一方在影响另一方的同时，也受到另一方的反作用，双方的运动或状态都因此改变。
   - 只由一方单方面推动另一方、而自身不受影响的作用，不算双向耦合；只发生一瞬间的触发，也不算双向耦合。
6. **起点与终点**：
   - 连锁由用户的一次操作启动；
   - 有明确的最终目标，目标达成时有收尾画面；
   - 从启动到达成最终目标的完整过程为 30–90 秒，按正常速度和默认参数计算。
7. **控制**：用户可以启动、暂停、慢放和重置连锁。慢放至少能降到原速的 1/4，慢放时连锁的过程与正常速度一致。

### 3.2 物理设定

1. 物理仿真在竖直平面内的二维空间中进行，画面的表现形式不限。画面中物体的位置、形状、液面和光路都必须与仿真结果一致；三维表现、着色器和滤镜只能改变外观，不能替代或改变仿真结果。
2. 采用国际单位制，重力加速度取 $9.8\ \mathrm{m/s^2}$，界面上显示比例尺。比例尺随镜头缩放更新，画面中的尺寸和距离按比例尺换算后与仿真一致。
3. 提供参数面板，可以调整各环节的主要物理参数，例如质量、摩擦系数、弹簧劲度系数、液体量和折射率。调整后重置运行，结果由仿真重新计算。
4. 仿真与画面同步实时进行：画面上每一帧的状态都由当时推进的仿真得出，不得预先计算整段过程再回放。正常速度下，仿真时间与真实时间同步，界面显示仿真时间；不得为维持帧率而自动放慢仿真。

### 3.3 单项演示

1. 除完整连锁外，六种机制每种都要有一个可以单独运行的演示场景，完整呈现第二节中该机制的全部现象。
2. 单项演示中的物理参数可以调整。
3. 每个单项演示都可以调节规模，即增加场景中参与仿真的对象数量或精细程度，并在界面上实时显示当前规模的数值，注明统计的是什么。增加的对象必须与场景中的其他对象实际发生相互作用；增大规模时，仿真精度不得降低。

### 3.4 视觉效果

1. 整体视觉风格、各种物理元素的表现，以及连锁过程的呈现方式，都由你设计。
2. 整个连锁在一个连续的场景中展开。镜头能自动跟随当前进行的环节，也能由用户手动缩放和平移。
3. 当前进行的环节在画面中有明确的标示，观看者能看清这一环是怎样触发下一环的。
4. 液体在画面上要表现为连续的液体，而不是一个个分散的点。
5. 碰撞、物体落入液体、光路出现等关键时刻要有视觉反馈。
6. 慢放时画面依然平滑。

### 3.5 性能

1. 界面上常驻显示帧率、每帧物理计算的耗时和当前规模。这些数值都必须是实际测得的；每一帧都推进物理仿真；物理在 Worker 或 GPU 上计算时，耗时如实包含这部分计算。
2. 完整连锁运行全程，帧率不低于 60 FPS。
3. 单项演示在保持 60 FPS 的前提下，能支持的规模越大越好。

## 四、技术要求

1. 交付一个网页项目，入口文件为根目录下的 `index.html`。
2. 使用 HTML、CSS 和 JavaScript。渲染和计算可以使用 Canvas 2D、WebGL 或 WebGPU（包括计算着色器），可以使用 Web Worker，也可以使用渲染库（如 Three.js、PixiJS）。
3. 物理仿真（包括在 GPU 上进行的计算）必须全部自己实现，不得使用任何物理引擎或物理仿真库，例如 Matter.js、Planck.js、Box2D 及其移植版本、cannon-es、Ammo.js、Rapier。碰撞检测、射线求交、空间划分、约束求解、数值积分和流体计算等都属于物理仿真；渲染库或其他库中提供这些功能的模块（例如 Three.js 的 Raycaster），同样不得用于仿真。
4. 可以使用通用的向量和矩阵运算库（如 gl-matrix）。

## 五、运行环境

1. 本题只做 PC 端，不考虑手机和平板，所有操作用鼠标和键盘完成。
2. 在 Google Chrome 和 Microsoft Edge 中运行，控制台没有报错。
3. 评测在本机进行：CPU 为 Intel Core i7-14700KF，显卡为 NVIDIA GeForce RTX 4080。性能以 Google Chrome 中的表现为准。
4. 界面使用简体中文。

## 六、规定

1. 开发时间为 120 分钟，从拿到题目开始计算。
2. 开发期间运行和测试页面时，优先使用你所在 Agent 工具自带的内置浏览器；它不可用时，使用本机的 Google Chrome；仍不可用时，使用本机的 Microsoft Edge。
3. 全程不得访问 GitHub 上的任何仓库，无论通过网页、`git`、`gh` 命令行还是 API。
4. 工作目录限定为 `H:\AI_OneShot_Model` 下你自己的模型代号文件夹：所有文件都在这个文件夹内创建和修改，不得访问本机的其他文件夹；运行所需的编译器、解释器、库和浏览器时必须访问的安装路径除外。
5. 时间结束时，以当时的项目文件作为最终提交。

## 七、评分标准

### 7.1 计分方法

总分 100 分，由下表各分项组成。各分项按评分要点评定，在该项分值内给分；总分为各分项得分之和，再按 7.3 处理违规。

### 7.2 分项与评分要点

| 分项 | 分值 | 评分要点 |
|---|---|---|
| 刚体碰撞与摩擦 | 3 | 第二节第 1 项的现象是否齐全；碰撞、接触与摩擦是否符合物理规律，堆叠能否稳定静止 |
| 滚动 | 3 | 第二节第 2 项的现象是否齐全；滚动与滑动是否区分正确，滚动的运动是否符合物理规律 |
| 绳索与滑轮 | 3 | 第二节第 3 项的现象是否齐全；绳索的形态与张力、滑轮两侧的运动关系是否符合物理规律 |
| 弹簧与振动 | 3 | 第二节第 4 项的现象是否齐全；储能与释放、振动或摆动的周期与衰减是否符合物理规律 |
| 流体 | 3 | 第二节第 5 项的现象是否齐全；液体的流动、液面、体积以及液体与物体的相互作用是否符合物理规律 |
| 光学 | 3 | 第二节第 6 项的现象是否齐全；光线的传播、反射与折射是否符合物理规律 |
| 机制交接与连锁设计 | 15 | 是否满足 3.1 的环节数、跨机制交接、仿真推动、光学最后一环、双向耦合、起点终点与时长要求；交接是否由物理过程自然完成、巧妙多样；控制功能是否可用，连锁能否稳定地完整运行 |
| 数值稳定性 | 7 | 长时间运行和连续重置后是否稳定：不发散、不穿透、不异常抖动，能量不凭空增加 |
| 参数响应 | 5 | 参数面板是否覆盖各环节的主要物理参数；调整参数后，连锁和单项演示的结果是否按物理规律变化 |
| 视觉效果 | 25 | 是否满足 3.4 的各项要求，以及 3.2 中画面与仿真结果一致的要求；整体视觉风格的完成度、统一性与美感；各物理元素的表现力与细腻程度；连锁过程是否清楚、有观赏性 |
| 仿真性能 | 20 | 是否满足 3.5 的显示要求；完整连锁运行全程是否保持 60 FPS；单项演示在保持 60 FPS 时能支持的规模；每帧物理计算的耗时；有无报错或卡死 |
| 综合体验 | 10 | 完整观看和操作后对整体作品的主观评价 |

### 7.3 违规处理

- 页面无法打开或白屏：总分记 0 分。
- 使用了物理引擎或物理仿真库：总分记 0 分。
- 连锁中有交接由脚本、预设动画或计时器直接触发（3.1 第 4 条规定的光学最后一环除外）：机制交接与连锁设计、参数响应两项记 0 分。
- 预先计算整段过程再回放：机制交接与连锁设计、仿真性能两项记 0 分。
- 显示的帧率、物理耗时或规模与实际不符：仿真性能一项记 0 分。
