# Nest OS 操作说明

## 1. 总览

- **根系统 `outer`**：主窗口里的桌面，有文件管理器、电子表格、小组件、编辑器、浏览器、任务管理器、设置、子系统管理和这份说明。
- **子系统 `inner-1`、`inner-2`…**：按全局创建顺序命名。在任一桌面点任务栏的“＋ 子系统”就能新建直属子系统，可以一直往下嵌套，兄弟实例可以并行。
- 每个子系统窗口的工具条可以暂停、继续、单步、调速、快照、重启，并打开内核源文件；“管理”打开子系统管理，还能恢复、分叉和关闭。
- 任务栏右侧显示所属系统和层级，向上箭头是“返回父桌面”。各层窗口边框和任务栏使用不同的层级色，焦点窗口边框高亮。

## 2. 程序格式（Nest 语言）

程序是文本文件（一般用 `.nest`），语法接近 JavaScript 的一个子集：

```
// 注释
include "/System/lib/sys.nest";    // 只能写在顶层，每个文件只包含一次

const COUNT = 5;                    // 全局常量 / 变量
let table = { a: 1, "b c": [1, 2] };

function add(x, y) { return x + y; }

function main(args) {               // 入口，args 是启动参数；返回值是退出值
  let total = 0;
  for (let i = 0; i < COUNT; i++) total += add(i, 1);
  for (let v of [1, 2, 3]) total += v;
  while (total > 100) { total = total - 1; if (total == 50) break; }
  try {
    throw "出错";
  } catch (e) {
    sys("print", "捕获：" + str(e));
  }
  let f = add;                      // 函数可以作为值（没有闭包）
  sys("print", f(1, 2));
  return total;
}
```

类型：数字、字符串、布尔、`null`、数组、映射、函数值。运算符：`+ - * / %`、比较、`&& || !`、`?:`、位运算、`= += -= *= /= %=`、`++ --`。访问不存在的成员得到 `null`。

内建函数：`sqrt sin cos tan atan asin acos abs floor ceil round exp log sign atan2 pow min max rand srand is_nan`；`len substr char_at char_code char_from index_of last_index_of split join str num fmt lower upper trim replace starts_with ends_with pad_left`；`push pop shift insert remove_at slice concat new_array reverse sort_num sort_str sort_key`；`keys values has del type copy json_parse json_str hash`。

编辑器的“启动”按钮会打开一个程序输出窗口运行当前文件；“编译”只编译并报告错误。预置程序在 `/Programs`：`sum.nest`（累加）、`msg_send.nest` + `msg_recv.nest`（消息）、`spin.nest`（持续计算）、`hello.nest`、`draw2d.nest`、`draw3d.nest`。

## 3. 系统接口

程序只能通过 `sys("名称", 参数…)` 取得服务。它会陷入本系统内核，由内核的系统调用表分发。

| 调用 | 说明 |
|---|---|
| `time` / `sleep(秒)` | 读取本系统虚拟时间；等待虚拟时长 |
| `self` | `{pid, system, path, depth, name, ppid, group}` |
| `spawn(路径, 参数, 选项)` | 启动程序，阻塞到载入完成，返回 pid 或 `{error}`。选项：`name`、`stdout`、`inherit_stdout`、`join_group`（和当前应用同生共死）、`quota`、`mem` |
| `exit(值)` / `kill(pid)` / `suspend(pid)` / `resume(pid)` / `wait_proc(pid)` / `proc_state(pid)` | 进程控制 |
| `send(pid, 值)` | 发消息。目标不存在时返回 `{error:"ENOPROC…"}` |
| `recv(超时?)` | 等消息，返回 `{from, data, t}`；超时返回 `null`；`recv(0)` 不等待 |
| `fs_read fs_write fs_append fs_list fs_stat fs_mkdir fs_delete fs_rename fs_copy fs_watch` | 本系统文件。失败返回 `{error}` |
| `print(文本)` / `draw(指令)` / `scene(场景文本, 帧)` / `scene_frame(帧)` | 输出到所属程序窗口的文本、二维图形、三维场景 |
| `work(剩余量)` | 报告尚未完成的工作，显示在进程管理器 |
| `bus_read(名)` / `bus_write(名, 值)` | 本系统黑板，飞控用它读传感器、写舵面 |
| `proc_list` / `stats` / `set_config` / `set_quota(pid, 额度)` | 进程管理器使用 |
| `sysctl(操作, 实例, …)` | 子系统管理：`new list pause resume step rate stop start restart close snapshot restore fork grant config input resize kernel_path snapshots` |
| `win_open` `win_set` `win_close` `surface_new` `ui` `ui_patch` `meta` `gfx_open` `gfx_frame` `gfx_close` `gfx_pick` | 窗口与显示 |
| `ancestors` `proj_open` `proj_focus` `proj_close` `proj_input` `proj_resize` `proj_closed` | 跨层投送 |
| `data_sources` `data_connect` `data_disconnect` | 实时数据连接 |

二维绘图指令是数组的数组：`["clear",颜色]`、`["rect",x,y,w,h,颜色]`、`["rrect",x,y,w,h,颜色,圆角]`、`["line",x1,y1,x2,y2,颜色,线宽]`、`["polyline",[x,y,…],颜色,线宽]`、`["circle",x,y,r,颜色]`、`["text",x,y,文字,颜色,字号,字重,对齐]`。

运行方法：程序在宿主提供的字节码 VM 里执行，变量、运行位置、等待状态都在上下文里，能保存和恢复。程序碰不到宿主 DOM、宿主计时器或其他实例的对象。宿主只提供执行环境（`vm_*` 特权内建，只有内核能用）和显示、输入设备。

## 4. 内核是程序

- **位置**：每个子系统对应父系统里的一份源文件 `/Systems/<实例>/kernel.nest`（创建时从父系统的 `/System/kernel.nest` 复制）。系统窗口工具条的“内核”按钮（`kernel-open`）在父系统编辑器打开它。
- **内容**：进程表、就绪队列、时间片调度、定时与消息等待、消息投递、目录树与配额、系统调用分发、直属子系统承载、跨层路由、快照都写在这份程序里。它在父系统里是一个“承载进程”，用 `sys("tick")` 向父系统要时间步，用 `vm_run` 运行自己的进程。
- **修改方法**：打开、修改、保存，然后点系统窗口的“重启”。只影响这个实例。

文件开头有三个专门留给修改的钩子：

```
function pick_next() { return shift(RUNQ); }          // 调度策略：比如改成 pop(RUNQ) 就是后进先出
function message_filter(from, to, data) { return data; }   // 消息规则：比如把字符串消息改写
function fs_write_filter(path, text) { return text; }      // 文件行为：比如给写入内容加前缀
```

`QUANTUM_DIV` 控制时间片（总预算 / QUANTUM_DIV）。增加系统调用：写一个 `function sc_xxx(p, a) { return 值; }`，在 `init_syscalls` 的表里登记，程序就能 `sys("xxx", …)`。

**内核写坏时**：编译错误或运行异常都会让该子系统显示“内核错误”面板（`kernel-error`）并停止，父系统和兄弟系统照常运行。改回后点“重启”。

**重启语义**：结束子树内原有进程，重新载入内核源文件，按保留的系统树结构（`/Systems/tree.json`）从初始运行状态重新启动各实例，文件保留。

**窗口管理与应用**：`/System/wm.nest` 负责窗口次序、焦点、命中判断、输入分发、任务栏、开始菜单；`/System/apps/*.nest` 是各应用。改了它们，重启相应应用或系统就生效。界面库在 `/System/lib/ui.nest`。

**编译器**：`/System/compiler.nest` 也是系统内的程序（产物在 `/System/bin/compiler.nbc`）。保存修改后，下一次启动任何程序前，内核先用现有编译器编译它，新编译器用于此后启动的程序。程序产物缓存在 `/System/bin/<源文件哈希>.nbc`，缓存键含编译器哈希，所以换编译器后旧产物自动失效。编译失败时继续用旧编译器并通知。

## 5. 预算与配额的计量

- **单位**：一条 VM 指令 = 1 单位。复制、比较、拼接、解析、读写文件等按规模折算：16 字节 ≈ 1 单位。跨上下文的所有传递都是深拷贝并按规模计费。
- **逻辑步**：根系统每 1/60 秒一个逻辑步。根默认总预算 600 000 单位/步；每个子系统默认总预算和拨付上限是父系统的一半。
- **逐级计入**：`vm_run` 的工作计入调用它的内核，所以后代工作逐级计入承载进程。任务管理器分别显示承载进程的“内核自身”和“内部”。
- **未完成工作**：一次操作超出当前额度时结果先完成，差额记为欠账（“剩余”列），付清前该进程不再运行。调度循环按时间片轮转，本步预算用完后其余进程排到下一步。
- **不计入逻辑预算**：宿主的实际绘制（DOM、WebGL）和 Chromium 网页执行。根系统应用（电子表格重算、文件管理器）的工作按规模计入对应的应用进程。
- **内存**：变量、数组、字符串、消息队列按跟踪结果计入进程；已载入显示设备的场景计入提交它的进程；子系统的内存计入承载进程。超过配额时分配失败，程序得到可捕获的错误，未捕获则进程异常。默认每级是父系统的一半（根到第 2 层是四分之一）。
- **存储**：文件大小计入本系统配额；子系统的文件实际存放在父系统 `/Systems/<实例>/disk/` 下，也计入父系统。超出时写入返回 `ENOSPC`。
- **控件**：任务/进程管理器的总预算、内存、存储、进程额度、直属子系统拨付上限都能调，回车或点“应用”生效。

时间速率和预算无关：调快时间不补发预算。

## 6. 虚拟时间

子系统时间 = 父系统逻辑时间 × 自身速率（系统工具条可在 0.25×～8× 之间循环）。暂停一个实例，整棵子树都不再运行（它们只能在承载进程的 `vm_run` 内运行），继续后不补进暂停时长。**单步**让暂停的直属子系统执行 1/60 秒父系统逻辑时间（再乘速率）。

## 7. 文件与跨层传递

- 每个系统有自己的目录树。根系统文档在 `/Documents`，下载在 `/Downloads`，回收站在 `/Recycle`（删除后可恢复）。
- **跨系统拖放**：从任一文件管理器拖文件到另一系统的文件列表或左侧目录。拖动时指针旁显示目标系统和目录。目标取得独立副本；重名时目标桌面询问是否覆盖；配额不足时失败并通知。
- **保存到本机 / 导入**：文件管理器的“导出”“导入”。根系统可以选择路径；子系统导出到数据目录下的 `exports`。快照同样可以导出导入。

## 8. 快照、恢复与分叉

系统窗口的“快照”把选定实例及全部后代保存到父系统的 `/Snapshots/<实例>-<步数>.snap`，内容包括内核及其运行位置、进程状态与变量、消息与计时等待、虚拟时间、文件、桌面和应用状态，以及显示设备保留的提交数据。写入按规模消耗父系统预算和存储。

在子系统管理里选快照后可以：

- **恢复到选中实例**：只改变该子树。范围外的文件、表格和拨付配置不变。范围外的投送外框继续对应同一源窗口，源窗口已不存在时投送结束。
- **分叉新子树**：新实例使用新身份，内部关系指向分叉内的节点。范围外的数据连接和投送仍属于原子树。
- **保存到本机 / 从本机导入**：作品重启后导入，再恢复或分叉，能继续运行。

实时数据源不属于快照：恢复或分叉后，图表用已接收的数据续行，显示“已恢复，待重新连接”，点“连接”建立新连接。

## 9. 三维场景播放器

新建子系统时默认打开播放器并载入默认场景。也可以在路径框输入路径点“打开”，或在文件管理器双击 `.scene`、`.flight`。

- 控制：播放、暂停、停止回到开头、重播、逐帧（1/60 秒）、循环、进度条、速率、镜头（演出 / 跟随 / 自由环绕）。空格切换播放，右方向键逐帧。
- 自由镜头：在视图里拖动环绕，滚轮缩放。点击部件显示名称和损坏状态。
- 帧率：60 帧/秒。播放位置由时序进程按系统虚拟时间推进。

默认演出、排演和回放都由**时序进程**（`player_timeline`）、**飞行场景进程**（`player_flight`）、**环境特效进程**（`player_fx`）协作，时序进程用消息驱动后两者，收齐同一时刻的结果后一次提交。排演时再加**飞控进程**。在进程管理器挂起其中一个，只停止它负责的更新。

### 场景资源格式（`nest-scene`）

一个 JSON 文件，不含代码。可编辑的内容在前面，贴图和几何数据在文件末尾。

| 字段 | 内容 |
|---|---|
| `environment` | 时刻与天气：`sun` 主光、`hemi` 环境光、`sky` 天空、`fog` 雾 |
| `materials` | 名字 → `{color, map, roughness, metalness, clearcoat, glass, opacity, vertexColors…}` |
| `textures` | 名字 → `{chunks:[数据地址分段], srgb, wrap, aniso}` |
| `geometries` | 名字 → `{n, pos, nor, uv, col, idx}`（base64 分段） |
| `parts` | 部件层级：`{name, parent, geometry 或 primitive, material, pos, rot, scale, visible, castShadow}` |
| `models` / `objects` | 物体的模型表和摆放表；`objects[i].collide` 同时决定飞行接触 |
| `terrain` | 高度场 `{size, n, heights, material}`，绘制和飞行接触共用 |
| `grass` | 草地区域，显示设备展开成草叶 |
| `cameras` | `default` 和演出镜头表 `show` |
| `flight` | 飞行模型参数、接触点、可脱落部件、`record` 控制时序 |
| `timeline` | 关键帧动画 `tracks`（没有 `flight` 时使用） |

**最小场景**（`/Demo/minimal.scene`，一个物体、一盏灯、一台相机）：

```json
{
  "format": "nest-scene", "version": 1, "name": "最小场景", "duration": 6, "fps": 60,
  "environment": { "sun": { "dir": [0.5, 0.8, 0.3], "color": "#fff2d8", "intensity": 3 } },
  "materials": { "m": { "color": "#8f6bff", "roughness": 0.35 } },
  "parts": [ { "name": "方块", "primitive": { "box": [1.6, 1.6, 1.6] }, "material": "m" } ],
  "cameras": { "default": { "pos": [4, 3, 5], "target": [0, 0, 0], "fov": 45 } }
}
```

改动材质、部件变换、镜头、地形、障碍或控制时序后保存，重新打开文件，画面和飞行结果都按新内容变化。

## 10. 飞行排演与飞控接口

点播放器的“飞行排演”打开面板，“从当前位置开始排演”把当前状态交给飞控：直升机是不稳定的被控对象，状态随虚拟时间连续演化，不等待飞控，没有控制输入就会失去姿态。

飞控是普通程序（默认 `/Flight/flightctl.nest`，路径可在面板修改），用总线通信：

```
function main(args) {
  let bus = args.bus;
  for (;;) {
    let s = sys("bus_read", bus + "/sensors");
    if (s != null) {
      // s: t, x, y, z, vx, vy, vz, yaw, pitch(抬头正), roll(右滚正), wp, wr, wy, omega, agl, up,
      //    hover_collective, crashed, goal { mode:"cruise"|"point"|"land", heading, y, speed, x, z }
      sys("bus_write", bus + "/control", { collective: 0.5, pitch: 0, roll: 0, yaw: 0, throttle: 1, t: s.t });
    }
    sys("sleep", 0.01);
  }
}
```

控制量范围：`collective`、`throttle` 0～1，`pitch`、`roll`、`yaw` -1～1。控制量保持到下一次写入，错过周期的控制不补发。

- **影响飞行的因素**：调低任一祖先的拨付、在同一子树运行 `/Programs/spin.nest`、提高时间速率都会拉长实际控制周期（面板上方显示当前周期）。约 50 ms 开始抖动，130 ms 明显发散，300 ms 以上基本坠毁；及时恢复能拉回。物理落后于虚拟时间时画面停在已算完的时刻，补算仍按虚拟时间和当时的控制量。
- **输入**：风速、风向、目标航向（也可点击地面）、故障类型与触发。“飞往 2 号坪降落”让飞控飞到第二个停机坪悬停并降落。
- **记录**：填路径点“保存”，得到 `.flight` 文件 `{format:"nest-flight", scene_path, scene, record:{dt, controls, events, duration}}`，包含场景资源、初态、实际输入和控制时序。重新打开后可跳转，回放结果不随当前预算变化。从任意位置点“开始排演”可以给出不同输入或飞控，分别保存各自的后续过程，原记录不变。

## 11. 跨层窗口投送

播放器和图表的“投送”按钮列出所有祖先桌面（可以跨层直接到根）。目标桌面出现投送窗口，标题栏标明来源。

- 应用、状态和计算都留在源系统；目标桌面只放外框。源程序为投送视图再提交一份界面和场景数据（副本），按投送窗口尺寸各自取景。
- 投送内的输入经目标系统接口回到源应用的消息队列，由源进程处理后提交新显示。
- 暂停源系统或它的祖先时，内容冻结，控件禁用并提示原因，外框仍可操作。
- 关闭投送只取消视图；关闭源窗口、结束应用或停止子树时投送结束并通知。

## 12. 实时数据连接

任一子系统打开“图表工作台”：选择已打开的工作簿（`chart-source`），填区域（如 `A1:D4`）、标签列（如 `A`）、数值列（如 `B,C,D`），点“连接”。根系统表格每次提交编辑、粘贴、撤销或重做并重算后发布新版本，未保存的修改同样发布。

- 数据接收（`chart_recv`）和图表（`charts`）是两个进程，用消息协作。可以单独挂起其中一个。
- 目标系统暂停时，更新在父系统的收件箱里按序暂存，继续后按序处理。
- 断开后保留最后的图表；关闭源工作簿时提示数据源已关闭，重新打开后重新选择连接。

文件拖放只复制文件，和实时连接无关。

## 13. 电子表格

- 单击选中，拖动选区，直接键入或双击编辑，编辑栏也可以输入。回车、Tab、方向键移动。
- 公式：`=B2*C2`、`=(A1+B1)/2`、`=SUM(B2:B4)`、`=SUM(A1,B2:B3,5)`。错误显示 `#DIV/0!`（除零）、`#REF!`（引用无效）、`#CYCLE!`（循环依赖）、`#NAME?`（不识别的名称）、`#VALUE!`（不是数字）。
- Ctrl+C / X / V / Z / Y / S / B，Delete 清除。表格选区以制表符和换行的文本进入剪贴板历史。
- 文件格式 `.sheet`（`nest-sheet`）：`{format, version, title, cells:{A1:{v:原值, b:粗体, i:斜体, align, color, bg, nf:小数位}}}`。未保存时标题和状态栏有标示，关闭或打开其他文件前可以保存、放弃或取消。

## 14. 浏览器

自制界面 + Chromium 网页视图，支持多标签、前进后退、刷新、停止、加载状态和失败重试。网页打开新页面时在浏览器内新建标签。网页按真实时间和网络运行，不属于系统虚拟时间、共享资源和快照，也不能访问宿主文件系统、Node.js 或系统内部对象。任务管理器把网页视图单独列出，标注“不计入逻辑预算”。
