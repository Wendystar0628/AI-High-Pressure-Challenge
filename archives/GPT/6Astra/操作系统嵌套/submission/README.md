# 层界 NEST · Nested OS

一个可递归创建桌面的 Windows 应用。原创山湖壁纸、独立文件系统、可编辑 NEX 程序与内核、三维飞行工作室、实时表格连接和跨层窗口投送。

## 启动

环境为 Node.js 与 Electron 45.2.1。依赖已经在本项目安装；重新部署时运行 `npm install`。

```powershell
npm start
```

启动命令自动执行本地 Vite 构建，然后打开 Electron 桌面，不依赖额外服务器。

```powershell
npm start -- --data-dir "C:\Temp\nest-session" --width 1600 --height 1000 --remote-debugging-port=19156
```

`--width` / `--height` 指客户区尺寸。未指定数据目录时使用 Electron 用户数据目录下的 NestWorkspace。每份数据目录都有自己的工作空间、文件与实例编号；不会把运行状态写回源码。外部站点需要联网，桌面、字体回退、图标、壁纸、应用与三维素材均可离线使用。

## 操作路线

1. 双击根桌面「电子表格」。`/Demo/sample.sheet` 已提供 A1:D4 示例，D2:D4 是公式。双击 B2 输入数字，Enter 提交。
2. 根桌面右侧「启动子系统」创建 inner-1。子系统中的「系统空间」可继续创建 inner-2、inner-3，以及同父级的兄弟实例。系统窗口标题栏可返回父层控制暂停或继续。
3. 子系统打开「图表工作台」，选择已打开的根工作簿，区域 A1:D4、标签列 A、数值列 B,D，点击连接。修改表格会发布新的完整版本。
4. 图表或播放器标题栏的「投送」可选择任意祖先，包括 outer。源窗口仍保留；关闭投送只撤销视图。
5. 新建子系统自动打开暂停的 24 号场景，也可双击「三维场景播放器」另开实例。播放、暂停、停止、逐帧、进度、数值跳转、速率与循环都使用源应用状态。
6. 在两层文件管理器之间拖放 .scene 文件，得到独立副本。同名文件会询问覆盖。文件工具栏可导入或导出到本机。

桌面图标单击选中、双击打开，右键有菜单。标题栏可拖动，右下角缩放，双击标题栏最大化；拖到左右边缘可半屏贴靠。任务栏可收起、恢复、切换。桌面和开始菜单里随时可打开中文版使用指南。

## 文件与桌面应用

各系统都有 `/Demo`、`/Documents`、`/Downloads`、`/Programs`、`/System`、`/Snapshots`、`/Recycle`。文件操作、程序文件调用、工作簿和场景读写使用同一份虚拟文件内容。删除移到回收站，可右键还原。

表格支持单元格和 Shift/鼠标拖动选区、公式栏、复制粘贴 TSV、撤销重做、保存与重开。工作簿是 JSON：

```json
{"title":"示例","cells":{"A1":"项目","B1":"数量","A2":"测试","B2":24,"C2":"=B2*6"},"format":{"header":true}}
```

公式支持 `+ - * /`、括号、单元格引用、`SUM(A1:B5)` 和逗号分隔参数。错误为 `#DIV/0!`、`#REF!`、`#VALUE!`、`#CYCLE!`。修改输入后依赖公式重新计算并发布单一版本；未保存内容也能用于数据连接。保存包含原始公式与基本格式，关闭未保存文档会询问保存、放弃或取消。

小组件含日期与翻月日历、倒计时、秒表与分段、多张便笺、实际复制的剪贴板历史、通知与免打扰。设置可修改名称、三种壁纸、强调色和界面比例。运行状态定期保存。

浏览器是隔离的 Electron Chromium `webview`，支持真实导航、多标签、后退、前进、刷新、停止和新窗口内部化。外部页面无法访问 Node.js、宿主文件或 NEST 对象。网页按真实网络时间执行，不属于虚拟执行预算或子树快照；失败可重试，站点自身限制仍由站点决定。

## 程序、内核与编译器

NEX 是受限的文本指令语言，程序保留 PC、变量、队列、等待状态与未付完的工作。表达式使用 Acorn 解析，然后由白名单解释器求值；不使用 `eval` 或宿主函数注入。

```text
set count 0
loop:
set count count + 1
print count
wait 100
if count < 20 goto loop
sys result file.write {path:"/Documents/count.txt",content:string(count)}
halt
```

指令：`set 变量 表达式`、`if 条件 goto 标签`、`goto 标签`、`print 表达式`、`wait 毫秒`、`receive 变量`、`send {to:进程ID,value:数据}`、`sys 变量 服务 参数`、`halt`。表达式有数组、对象、算术、比较、三元条件、属性读取；禁止 `constructor` / `prototype` / `__proto__` 等宿主逃逸入口。

纯函数包括 `sin cos abs min max sqrt floor round len number string split trim slice index starts ends includes append assoc replaceAt has`。系统变量 `time` 是本层虚拟秒数，`pid` 是当前进程身份。

常用系统调用：

| 服务 | 参数 / 结果 |
|---|---|
| `clock.read` | 当前虚拟时间 |
| `identity` | `{id, systemId}` |
| `file.read` | 路径字符串，返回文本或错误 |
| `file.write` | `{path,content}`，受本层与祖先存储额度约束 |
| `file.attributes` / `file.remove` | 设置文件类型 / 删除本系统指定路径 |
| `notification` | 向本系统发送一条通知 |
| `process.start` | 本系统程序路径，返回进程身份 |
| `process.end` | 要结束的进程身份 |
| `message.send` | `{to,value}`；按发送时的独立值投递 |
| `display.submit` | 可复制的显示数据，保存在进程显示状态 |
| `flight.sensor` | 位置、速度、姿态、目标、取样时间 |
| `flight.control` | `{collective,cyclic,cyclicZ,stamp}` |

`/Programs/sum.nx`、`compute.nx`、`send.nx`、`receive.nx` 可直接打开编辑运行。`draw.nx` 通过 `display.submit` 在编辑器预览区提交二维图形，点击画面产生输入消息。显示数据为 `{kind:"2d",width,height,background,shapes:[{type:"circle",x,y,r,fill}]}`，也支持 rect、line、text；三维数据使用 `{kind:"3d",resource,frame}`。发送程序的接收身份需填写任务管理器里实际存在的 pid；生命周期结束后原身份不会交给新进程。

每个子系统的内核位于**父系统** `/System/inner-N.kernel.nx`，由父层的承载进程执行。它使用与普通程序相同的指令格式，源代码负责选择进程、轮转游标、等待唤醒、请求分派、消息顺序、文件配额检查和结果交付。宿主提供解释器单步与底层数据/显示设备原语。内核不单独使用宿主定时器。

修改 `quantum` 可以改变每次执行的子额度；`policy` 支持 `round-robin` / `reverse`；`messageMode` 支持 `fifo` / `lifo`。也可编辑分支规则、添加对请求名称的处理，然后在父层点击重启。错误只使该子系统进入内核错误，父与兄弟仍然工作。

`/System/compiler.nx` 是驻留编译器程序：自身进行逐行解析、标签表构建、跳转解析和指令生成。启动普通用户程序会创建编译任务；编译器的循环与数组复制也参与预算。编辑并运行 compiler.nx 会让当前编译器编译它自己，安装生成的代码，后续用户程序使用该版本。初始引导时由宿主编译相同语法，系统启动文件由这一引导路径载入。

`/System/desktop.nx` 负责子桌面焦点、窗口堆叠、布局与应用输入分发；挂起它后输入保持在队列中。`application.nx` 处理窗口输入，其 caption/accent 可改变应用标题与颜色。`files.nx` 逐个处理复制文件，通过内核文件调用写入，挂起文件进程会延后复制。编辑器的保存、编译和飞控接管同样经过应用消息。播放器时序、场景、特效、图表接收与图表计算分别有 .nx 源文件；`chart.nx` 实际扫描选区数值并计算坐标范围，修改 padding 后重新打开图表即可看到变化。宿主组件负责设备绘制和具体应用原语，NEX 程序负责它们的调度、消息与调用时机。

## 执行额度与隔离

固定逻辑步为 50 ms，默认根预算 12,000 单位。每条指令至少 1 单位；数组、字符串副本根据结果长度分块计费，消息、文件传递与请求完成按 32 字符块付费。场景取样按节点数、图表按数据规模、排演物理按积分步数付费。未完成的指令复制和系统调用保留剩余工作，下次续行。

承载进程执行子系统内核，再由其选择内部进程；所有下级消耗回计到同一份祖先预算。每个进程额度和子系统 grant 都是上限，不会创造预算。增加层级、窗口、投送、速率只会分用现有额度。任务管理器显示本层总预算、实际用量、内核与用户工作、累计工作、等待/未完工作、额度、错误和变量。

内存包括进程变量/消息/代码、应用资源与投送副本，存储包括文件文本；祖先额度汇总后代使用，兄弟共享祖先余量。真实显卡驱动/Chromium 内部开销不冒充 NEX 内存或逻辑指令。CPU/GPU 帧率不是计量目标。

## 场景、飞行与记录

原创资源为 `public/assets/helicopter-24.scene`，虚拟路径为 `/Demo/helicopter-24.scene`。模型、节点层级、材质、灯光、镜头、部件运动表达式、障碍与 15 秒演出记录都在资源中。播放器/设备没有硬编码直升机几何。

最小场景 `/Demo/minimal.scene`：

```json
{
  "version":1,"title":"最小场景","duration":5,"fps":30,"background":"#d9e5df",
  "camera":{"position":[4,3,5],"target":[0,0,0],"fov":45},
  "lights":[{"type":"hemisphere","sky":"#ffffff","ground":"#52656e","intensity":3}],
  "materials":{"violet":{"color":"#7961b0","roughness":0.3}},
  "nodes":[{"id":"物体","shape":"box","material":"violet","position":[0,0,0],"scale":[1,1,1],"motion":{"ry":"t"}}]
}
```

形状包括 `group`、`box`、`sphere`、`cylinder`、`cone`、`torus`、`plane`、`text`、自定义顶点与索引的 `mesh`；`parent` 建立部件关系。材质使用标准 PBR 字段。`motion` 的 x/y/z、rx/ry/rz、scale 是纯表达式，以已提交时刻 t、位置和 roll/pitch/yaw 为输入，scale 乘以部件基础缩放。镜头、章节、编号和描述都来自资源数据。资源修改保存后从文件管理器重新打开生效。

显示后端使用一个共享 WebGL 2 渲染器，按各视图尺寸把实时结果复制到各自 canvas，避免超过 Chromium 同时活跃 WebGL 上下文上限。上下文恢复后从系统数据重新构建。显示定时器只重绘已提交数据，不推进程序、物理或播放时间。Electron 关闭后台节流与原生窗口遮挡节流。

时序进程把同一取样时刻消息发送给场景与环境特效进程，可在任务管理器单独挂起。自由镜头可拖动与滚轮缩放，点击部件显示名称。播放器进度、相机、资源、未完成取样都属于源系统。

飞行排演从当前画面接管。`/Programs/flight-control.nx` 是普通闭环控制程序，读取传感器并写入总距与双轴控制。物理以 1/120 秒子步积分，控制按实际写入时刻保持；降低调度份额、挂起控制或增大时间倍率会拉长控制周期。可改变风、航向、地面目标、第二停机坪着陆目标或触发故障。场景节点的 `collision:"ground"` 产生地面/椭球丘陵表面，`collision:"solid"` 产生实体障碍；计算使用实际节点的位置和缩放。修改机库、树干或丘陵几何会改变接触结果。旧资源也可使用 obstacles 包围盒数组。

从排演面板「编辑飞控程序」进入编辑器，修改并运行后，驻留编译器生成的新控制进程接管这个播放器；编译失败时原控制器继续运行。传感器包含双轴位置、速度、姿态角与角速度，默认程序采用限幅的目标倾角、姿态反馈与高度反馈，可平稳转场到第二停机坪。

排演保存 `.flight` 文件，包括场景、状态记录、输入与实际控制时序。文件重开后可按记录跳转回放，结果与新预算无关；从某个记录位置再次开始排演会产生新的后续轨迹。模型为原创程序化三维造型，飞行动力学为展示用途的简化模型。

## 图表、投送与快照

图表显式连接根系统已打开工作簿的文档身份及矩形选区。根服务把完整新版本复制到连接队列；子树暂停时保留在范围外，恢复后按顺序送给接收进程，再交给图表进程。断开保留最后图表，关闭工作簿标识源关闭；重新打开后需重新选择连接。

投送外框属于目标祖先。显示内容以源应用数据副本交付；控件输入回到源应用消息队列，经调度处理。源应用最小化不停止投送，源系统暂停会冻结画面并禁用控制，关闭源应用或停止子树会结束投送。

系统空间的快照按钮把整棵子树序列化成父层 `/Snapshots/*.snapshot`。包含内核 PC、变量、微操作剩余量、进程、消息、虚拟时间、文件、窗口、场景、物理、图表缓存与应用状态。恢复保持范围外桌面；分叉重写实例、进程和窗口身份，内部关系重连，外部订阅不继承。图表恢复后显示“已恢复，待重新连接”。快照文件可导出到本机，重启后导入打开。

## 自动化与验证

根目录 `automation.json` 描述启动参数、客户区、调试端口、资源路径和上下文。主窗口暴露：

```js
window.bench.version
await window.bench.ready()
await window.bench.reset()
await window.bench.inspect()
```

关键控件具备题面规定的 data-testid，窗口/系统归属与投送来源属性。Windows 原生窗口标题为「层界 NEST · Nested OS」。

```powershell
npm test                 # 程序/四层调度/公式/快照/编译器/隔离测试
npm run build            # 离线生产构建
node scripts/smoke-ui.mjs # 对已启动的 19156 桌面执行主线界面检查
node scripts/nesting-ui.mjs # 四层桌面、深层投送、快照与分叉检查
node scripts/files-check.mjs # 110% 缩放下的跨层拖放、保存与自定义程序
node scripts/final-ui.mjs # 真实网页、新标签、最小场景与完整 15 秒演出
node scripts/reconnect-ui.mjs # 投送内断开连接、编辑表格、缓存冻结与重新连接
```

开发截图与独立测试数据使用系统临时目录。无需录屏、外部网站仿制内容或额外服务。

连接断开或数据源关闭后，图表保留最后完成的画面；已排队的旧订阅数据不会覆盖它。重新连接使用新的订阅身份，允许切换到版本号较小的新工作簿。恢复快照后同样需要重新连接外部数据源。场景跳转会取消过期的取样结果；同名场景重新载入及快照恢复会同步刷新祖先桌面的投送资源。
