# 栖境 NEST OS

Windows 桌面项目，Electron 45.2.1 + Three.js。原创山湖壁纸、矢量图标及 24 号直升机三维资源。

## 启动

```powershell
npm install
npm start
```

支持 `npm start -- --data-dir <目录> --width 1440 --height 960 --remote-debugging-port=19106`。无需网页服务器。默认运行数据位于系统临时目录 `nest-os-data`，不写回项目源码。自动化约定见 automation.json。首次启动仅呈现根桌面。

## 操作

双击桌面图标；开始菜单可打开所有应用。窗口支持拖动、右下角缩放、标题栏双击最大化、左右边缘贴靠与任务栏恢复。桌面右键打开上下文菜单。每个系统「系统空间」管理直属子系统，支持四层及以上递归与兄弟实例。

先在根系统打开示例工作簿，再创建子系统，在图表中选工作簿 / A1:D4 / 标签 A / 数值 D，点击连接。表格任意编辑会发布新版本，暂停目标后更新排队。源播放器和图表的「投送」可选择任意祖先桌面。投送外框独立，输入仍发给源系统。

详细简体中文指南可从每层桌面右上角「使用指南」或开始菜单打开。包含程序格式、接口、计量、内核位置、飞控、场景格式、文件、排演、快照与数据连接说明。

## 文件格式与程序

- `.nest`：`{"version":1,"code":[...]}`。set、if、jump、wait、send、recv、sys、end。表达式使用受限解析器，不允许宿主 DOM、Node、定时器或全局对象访问。变量、pc、等待、队列均可序列化。
- 父系统 `/System/inner-N.kernel.nest`：该实例内核；父桌面「系统空间→编辑内核」打开。保存后重启生效，解析错误隔离在该子树。
- `/System/window-manager.nest`、`files.nest`、`charts.nest`：窗口消息调度、文件排序和图表数值规则。
- `/Programs/accumulate.nest`、`spin.nest`、`sender.nest`、`receiver.nest`：可编辑运行的程序。先运行 receiver 后运行 sender。进程管理器点行查看变量与输出。
- `/Programs/flight-control.nest`：闭环高度控制器。`flight.sensor` 取得高度；`flight.control` 写入总距，直到下次控制维持原值；与用户程序竞争额度。
- `.sheet`：cells 地址字典，原始公式保留。支持算术、括号、SUM 矩形范围，错误显示 #DIV/0!、#CYCLE!、#REF!。
- `.scene`：纯 JSON，nodes 几何 / 层级 / 材质 / 关键帧、lights、camera、emitters。assets/helicopter-24.scene 是独立资源；同格式的其他场景也能打开。assets/build-scene.cjs 是原创资源生成脚本。
- `.flight`：保存资源与采样的实际机体状态，支持重开、定位与接续排演。
- `.snapshot`：子树序列化状态，保存至父系统 /Snapshots，通过文件管理器导出到本机。双击导入的快照分叉。恢复后的数据连接需重新连接。

## 实现边界

指令解释器有预算、时间等待、消息等待、程序状态与额度。子系统内核是父系统加载的指令文件，调度通过有限的内核服务指令执行；绘制设备与多数应用服务的内部算法仍由 JavaScript 实现，并非通用操作系统或硬件模拟器。内存使用序列化估算与场景固定估算，非完整精确的资源计费。排演为简化动力学；默认演出使用资源关键帧，排演记录保存实际采样状态。编译器以同一套 VM 指令编写，在进程预算内执行 JSON 解析、遍历与指令转换；底层 JSON 解析与最小指令校验是执行环境原语。它不是通用语言编译器。

绘制使用单一 WebGL2 renderer，将当前提交绘制到各个可见 canvas，避免多个三维窗口耗尽 WebGL 上下文。窗口与网页遮挡由 Chromium 合成，外部网页使用隔离的 webview，不开放 Node 或系统对象。关闭视图释放 guest；网页按真实时间运行，不进入虚拟时钟或快照。禁用后台遮挡节流。

## 可编辑内核服务（补充）

内核文件的 `code` 循环直接选择进程：`kernel.count` 读取进程数，`kernel.run` 按索引执行有限指令片，cursor 和跳转规则可改写。`services` 字典定义可中断、可保存调用栈的系统服务；与普通程序使用同一套 set/if/jump/wait/sys/return 指令。示例 `math.double` 接受 `input`，默认返回 `input*2`；将内核中的表达式改为 `input*3`，保存、重启后，程序 `{"op":"sys","call":"math.double","value":"14","name":"answer"}` 得到 42。可新增服务名称与指令体。

`message.send`、`file.read`、`file.write` 的服务体也位于内核文件中。修改 message 的处理表达式或文件 data 的处理表达式，会改变实际消息与文件结果。服务内的 `message.deliver`、`file.read.raw`、`file.write.raw` 是执行环境设备原语。服务进入时冻结传入值，返回时恢复调用者的 code、pc、变量与目标结果变量。

场景取样、特效与图表按资源数量额外消耗可中断工作单位，文件写入每 256 字符一单位；工作尚未付完时不提交结果。运行时检查覆盖未完成文件写入的快照与续行。虚拟时钟随祖先推进，不因低执行额度而变慢。预算不足会使程序实际处理落后于时钟。

## 编译器、程序显示与飞控扩展

/System/compiler.nest 也是可调度程序。新启动的程序先执行该编译器，再执行转换后的 code；编译过程中的 pc、数组与临时变量也可进入快照。预置编译器把 increment 指令转换成 set name=name+1。将编译器第 10 条指令的表达式改成 target+"+2" 后，此后启动的 increment 程序实际加 2。打开编译器本身，点击运行，可编译自身，结果写入 /System/compiler.compiled.nest。

程序可调用 display.submit，将 value 文本或矩形/圆/文本数组提交到独立的程序显示窗口；scene 参数可提供系统中的 .scene 路径，time 参数为场景取样秒数。程序不取得图形对象。

flight.sensor 支持 sensor 字段 altitude、x、z、verticalSpeed、heading，同时写入 sensorTime。flight.control 支持 value 总距与可选 heading 航向。排演在停机坪低速接触可安全着陆；高速接触与姿态发散判为撞击。

新增 tests/compiler.test.cjs 验证编译器变更与自编译；tests/lifecycle-ui.cjs 实测完整 15 秒投送演出、暂停/恢复、投送身份、排演与记录保存。

## 第二轮质量改进：可编辑应用程序

- `/System/player.nest` 直接计算虚拟时间差、播放位置、倍率、循环与结束条件，再请求有限的物理取样并发送场景消息。将 `position+delta*rate` 改成 `position+delta*rate*2` 会实际加倍播放推进。
- `/System/flight-scene.nest` 与 `/System/effects.nest` 分别消费时序消息；正常状态下完成同一时刻的机体/特效提交，挂起其中一个只冻结对应部分。
- `/System/data-receiver.nest` 接收祖先暂存的版本副本，通过进程消息交给 `/System/charts.nest`。图表程序逐行逐列取值和计算，未完成处理保留指令位置与中间数组。把计算改为 `value*2+7`，144 会变成 295。
- `/System/window-manager.nest` 读取输入消息、选择焦点目标、计算窗口层叠顺序并写回窗口记录；可以修改条件、顺序和路由代码。宿主仍承担 DOM 布局、原始指针命中、窗口拖动与多数常规应用控件的绘制/处理，这部分尚未完全转移成 VM 程序。
- 飞控设备按调用进程的播放器身份绑定，多实例不串用。播放器的「编辑飞控」进入编辑器后，执行目标会预选对应播放器；运行替换该播放器的控制进程。默认高度控制增加了垂直速度阻尼。
- 自制输入对话框替代 Electron 不支持的 `prompt`；保存/放弃/取消为同一对话框。文件夹操作支持递归副本、重命名、剪切、回收站原路径恢复，配额失败会回滚。
- 飞行记录重开从首帧开始，定位不提前触发未来故障；从历史位置继续排演会截断当前分支的未来记录，原保存文件不受影响。

新程序安装于新系统文件中；已经保存过的工作空间不会被静默覆盖。测试新版默认文件可使用新的 `--data-dir` 或 `bench.reset()`。

## 文件与窗口规则的程序化

`/System/files.nest` 逐项比较目录条目并提交排序后的列表；`sort` 可以改为 `descending`。`readOnly=true` 拒绝写入操作，`allowDelete=false` 拒绝删除，判断与分支在程序中执行。子系统文件创建、粘贴、重命名、删除和恢复经窗口管理队列交给文件进程，挂起期间请求保留，较大的复制按每 256 字符一个单位分步付费。`files.apply` 是可编辑内核服务，默认调用原子的事务文件设备。宿主负责显示程序提交的列表与对话框。

窗口管理程序接收指针坐标及窗口矩形数据，逐个进行边界判断和遮挡比较；`hitRule` 可由 `front` 改为 `back`，改变重叠区域选中的窗口。焦点、层叠和命中计算保留在 VM 执行位置中。DOM 原生控件内部的命中与输入编辑、窗口拖动布局仍由宿主处理。

`/System/snapshot.nest` 在父系统中运行，先固定一个逻辑时点的子树，再按副本体积消耗预算；复制和写入都完成后才出现可打开的快照文件。界面会提示处理中及完成状态。

追加验证：`files-program.test.cjs` 检查改排序/禁止删除/挂起/低预算复制；`window-hit.test.cjs` 检查改命中规则；`snapshot-budget.test.cjs` 检查父系统计费和未完成副本不写入。

## 桌面与飞行细节

所有系统的托盘和小组件时钟使用系统虚拟时钟；快捷缩放、强调色和免打扰与设置窗口共享状态。进程表直接显示剩余工作与估算 KB，并单列 Chromium 网页视图；挂起等待中的进程后继续仍保留原等待条件。工作表扩为 A1:L99，支持方向键/Tab 移动，非法区域与残缺表达式给出错误。

排演的接触查询读取资源中的静态 box / sphere / cylinder / cone 几何，地形高度与障碍尺寸改变会影响接触位置；圆形停机坪支持低速着陆。复杂旋转几何、任意网格与机体多点碰撞尚不支持。点击排演地面可设目标航向。物理步骤按场景节点与补算步数消耗预算。旋翼增加实时透明旋转盘，演出起飞尘土与故障烟跟随资源中的 actor，保持同一显示时刻。

`desktop-ui.cjs` 在 Electron 内验证倒计时通知、便笺、快捷设置同步、任务读数和由 VM 完成的子系统文件创建；`desktop-flight.test.cjs` 验证修改资源后的接触高度与公式非法引用。

## 投送显示副本与排演文件

播放器和图表程序显式执行 `app.present` 提交可复制的显示数据。复制按每 1024 字符一个逻辑单位计费，并随投送副本数增加；预算不足时保留待提交帧。投送窗口保存独立副本，控件通过源窗口身份返回消息，不能修改源应用的可变数据。资源、显示时间、相机和图表值随同提交，源播放器也使用已完成的提交绘制。恢复快照时重新接续对应源窗口的已保存显示。

从任一源窗口或投送窗口保存排演，都会在源系统创建文件写入程序；每次使用新的 `/Documents/排演记录-N.flight` 文件名，保留原记录。实测覆盖打开记录、暂停定位 1.5 秒、从该位置接续排演并另存分支。

`presentation.test.cjs` 验证预算不足时延迟提交、源/目标独立副本；`record-ui.cjs` 验证实际文件重开和分支保存。
