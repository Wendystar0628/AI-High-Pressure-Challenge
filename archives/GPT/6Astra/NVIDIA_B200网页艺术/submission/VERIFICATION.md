# 交付检查

入口：`index.html`。开发与检查均使用 `file:///`，未依赖本地服务器。

已完成的实际检查：

- Chrome 逐章打开、截图检查与交互；浏览器控制台没有运行错误。
- 1366×768、1440×1000、3840×2160 布局。
- 8 个连续导出区间，`begin('page', {fps: 3})` 与 `{fps: 60}`，随机进度和反向寻帧。
- 八章各取同一进度、同一时刻，在中间跳转到另一章后返回，WebGL 画面哈希一致。
- 七处章间边界分别比较同一晶粒角点的投影；边界两侧进度相差 0.0000002 时无可见位置跳变。
- 用浏览器表单实际输入 A = [1, 2; 3, 4]、B = [5, 6; 7, 8]，FP16 输出 [19, 22; 43, 50]，八卡归约 134。
- 切换稀疏后 A 的非对角元为零，输出 [5, 6; 28, 32]，归约 71，每次示意工作量由 16 FLOP 降到 8 FLOP。
- 输入、精度和稀疏选择跨章并刷新后仍保持。
- 显存独立查看、深入一级、移动剖切和精度联动。16 值 FP4 占 9 B（含块缩放），FP64 占 128 B，实际三维逻辑页填充随之变化。
- 五种产品切换、GPU / 链路 / 机柜托盘选择以及对应三维反馈。

数值回归：运行 `node verify.cjs`，验证 E4M3、FP16 舍入边界、E2M1 共享缩放、矩阵结果、稀疏操作数、八卡归约与显存容量边界。

说明：几何比例、功能区、TSV、微凸点与层厚经过示意化处理；工作量与传输速率是演示，不是硬件性能测试。详细配置口径及来源见网页「资料与说明」。
