# 操作系统嵌套 · 操作说明

## 0. 快速上手
- 根系统（标识 outer）是日常桌面。右键桌面、双击图标、开始菜单、任务栏、窗口按钮都可用。
- 从开始菜单的「子系统管理」或桌面图标创建直属子系统；每层都能再创建直属子系统，支持四层以上。
- 全部非根实例按创建顺序命名为 inner-1、inner-2……；层级由父子关系表达。
- 「系统」面板显示父子关系、运行状态与归属，可新建、启动、暂停、继续、单步、调速、重启、关闭、快照、恢复与分叉。
- 首次启动只显示根系统桌面，不自动播放演示。按 F1 或开始菜单「操作说明」可随时打开本文。

## 1. 系统模型
每个实例有独立的进程表、程序状态、虚拟时钟、消息队列、文件系统、桌面与应用状态。
根系统运行在桌面应用主窗口中；子系统作为父系统中的一个「承载进程」运行，该进程执行父系统文件系统里的内核程序。
宿主只提供：程序执行环境（CPU 设备）、显示设备、输入设备、时钟与随机数设备、原始磁盘设备；
不代替任何子系统做调度、消息投递、文件分发或应用推进。根系统的内核同样是一份内核程序（允许由宿主实现的部分仅作引导）。

### 1.1 逻辑步、虚拟时间与预算
- 一个逻辑步在 1 倍速下推进 0.1 虚拟秒；实际间隔 100 ms。界面与说明统一采用此长度。
- 子系统虚拟时间增量 = 父系统本步增量 × 自身速率，逐级如此。时间速率与执行预算相互独立，调快时间不补发预算。
- 每个系统每步有有限总执行预算；默认根系统 1800 单位，逐级递减（1250 / 900 / 700）。
- 预算沿祖先链逐级拨付：父内核按剩余预算与子实例上限决定实际拨付；后代工作全部计入承载进程读数，兄弟子树共享父系统剩余预算。
- 工作量单位 = 执行的指令 / 明确的计算步。指令按 1 单位计费；字符串、数组、文件、场景取样、表格重算、图表坐标、飞行物理、显示提交按数据规模追加计费（每 24~32 字符 1 单位，单次封顶）。
- 预算不足时未完成的工作保留进度，在以后取得额度后续行；结果与完成进度、进程和承载读数对应。
- 宿主的实际绘制、DOM 合成与 Chromium 网页执行不计入逻辑预算，这一边界是硬性的。

### 1.2 内存与存储配额
- 程序变量、数组、字符串、消息队列、进程与应用缓存、已载入显示设备的几何/贴图/实例/粒子规模占用内存；文件占用存储配额。
- 配额逐级拨付、兄弟共享；分配或载入失败时程序得到可处理的错误或被系统结束，影响限于所在配额范围。
- 任务管理器 / 进程管理器显示总预算、实际拨付、各进程消耗、剩余工作、内存与存储占用、错误。

### 1.3 暂停、单步、重启、停止
- 暂停一个实例停止整棵子树推进；继续后后代保留原有暂停或挂起状态。祖先暂停覆盖整棵子树。
- 父系统可让暂停的直属子系统执行一个固定逻辑时间步（0.1 虚拟秒 × 该实例速率）：这次单步覆盖其子树，后代仍遵守各自暂停状态、速率与逐级预算；父系统或其祖先暂停时不能发起。
- 重启：结束子树内原有进程，重新载入内核源文件，按保留的系统树结构从各实例初始运行状态启动，保留已保存文件。
- 停止实例或结束承载进程停止整棵子树；兄弟子树与祖先仍可使用。关闭实例后全部程序停止，已保存快照仍可重新打开。

## 2. 程序与系统接口
程序是可创建、编辑、保存、重新加载的文本文件（扩展名 .prog），用同一种格式书写，能表达变量与计算、条件与循环和系统服务。
程序在系统管理的执行环境中运行，不能直接访问宿主 DOM、宿主计时器或其它实例内部对象。

### 2.1 指令（每行一条，# 开头为注释）
    set 变量 = 表达式        赋值
    push 数组变量 表达式     追加到数组
    seti 集合 键 表达式      设置数组下标或映射键
    del 集合 键              删除
    label 名称 / goto 名称   标签与跳转
    if 表达式 goto 名称      条件为真跳转；ifn 为假跳转
    out 表达式               写入进程输出（消息小程序可核对）
    sys 名称 参数... -> 变量 系统调用（陷入所属内核，等待结果）
    dev 名称 参数... -> 变量 设备调用（仅内核/编译器可用）
    yield / end / err 表达式 让出 / 结束 / 异常结束

表达式支持数值、字符串、变量、四则与比较、逻辑运算及内建函数：
get(集合,键)、seti、len、str、num、isnum、cat、split、join、words、trim、find、has、keys、sub、char、rep、gotosub、abs、min、max、floor、ceil、round、type。
值可为数值、字符串、数组 []、映射 {}、布尔与 null。

### 2.2 系统服务（sys）
    sys time -> t                     读取本系统虚拟时间
    sys sleep 秒数                    等待指定虚拟时长
    sys self -> me                    取得自身身份
    sys spawn 程序路径 参数映射 -> pid 启动进程
    sys kill pid                      结束进程
    sys send 目标pid 值 -> ok         向指定进程实例发送消息
    sys recv -> 值                    等待并接收消息（先进先出）
    sys fread 路径 -> 内容            读取本系统文件
    sys fwrite 路径 内容 -> ok        写入本系统文件
    sys flist 目录 -> 列表            列目录
    sys fdel 路径 -> ok               删除
    sys draw 数据                     向所属应用显示区域提交二维图形或三维场景
    sys app_tick appId -> 结果        应用服务一次推进（图表/播放器/排演）
    sys quota 数值                    设置本进程额度上限
    sys sensor -> 传感器              排演传感器（带虚拟时间戳）
    sys control 总距 舵面 尾舵 -> ok  飞控写入控制量
    sys scene_sample 时刻 / sys fx_sample 时刻 位姿
    sys rand / sys clock / sys log / sys notify
    sys misc 名称 参数...             其它扩展服务（订阅、投送、记录、导入导出等）

消息只交给发送时指定的那个进程实例；同一发送者发给同一接收者按发送顺序接收；目标不存在时发送方得到明确结果；挂起接收进程时已到达消息保留，继续后按顺序处理。以上为预置内核规则，修改内核可改变它。

### 2.3 编译器
程序文件先由系统内编译器 /System/compiler.prog 降低为可执行指令表（去注释、把标签解析为行号），再由执行环境装载。
编译器是系统内程序，可以在编辑器中修改并「编译自身」，修改后的编译器用于此后启动的程序；编译本身按规模计入该系统预算。
引导载入内核与编译器自身时使用宿主 ROM 引导解析器，其余程序（含从编辑器新建的程序）都经过系统内编译器。
按说明新建的程序、改变循环次数与消息内容后的程序同样能运行，不限于预置程序。

### 2.4 内核程序与修改内核
每个子系统对应父系统文件系统中的一份内核源文件：/Systems/<实例id>/kernel.prog（模板为父系统 /System/kernel.prog）。
内核程序用同一种程序格式写成，由承载进程执行，实现：进程表、轮转调度、等待与唤醒、消息投递、文件配额与系统调用分发、直属子系统拨付。
修改下列参数并重启该实例即可改变实际行为，其它子系统不受影响：
    Q          时间片（默认 24）
    GRANTDIV   直属子系统分额分母（默认 1）
    MSGDROP    未知目标消息投递规则（0 报错 / 1 静默丢弃）
    READONLY   文件系统只读开关
也可以改写调度循环、增加系统调用分支或改变消息规则。内核写坏时该实例显示「内核错误」并停止，父系统与兄弟系统照常运行，改回后可重新启动。
「内核」控件 kernel-open 在父系统编辑器中打开该实例的内核源文件；system-restart 重启该实例。
子系统的窗口管理、文件管理器、播放器、图表工作台都是内核启动的程序（/System/programs/*.prog），源文件可改，重启相应应用或系统后生效。

### 2.5 显示设备
程序把场景资源（几何、材质、贴图、灯光）与每一时刻的场景状态（部件位姿、损坏、相机、粒子发射）作为可复制的数据经 sys draw 提交；
宿主显示设备按提交内容与时刻绘制（Three.js / WebGL 2），可展开烟尘、旋翼模糊等细节，但不推进场景状态：相同提交得到相同画面，两次提交之间画面不变。
所有三维视图共用一个 WebGL 上下文，逐视图渲染后拷贝到各自的 2D 画布，因此同时打开很多视图也不受每线程 16 个上下文的限制；上下文丢失后从系统状态自动重建。

## 3. 根系统应用
- 文件管理器（files）：目录导航、路径、文件列表、新建/重命名/复制/移动/删除/打开、文档/下载/回收站；删除可从回收站恢复；文件按类型打开到对应应用；跨层拖放；导出到本机 / 从本机导入。
- 电子表格（spreadsheet）：行列标题、单元格与区域选择、编辑、复制粘贴、撤销重做；公式支持四则运算、括号、单元格与区域引用、SUM；依赖重算；除零(#DIV/0!)、无效引用(#REF!)、循环依赖(#CYCLE!) 有明确反馈；可新建/打开/保存工作簿（.sheet，JSON），未保存修改有标示，关闭或打开另一文件前可保存/放弃/取消。
- 桌面小组件（widgets）：时钟与日历（可翻月）、倒计时（到时产生通知）、秒表（分段）、便笺（多张、可保留）、剪贴板历史（文本与表格选区，选区可作制表符换行文本）、通知中心（已读/清除/免打扰）、快捷设置（主题、强调色、缩放、免打扰，与系统设置一致）。
- 文本与程序编辑器（editor）：新建/编辑/保存/启动程序，可打开直属子系统内核源文件与飞控程序，「编译」按钮运行编译器。
- 任务管理器（tasks）：应用、自定义进程、直属子系统承载进程及其父子关系；状态、实际工作量、剩余工作、内存占用、错误；挂起/继续/结束；调整总预算、内存与存储配额、进程额度与子系统拨付上限；能区分逻辑进程与浏览器网页视图（Chromium 执行不计入自定义指令读数）。
- 设置（settings）：系统名称、壁纸、强调色、界面缩放，实际影响桌面与应用并保留；缩放后输入命中与窗口操作仍正确。
- 浏览器（browser）：复用现成 Chromium 内核（Electron webview），自制标签栏/地址栏/导航按钮/加载状态；真实联网、多标签、前进后退刷新停止、站内浏览与搜索；网页视图随自制窗口移动/缩放/裁剪/遮挡；网页未向宿主文件系统、Node.js 或系统内部对象开放。联网网页按真实时间与网络状态运行，不纳入虚拟时间、共享资源与完整快照。

## 4. 子系统应用
每层的非根系统以三维场景播放器、飞行排演、图表工作台、跨层窗口投送为主要入口，并保留文件管理器、文本与程序编辑器、进程管理器。
程序、场景资源、排演记录与配置从本系统文件系统读取，相关应用使用同一份实际数据。

### 4.1 三维场景播放器（player）
- 从本系统文件系统打开独立场景资源（.scene，纯数据 JSON，不含宿主代码）：几何与部件层级、材质与贴图、灯光、镜头、关键帧/飞行记录时序。
- 播放/暂停/继续/停止回开头/重播/逐帧前进/循环开关；显示当前时间、总时长、速率与状态；帧率 30 fps，逐帧推进 1/30 秒；非循环到结尾停在末帧。
- 进度条拖动或输入时间跳转；暂停后跳转仍暂停；调速不跳变。跳转与逐帧的第一次呈现就是该时刻的完整画面。
- 播放位置由播放器进程按所属系统时间推进，图形更新受调度与系统接口管理；暂停子树、单步或恢复快照时状态/读数/画面一致。
- 同一场景可在两个播放器或两个实例中分别打开，各自位置、速率、循环、相机、损坏与碎片互不影响。
- 镜头：演出镜头 / 跟随镜头 / 自由环绕（拖动与滚轮调整）；点击部件显示名称与损坏；排演中点击地面设为目标航向。
- 默认演出、排演与记录回放至少由时序、飞行场景、环境特效三个职责不同的进程协作（player_timeline / player_flight / player_fx.prog），时序进程经消息驱动后两者；挂起其中一个只停止它负责的更新。

### 4.2 场景资源格式与最小场景
    { "format":"scene/1", "name":"...", "duration":15, "fps":30,
      "environment": { "sky":"#...", "sun":[x,y,z], "terrain":{...}, "helipads":[[x,z],...], "objects":[...] },
      "model": { "parts":[ {"name":"hull","geo":"...","material":"...","transform":[...]}, ... ] },
      "lights":[ {"type":"directional","color":"#...","dir":[x,y,z]} ],
      "cameras": { "show":[ {"t":0,"pos":[...],"target":[...]}, ... ], "follow":{...} },
      "timeline": { "initial":{...}, "controls":[ {"t":0,"collective":0.3,...}, ... ] } }
最小场景（一个物体、一盏灯、一台相机）可写作：
    {"format":"scene/1","duration":3,"fps":30,
     "environment":{"sky":"#9ad","helipads":[[0,0]],"objects":[]},
     "model":{"parts":[{"name":"box","geo":"box:2,1,2","material":"purple","transform":[0,0.5,0]}]},
     "lights":[{"type":"directional","color":"#fff","dir":[1,2,1]}],
     "cameras":{"show":[{"t":0,"pos":[6,4,6],"target":[0,0.5,0]}]},
     "timeline":{"initial":{},"controls":[]}}
更改资源并重新打开后画面按实际文件内容变化；同一播放器可打开同格式其它合法场景，无需修改播放器源码。播放器和显示设备代码里没有写死这架直升机。

### 4.3 直升机场景与飞行排演（rehearsal）
- 默认演出 1 倍速总时长 15 秒：停机与旋翼加速 → 起飞 → 飞行 → 失控与下坠 → 撞击与余波（碎片、尘土、烟雾、火光、残骸停稳）。默认演出是资源中预置的一份飞行记录，结局不随预算变化。
- 场景是完整三维空间：起伏地形、两个停机坪、建筑障碍、树木草地与远景都是有体积对象；接触发生在这些几何上，改动资源里的地形或障碍，飞行结果相应变化。
- 紫黄配色 24 号直升机：紫色机身、黄色识别涂装、机身两侧醒目的「24」；连续曲面机身、透明驾驶舱（座椅与仪表板）、舱门接缝、发动机舱与排气口、桨毂桨叶、尾梁垂尾水平安定面、尾旋翼、起落架；部件可独立运动与损坏。
- 材质与光照：漆面、玻璃、金属、橡胶、地面、草叶粗糙度与反光不同；撞击后熏黑、断口露出内部结构；实时投影随离地高度变化，旋翼影子扫过机身。
- 烟尘与碎片：下洗气流带起尘土并压倒草叶；有厚度的碎片翻滚、落地、弹跳、停稳并投影；烟与火在三维空间中遮挡、随风偏移、照亮周围、遮住后景。
- 飞控进程：/System/controller.prog 是可在编辑器查看修改的普通程序文件，经 sys sensor 读取带时间戳的传感器值（alt/vy/pitch/roll/vx 等），经 sys control 写入总距与舵面；控制量保持到下一次写入，错过周期不补发。按说明新写的飞控程序同样能驾驶直升机；第二个停机坪可供悬停降落。
- 调度影响飞行：调低任一祖先拨付、在同一子树运行持续计算或提高时间速率，控制周期变长，机体抖动、发散直至坠毁；及时恢复可拉回。修改飞控程序改变飞行。物理落后于虚拟时间时画面停在已算完时刻，补算仍按虚拟时间与当时控制量进行。
- 飞行输入：风、目标航向、故障触发时机都会改变正在发生的飞行；不同输入历史与控制时序产生不同的接触与余波，不是换预设轨迹或固定时刻的同一组坠毁效果。
- 记录与回放：排演可保存为 .record 文件（场景资源路径、初态、实际输入、实际发生的控制时序）；重新打开后可跳转任意位置回放当时状态，回放结果不随当前预算变化；从同一位置可继续排演并给出不同输入/预算/飞控，分别保存连续后续，原记录仍可打开。记录回放使用播放器的进度与播放控制；系统完整快照另按 2.12 保存整棵子树。

### 4.4 图表工作台（charts）与实时数据连接
- 任一深度的子系统提供独立图表工作台，从根系统电子表格显式建立实时数据连接：选择已打开工作簿与矩形区域（如 A1:D4）、标签列与一个或多个数值列，生成分组柱状图或折线图，可切换类型；标题、坐标轴、图例、数据值与悬停/选中反馈清楚。
- 建立连接先取得选区当前完整值，之后每次提交单元格/区域编辑、粘贴、撤销或重做并完成公式重算后，发布该区域的新版本；未保存修改同样发布。图表看到的每个版本都是提交重算完成后的完整选区。
- 连接按工作簿文档身份与选区建立，数据以副本跨层传递；子系统保存自己的数据，不绑定根系统表格对象或宿主 DOM；版本只前进不后退，断开的连接不再改变图表。
- 数据接收（chart_receiver.prog）与图表计算/绘制（chart_draw.prog）是职责可区分的子系统进程，经消息协作，正常取得执行机会后才处理数据、计算坐标并提交图形；图表过渡使用子系统虚拟时间，源窗口与投送窗口显示同一结果。
- 暂停目标系统或其祖先时，根系统表格仍可编辑重算，更新在范围外按序暂存；继续后交给子系统按序处理。单独挂起接收或图表进程时其它进程继续，已接收消息保留。
- 可主动断开/重新连接；断开保留最后图表与数据；关闭源工作簿明确提示数据源已关闭并保留已接收数据；源工作簿重新打开后由用户重新选择连接。关闭图表或停止包含它的子树释放订阅。
- 根系统实时数据源不属于子树快照；恢复或分叉后图表用缓存与已接收数据续行，连接处于「已恢复，待重新连接」，重新连接时建立新连接并取得源工作簿当前完整选区。

### 4.5 跨层窗口投送（projection）
- 播放器与图表窗口都有「窗口投送」入口 window-project，project-target 选择任一祖先桌面（可跨过中间层直接到根系统）。目标桌面创建可独立移动、缩放、贴靠、最小化的投送窗口；源窗口保留；每个源窗口至多一个投送，再次投送聚焦已有窗口。
- 执行归属：源应用、状态与计算始终属于源系统，工作逐级记入承载预算；目标桌面只承载外框、显示与输入转发，不另启播放器或图表计算。
- 显示边界：源系统经显示接口提交可复制图形/场景数据副本，目标接收后绘制；不读取源可变应用对象，不搬动源窗口 DOM。源窗口与投送显示同一应用状态：同一时刻、同一机位，不同尺寸各自取景不拉伸。
- 输入往返：投送中的播放、进度、飞行输入、镜头拖动、三维点选、图表类型、数据点与数值输入经接口进入源应用消息队列，由源进程处理后提交新显示；一次输入只执行一次。
- 暂停与可见性：最小化源桌面/中间系统窗口/源应用窗口不停止源进程，投送继续更新；暂停源系统或任一祖先时应用内容冻结，投送控件禁用并提示原因；目标桌面仍运行时其外框与其它应用仍可操作。
- 关闭与隔离：关闭投送只取消视图，源应用继续运行并可再次投送；关闭源窗口、结束源应用或停止包含它的子树时对应投送结束并反馈。来源标识显示系统层级与应用。
- 投送外框归目标系统，应用内容与交互结果归源系统。

## 5. 文件、快照与跨层传递
- 每个系统有独立目录树，不同实例同名路径互不影响；工作簿、程序、内核源文件、场景资源、配置、排演记录与普通文本走同一套文件操作。
- 各层文件管理器之间可双向拖放文件（祖先↔后代、兄弟之间），投放前显示目标；经相应系统接口传递，目标取得独立副本；重名可取消或确认覆盖，目标存储配额不足时传递失败并反馈。
- 文件复制与实时订阅是两种操作：复制的工作簿保持独立；实时图表通过显式数据连接接收更新。
- 可把本系统文件保存到本机，再从本机导入；作品重启后导入仍能恢复整棵子树并继续运行。
- 每层可为运行中或暂停的直属子系统创建快照（父系统 /Snapshots/*.snap），保存选定实例及全部后代在同一逻辑时点的全部运行状态：系统树、内核与运行位置、各进程状态与变量、调度与未完成工作、虚拟时间、消息与计时等待、内存占用、文件、桌面、应用状态与随机状态；播放器、排演、图表状态与相机都在其中。宿主图形对象不属于快照。
- 可恢复到原实例，也可从中启动独立的新子树（分叉）。恢复/分叉只改变选定子树；范围外状态保持当前值；恢复与分叉后各节点使用新实例身份，内部关系指向分叉内对应节点。快照写入是父系统的工作，按规模消耗父系统预算与存储配额。

## 6. 工作簿格式（.sheet）
JSON：{"cols":8,"rows":20,"cells":{"A1":{"v":"项目","f":null,"style":{}},"D2":{"v":144,"f":"=B2*C2"}},"version":1}。
公式以 = 开头；保存格式包含内容、公式与基本格式，重新打开保留。示例工作簿 /Demo/sample.sheet 的 A1:D4 为示例数据，D 列保存公式。

## 7. 自动化约定
- 启动参数：--data-dir <目录> --width <宽> --height <高> --remote-debugging-port=<端口>；automation.json 记录启动命令、窗口标题、素材路径（fixtures）。
- window.bench.version = 1；await window.bench.ready()；await window.bench.reset()；await window.bench.inspect()。
- 自制界面的关键控件具有稳定 data-testid，标注 data-system-id，窗口容器标注 data-window-id / data-app-id；详见题面 2.17 的标识表。
- inspect() 返回 systems / windows / browsers / players / charts / projections，时间单位为秒。

## 8. 已知边界
- 外部网页由 Chromium 执行，不计入自定义系统的虚拟时间、逻辑预算与完整快照；网页失败可重试。
- 评分或录制时主窗口可能被其它窗口完全盖住：本作品的逻辑步由 setInterval 驱动并关闭后台节流，绘制与状态保存不依赖窗口可见性；被盖住时网页视图可能空白，但作品不会停止运行或留下空白自定义画面。
