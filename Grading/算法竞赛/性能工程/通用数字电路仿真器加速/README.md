# 通用数字电路仿真器加速：隐藏测试数据

本目录是题目《通用数字电路仿真器加速》的隐藏测试数据和出题工具，**不能让被测模型接触**。

## 目录内容

| 路径 | 说明 |
|---|---|
| `performance/inputs/input_01.txt` – `input_24.txt` | 24 个隐藏性能输入，每个约 9 MB：8 类电路结构，每类 3 个实例 |
| `performance/expected/expected_01.txt` – `expected_24.txt` | 对应的标准答案（评测程序的标准输出），由参考解法算出 |

| `grader/grader.cpp` | 官方评测程序，与题面第五节中的代码逐字节一致 |
| `baselines/reference_solution.cpp` | 参考解法：出题人写的通用优化解法，每次评测重新运行，其用时 $R_i$ 是加速比的分母 |
| `baselines/weak_solution.cpp` | 弱基线：认真的第一版写法，只用来交叉核对标准答案，不参与计分 |

所有文件都使用 LF 换行。

各类结构与参数含义（生成器第 3 个及之后的参数；省略时取方括号中的默认值，与上一版输出逐字节相同）：

- **深链**：每个门的输入大多来自最近生成的若干个门，依赖链极长。参数为取输入的窗口大小 [64]；窗口越小，链越深。
- **多层宽网格**：输入主要来自上一层，另有约 20% 跨层长距离连线。参数为层数 [40]，主体约 45 万个门平均分到各层。
- **阵列乘法器**：大量阵列乘法器，部分乘积再经加法器累加。参数为乘数位宽 [16]。
- **分组密码轮函数**：64 位状态经异或轮密钥、4 位非线性替换、置换和线性混合。参数为每块的最少轮数 [6]，每块轮数在该值到该值加 6 之间随机。
- **控制逻辑**：多路选择树、16 位比较器、相等判断和译码器。参数为选择位数 [5]，即 $2^k$ 选 1 和 $k$–$2^k$ 译码。
- **寄存器堆**：4096 个触发器组成 $2^a$ 个 $4096/2^a$ 位寄存器，64 个读口，外加胶合逻辑。参数为地址位数 $a$ [7] 和写口数 [16]。
- **环形流水线**：每级读上一级的寄存器、写本级的寄存器，最后一级接回第一级。参数为级数 [16]，每级写 $\min(448,\ 8192/\text{级数})$ 个触发器。
- **混合 SoC**：乘法器、密码轮、控制逻辑和随机逻辑块混合。三个参数为乘法器、密码轮、控制逻辑块的累计百分比 [25 50 70]，其余为随机逻辑块。

所有电路都满足：

- 每个门在结构上均可到达某个触发器或主输出，每个触发器都经异或折叠接到主输出。这不等于经过布尔化简后每个门都不可删除。
- 每个电路 4096 组激励的摘要 $H_m$ 互不相同（24 个电路均已核对）。上一版统计过原有 8 个电路主输出为 1 的比例，约为 0.499。
- 用 `gen_hidden.exe` 按表中参数重新生成，与 `performance/inputs` 中的文件逐字节一致。

- 24 个中位数在 0.95–2.51 秒之间，合计约 27 秒。同一输入 3 次实测的差异（最大值÷最小值−1）中位数为 1.8%，最大为 11.2%（05 号）。05 号（14 层宽网格，参考解法最慢的输入）单次运行的波动明显大于其他输入，健康检查的单输入警告（阈值 10%）在该输入上可能偶尔被触发；其余输入 3 次实测的差异都在 6% 以内，多数在 3% 以内。
- **参考解法**：只保留能影响输出的门；在深度优先序和按层序中选需要存储位置更少的一种，并复用已不再使用的存储位置；软件预取；AVX2 一次处理 256 组激励；门计算无分支；用 64×64 位矩阵转置生成主输入、计算摘要。
- **弱基线**（只用于交叉核对）：Kahn 拓扑序；每个门用 switch 计算；每个信号存 4 个 64 位字，一个线程一次处理 256 组激励。
- 每次运行的原始计时见 `validation.json`。其中 `reference_medians_ms` 是 `evaluate.py` 健康检查的参考值：正式评测中参考解法在每个输入上默认只运行一次，其用时若在任一输入上偏离超过 10%，或几何平均偏离超过 5%，报告会给出警告，不改变得分。
- 题面不设固定的单输入时间上限：提交在某个输入上的 $s_i\le0.1$（不到参考解法速度的十分之一）时，该输入得 0 分；每个进程仍有 60 秒的防挂起限制。参考解法每个输入约 1.0–2.5 秒，0.1 倍速的提交约 10–25 秒。

## 校验

- 标准答案由参考解法算出，每个输入运行一次并保存其标准输出。
- 弱基线与参考解法是两套独立实现。新增的 16 个输入上，弱基线的输出与标准答案逐字节一致；原有 8 个输入（现编号 01、04、07、10、13、16、19、22）的输入和答案只改了编号、内容未变，上一版已用弱基线逐字节核对，本次未重跑。
- 上述标定会话中，参考解法 72 次运行的输出全部与标准答案一致。
- 参考解法和弱基线均通过 7 个正确性输入，评测程序预热调用中样例电路的结果都正确。错误的原地触发器更新实现会在正确性输入中被检出（上一版记录，见 `validation.json` 的 `sequential_update_mutant`）。

## 评测时

在本目录的上一级运行统一工具，参考解法可执行文件必需：

```powershell
python evaluate.py --task circuit --exe C:\eval\circuit\grader.exe --reference C:\eval\circuit\reference.exe --report C:\eval\circuit-result.json
```

工具先运行提交的 7 个正确性输入（任一失败即记 0 分，后面不再运行）；再在每个性能输入上让参考解法和提交各运行一次（`--repeats N` 时各 N 次，奇数输入先参考解法后提交，偶数输入先提交后参考解法，取各自中位数），按题面评分标准输出 $R_i$、$C_i$、$s_i$、各输入得分、作参考的 $G$ 和本题得分。参考解法本身运行失败时这次评测作废。具体说明见上一级 README。

以下命令展示单次运行和性能输入重建方式；手工评测时也必须执行正确性检查，并在同一次评测中运行参考解法。

把 `grader/grader.cpp` 与选手解法放在同一目录编译（参考解法同理，把 `solution.cpp` 换成 `baselines/reference_solution.cpp`）：

```
g++ -O2 -std=c++20 -march=native -fopenmp -o grader.exe grader.cpp solution.cpp
```

对每个隐藏输入运行一次（一个新进程），读取 `simulate_ms`，并比较标准输出与 `performance/expected` 中的答案（忽略行尾的 `\r`）：

```
set OMP_NUM_THREADS=16
start "" /b /wait /high /affinity FFFF grader.exe input_01.txt > out_01.txt 2> time_01.txt
```

由生成参数重新生成输入，结果应与 `performance/inputs` 中的文件逐字节一致：

```
g++ -O2 -std=c++20 -march=native -o gen_hidden.exe gen_hidden.cpp
gen_hidden.exe deep 6151827736420917 > input_01.txt
gen_hidden.exe regfile 5872924447304816 8 24 > input_18.txt
```
