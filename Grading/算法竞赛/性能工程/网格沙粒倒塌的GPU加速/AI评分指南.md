# 网格沙粒倒塌的GPU加速 · AI 评分指南

依据题面 `E:\Project\AI_OneShot_Bench\算法竞赛\性能工程\网格沙粒倒塌的GPU加速.md` 第八、九、十二节，满分 100 分。评分资料：本目录的 `grader/`（评测程序 `grader.cu`）、`baselines/`（参考解法 `reference_solution.cu`；另一份朴素实现 `weak_solution.cu` 只用来核对标准答案，评分时不用）、`performance/`（24 个性能输入及答案）、`correctness/`（7 个正确性输入及答案）；上一级目录的 `evaluate.py` 及其说明 `README.md`。

## 评分要点

- 用题面第七节的编译命令（在 Visual Studio x64 开发环境中），把 `grader.cu` 分别与提交、参考解法 `baselines/reference_solution.cu` 编译成两个可执行文件，再运行 `evaluate.py`，例如：

  ```
  python E:\Project\AI_OneShot_Bench\Grading\算法竞赛\性能工程\evaluate.py --task sand --exe <提交.exe> --reference <参考解法.exe> --report <报告.json> --pause 1
  ```

  本目录 `validation.json` 中参考解法的标定耗时（`reference_medians_ms`）是在 `--pause 1`（每次运行前停顿 1 秒）下测得的；`evaluate.py` 拿它核对本次参考解法的耗时，偏差大时只给出警告，不改变得分。参考解法本身运行失败时，本次评测作废。
- 计分以 `evaluate.py` 按题面公式算出的结果为准：同一次评测中，参考解法和提交在 24 个性能输入上各运行一次，计时分别为 $R_i$、$C_i$，加速比 $s_i=R_i/C_i$；报告里另给出 24 个 $s_i$ 的几何平均 $G$ 作参考，不用于计分。
- 每个性能输入单独计分：按题面第十二节的锚点表在 $\ln s_i$ 上分段插值，$s_i$ 为 0.2、0.5、1、1.5、3、6 时分别得 0、5、20、34、60、100 分；$s_i\le0.2$ 得 0 分，$s_i\ge6$ 得 100 分并注明需要复核。提交在某个性能输入上运行失败（输出错误、CUDA 报错、超过进程时间、崩溃）的，该输入记 0 分。24 个输入得分的平均值，再乘以“通过的正确性输入个数 ÷ 7”，就是本题得分：某个正确性输入失败只去掉它那 1/7，性能输入照常测试计分。
- 按题面规则 8，内存和显存（显卡同时负责显示输出）占用过多导致内存、显存紧张或运行异常的，酌情扣分。你记录提交的内存、显存占用和有无异常，扣不扣、扣多少由出题人决定。

## 记 0 分的情形（照原文）

出现以下任一情形，本题记 0 分：

- 编译失败；
- 违反题面第九节的规则，即下列任一条：

1. 单个源文件 `solution.cu`，不超过 256 KB，实现 `init()` 和 `solve()`，不含 `main()`。
2. 只用 C++ 标准库、CUDA Runtime API、CUDA C++ 设备端功能（含内建函数和内联 PTX）以及 CUDA Toolkit 自带、无需额外链接的头文件库（如 CUB、Thrust）；不以任何方式调用 CUDA Driver API，不用其他第三方库。
3. 求稳定状态的全部计算在 `solve()` 中由 GPU 完成：
   - 主机端只能读回少量控制信息（总量与 $L^2$ 相比可忽略）并据此决定是否继续提交工作，不能把网格内容复制回主机，不能在 CPU 上对格子数值做任何计算；
   - `init()` 只能分配和释放显存与主机内存、把解法自己的缓冲区清零、创建流和事件等运行时对象，除清零外不做任何计算（包括只依赖 $L$ 的预计算），不读写评测程序的网格；`init()` 返回时，解法创建的主机线程不再做任何工作。
4. 不读写文件，不使用或改动标准输入、标准输出和标准错误，不联网，不启动其他进程。
5. 程序通用：对任意满足题面第一、六节约束的输入都返回正确结果；不针对具体输入硬编码结果，不在源码中内嵌预先算好的数据。
6. `init()`、`solve()` 会被多次调用，规模可以不同：`init()` 能按新的 $L$ 重新初始化；可以复用已分配的显存，但每次 `solve()` 都重新初始化本次状态，不复用之前调用的计算结果；结果写回 `grid` 本身，不释放 `grid`；所有 GPU 工作在 `solve()` 返回前提交，返回后不再有主机线程提交工作。
7. 不修改评测程序，不干扰任何一次运行的计时（包括参考解法的运行）；不改进程或线程的处理器亲和性和优先级，不超出给定的逻辑处理器；不改系统设置或任何能延续到进程结束之后的状态，不访问或影响本进程以外的进程。
8. 每次运行的整个进程不超过 60 秒；内存和显存见“评分要点”。

- 规则 5 的认定：看程序是否按具体输入的内容分支，或在源码中内嵌针对评测输入算好的结果；与输入无关的通用常量表（如查找表）不算违规。性能输入上运行失败只按该输入记 0 分，不据此认定违反规则 5。

## 输出

得分；正确性输入通过个数（k/7）；24 个性能输入的 $R_i$、$C_i$、$s_i$ 和各输入得分，以及作参考的 $G$；对题面第九节各条规则的审查结论；提交的内存和显存占用情况。题面“规定”一节（第十节）的执行情况不在评分范围内。
