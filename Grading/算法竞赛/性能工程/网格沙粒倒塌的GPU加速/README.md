# 网格沙粒倒塌的GPU加速：隐藏测试数据

本目录是题目《网格沙粒倒塌的GPU加速》的隐藏测试数据和出题工具，**不能让被测模型接触**。

## 目录内容

| 路径 | 说明 |
|---|---|
| `performance/inputs/input_01.txt` – `input_08.txt` | 8 个隐藏性能输入 |
| `performance/expected/expected_01.txt` – `expected_08.txt` | 对应的标准答案（评测程序的标准输出，每个约 16 MB） |
| `generator/gen_sand.cpp` | 隐藏输入生成器 |

| `baselines/strong_solution.cu` | 强基线：出题人写的通用优化解法，仅作参考 |

## 接口与计时区间

题面第三、四节的接口为 `void init(int L)` 与 `void solve(uint32_t* grid, int L)`：

- 评测程序在计时区间外解析输入，在主机上把各堆沙粒累加成初始网格，`cudaMalloc` 分配显存网格（`uint32_t`，下标 `y*L+x`）并上传，然后调用 `init(L)` 并同步。解法在 `init()` 中分配自己的显存。
- 计时区间只有 `solve(grid, L)` 与其后带错误检查的 `cudaDeviceSynchronize()`。`solve()` 在显存中原地把网格变为稳定状态。
- 计时结束后评测程序下载网格，检查每个格子为 0–3，再按原格式写出。
- 预热：对样例 2（`L=5`）走同样的 `init` + `solve` 流程，不计时，结果错误则本次运行失败。之后对测试输入再次调用 `init(4096)`，解法必须能重新初始化。
- 旧接口（`std::vector<uint8_t> solve(const SandInput&)`）的计时包含主机累加、显存分配、上传和下载等固定开销，旧耗时不能与下表比较。

## 八个输入

全部满足题面第六节的规模：$L=4096$，$P\le 2\times10^6$，$C\le 2^{23}$。$R$ 为同步规则（每轮每个格子倒塌 $\lfloor h/4\rfloor$ 次）下有倒塌发生的轮数，“倒塌总次数”与倒塌顺序无关。

| 编号 | 沙粒分布 | 生成参数 | $P$ | $C$ | $R$ | 倒塌总次数 |
|---|---|---|---|---|---|---|
| 01 | 中心附近的单个大堆 | `single 830172645513 860000` | 1 | 860000 | 165406 | 12912050404 |
| 02 | 中部的 4 个大堆 | `few 271940388615 2120000` | 4 | 2120000 | 171942 | 27178508934 |
| 03 | 全图随机的 16 个堆 | `many 664018273951 4520000` | 16 | 4520000 | 166627 | 32021175031 |
| 04 | 8 个中堆加大量小堆，散布全图 | `dust 918273645501 5860000` | 91591 | 5860000 | 168048 | 30410741429 |
| 05 | 靠近边界的 12 个堆，大量沙粒落出网格 | `edge 345612987734 3370000` | 12 | 3370000 | 168379 | 33347862265 |
| 06 | 连续 675×675 棋盘区域，一半格子初始为 8（平均密度 4，高于稳定状态的上限 3），形成持续的密集活动区 | `dense 572839104656 675 8` | 227813 | 1822504 | 166633 | 21832578832 |
| 07 | 沿半径 700 的圆环和十字分布的 2 万个中堆 | `ring 103948576613 6600000 700` | 20000 | 6576692 | 168034 | 71578167446 |
| 08 | 5 个大堆、大量中小堆和稀疏背景混合 | `mixed 486120375597 3700000` | 839598 | 5379592 | 165920 | 25239545000 |

- 新接口下弱基线每个同步轮在全图上约需 84 µs，耗时几乎与 $R$ 成正比。为压低计时噪声，各输入按同一目标重新标定：弱基线每个输入约 14 秒（$R\approx1.6\times10^5$–$1.7\times10^5$），8 个输入合计约 2 分钟。种子与分布族沿用上一版，只调整沙量参数。
- 06 号原为 1900×1900、每个活跃格 4 粒的棋盘区（平均密度 2），约 950 轮即稳定；现改为每个活跃格 8 粒，沙量超过区域所能稳定容纳的上限，必须经边界向外长距离扩散，整个过程中区域内大部分格子持续倒塌。
- 07 号的圆环半径由 1100 改为 700：该分布的轮数约与沙线密度的平方成正比，半径 1100 时即使用满 $C\le2^{23}$ 也只能达到约 10 秒。
- 生成器新增可选的第 4 个参数：`ring` 为圆环半径（默认 1100），`dense` 为每个活跃格的沙粒数（默认 4）。省略时与上一版生成器的输出逐字节相同；生成器拒绝输出超出 $P\le2\times10^6$ 或 $C\le2^{23}$ 的输入。

答案由独立的 Python 串行工作队列计算：每次选择不稳定格子进行合法倒塌，直至稳定。它与两套 GPU 同步迭代基线采用不同的执行方式。输入和答案的格式与评测程序接口无关，本次未改动；可用上一级 `gen_correctness.py --task sand` 重建。

- 强基线的综合加速比 $G=5.482$，按题面评分标准（$S_{\max}=576$）对应 26.8 分。
- **弱基线**：全图同步更新，以 32×32 为输出分块、外加 4 格边缘，在共享内存双缓冲中连续计算 4 轮；每 64 个逻辑轮次读回一次终止标志。不使用活跃区域筛选，每次仍处理全图。`init()` 分配第二个网格缓冲区和标志；每次检查之间的启动次数为偶数，结果自然落在评测程序的网格中。
- **强基线**：同样的同步规则；每个线程块把 64×64 的区域（48×48 内部加 8 格边缘）载入共享内存，在里面连续算 8 轮再写回内部；只处理自身或 8 个相邻区域在上一次启动中仍有变化的区域。`init()` 分配第二个缓冲区和活跃标记；若最后一次启动写在第二个缓冲区，则在显存内复制回评测程序的网格。
- 此前一次同条件的会话（候选为功能相同的强基线构建）中，弱基线各输入中位数与上表相差不超过 3.5%，几何平均相差约 0.1%，强基线 $G=5.497$。
- 每次运行的原始计时、中位数和逐例正确性结果见 `validation.json`。其中 `weak_baseline_medians_ms` 是 `evaluate.py` 健康检查的参考值：正式评测中弱基线的中位数若在任一输入上偏离超过 5%，或几何平均偏离超过 3%，报告会给出警告。

## 校验

- 标准答案由强基线算出。弱基线和强基线是两套独立实现，在 8 个输入上的结果逐字节一致（弱基线另行单独运行一次比对，并在上述会话中每次运行都与标准答案比对）。
- 两个基线均在新评测程序下通过 7 个独立参考答案的正确性输入，预热样例结果正确。
- 另用强基线的计数副本核对：8 个输入的同步轮数和倒塌次数见上表，计数副本的输出同样与标准答案一致。

## 评测时

在本目录的上一级运行统一工具，弱基线可执行文件必需：

```powershell
python evaluate.py --task sand --exe C:\eval\sand\grader.exe --weak C:\eval\sand\weak.exe --strong C:\eval\sand\strong.exe --report C:\eval\sand-result.json
```

工具先运行提交的 7 个正确性输入（任一失败即记 0 分），再依次让弱基线、强基线和提交在每个性能输入上各运行一次，按题面评分标准输出 $W_i$、$C_i$、$s_i$、$G$ 和得分。具体说明见上一级 README。

以下命令展示单次运行和性能输入重建方式；手工评测时也必须执行正确性检查，并在同一次会话中先运行弱基线。

在 Visual Studio 的 x64 开发环境中，把 `grader/grader.cu` 与选手解法放在同一目录编译（弱基线同理，把 `solution.cu` 换成 `baselines/weak_solution.cu`）：

```
nvcc -O3 -std=c++17 -arch=sm_89 -Xcompiler "/O2 /utf-8" -o grader.exe grader.cu solution.cu
```

单次运行（新进程），取 `solve_ms`，并比较标准输出与 `performance/expected` 中的答案（忽略行尾的 `\r`）：

```
start "" /b /wait /high /affinity FFFF grader.exe input_01.txt > out_01.txt 2> time_01.txt
```

由生成参数重新生成输入，结果应与下面的指纹一致：

```
g++ -O2 -std=c++20 -o gen_sand.exe gen_sand.cpp
gen_sand.exe single 830172645513 860000 > input_01.txt
gen_sand.exe dense 572839104656 675 8 > input_06.txt
```
