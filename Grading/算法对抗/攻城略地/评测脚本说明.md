# 攻城略地评测与定分工具

## 正式评测

```powershell
python E:\Project\AI_OneShot_Bench\Grading\算法对抗\攻城略地\evaluate.py --bot <bot.exe> --report <报告.json>
```

默认读取同目录的baselines.json和seeds.json。正式配置是五档、96个不同隐藏种子、每图对每档一局、8局并行、CPU 0–15，共480局。按种子文件顺序从1编号，奇数图提交为甲方，偶数图为乙方；每档48甲、48乙。对手自动按题面g++路径及-O2、-std=c++20和配置宏编译。提交应事先用公开main.cpp编译，规则检查由评分执行者负责。

公开arena.py仍然是每图换边各一局的本地工具，没有改它；正式evaluate和基线循环赛改为单图单局交替座位。

## 陪练对准

```powershell
python E:\Project\AI_OneShot_Bench\Grading\算法对抗\攻城略地\evaluate.py --bot .\my_sparring.exe --seeds 100800-100999 --cpus 0-15 --jobs 8 --report .\calibration.json
```

开发种子只用100000–100999，可写范围或逗号列表。明确给出--seeds、--cpus、--jobs时进入开发模式，不读隐藏种子。每图对每档一局，按列举顺序交替座位；200图五档共1000局。CPU分配必须按指挥当时许可填写，示例0–15不是自行使用的授权。

控制台只给各档胜平负表、r和判罚汇总；没有逐回合日志、没有命令输出，脚本也没有--log-dir参数。报告games只是每局结果摘要。正式陪练对准使用已完成定分的baselines；临时配置可用--baselines指定。

可选--work-dir改变编译/裁判缓存，默认报告同级的<报告名>_work；--calibration改变周期系数文件，默认本目录cycles.json。原始CPU/墙钟/内存限制固定，不提供放宽倍率。一个对局不重试，完整运行才计分。

## baselines.json v2

顶层schema是siege-baselines-v2，opponents按弱到强排列。每项：

```json
{"id":"tier1","name":"第1档","rating":0.0,"score":0,"source":"opponents/baseline.cpp","defines":{"TIER":1}}
```

五个score依次是10、20、40、60、80；rating用96图循环赛的实际拟合值，严格递增。源码相对配置文件目录解析，也可用绝对路径；defines为编译宏，可省略。不同对手可以指定不同源码。id只能含英文字母、数字、下划线或连字符，且不能为保留名candidate。

R1-200是0分锚点、R5+200是100分锚点，都由脚本自动派生，不增加对手。r下界仍R1-200、上界仍R5+200。R1-200到R1由0线性增至10，R1到R5在各档锚点间线性插值，R5到R5+200由80线性增至100。临时2–4档也可运行，使用10/20/40/60前缀分值；没有完整五档时不补0分和满分锚点，临时分数不作正式评分。

旧siege-baselines-v1（0/25/50/75/100）会被拒绝，避免混用旧满分线。

## 正式基线循环定分

tournament.py支持--round-robin <名册.json>，生成每张图每对一局的循环赛。名册players按tier1到tier5顺序，包含id/name/executable/source/defines；推荐全部用绝对路径。默认读取正式96个种子；奇数图较低档为甲，偶数图较低档为乙，每对96局，十对共960局。--seeds可改为开发种子范围；原--matches显式比赛列表仍可用，列表按原样执行。

```powershell
python tournament.py --round-robin roster.json --report round_robin.json --cpus 0-15 --jobs 8
python rate.py round_robin.json --anchor tier1 --output ratings.json --roster formal_roster.json --baselines baselines.json --require-formal
```

写正式基线的名册还需seeds字段，保留这96张图的原顺序（自动定分脚本会写）。rate的数值拟合仍为无正则Bradley–Terry，--require-formal检查96图、每对一局、交替座位的完整960局；缺局、重复、实力值非递增或不收敛都不写正式配置。--ridge仅用于探索，正式导出要求0。

## 报告与重抽样

报告schema为siege-evaluation-v2。complete才是完整结果；running/error/interrupted不能当评分。主要字段为score、score_raw、score_ci95、score_ci95_raw、r、rating_bounds、rating_ci95、by_opponent、wins/draws/losses、cpu_timeout_turns、forfeit_losses、penalty_games、对手侧相应计数，以及simultaneous_forfeit_draws。完整五档还给出full_score_rating=R5+200。

报告保存种子顺序、座位规则、实际CPU池/周期系数和逐局结果摘要，没有命令。is_official_configuration只有五档10/20/40/60/80、正式96图、8局并行和CPU 0–15时才为true。pid是这次控制进程PID，仅在自己启动的运行中进程上用于中断。

1000次重抽样按地图整块，抽到的图携带其对所有档的单局和原座位，不重新轮换座位。每个抽样里各档仍恰好map_count局，因此等价地用每图完整块得分汇总求MLE。按种子排序后用独立SplitMix64、固定种子0抽样，分位数用(n-1)*p相邻线性插值；未舍入分数先求区间，最后十进制四舍五入到一位。区间不改变得分。

双方同时判罚按题面记平，增加penalty_games和simultaneous_forfeit_draws，不增加forfeit_losses。对手编译或裁判故障停止，不伪装成受测0分；编译诊断只写工作目录opponents/<id>.compiler-error.txt供指挥/基线作者查看，不在控制台或报告展开源码。完整成功退出0，错误2，用户中断130。
