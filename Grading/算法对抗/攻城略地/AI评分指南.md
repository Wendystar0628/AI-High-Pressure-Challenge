- 一律评作答结束时工作目录中的内容，不看git提交。
- 依据：题面第五、六、七、八、十一节。公开材料在 `算法对抗/攻城略地/`，作答时整个文件夹复制成 `数据/`。除了engine.hpp、main.cpp、mapgen.py、arena.py、sample_bot.cpp，还需referee_core.py、winproc.py、engine_bridge.cpp及两个陪练exe。
- 评分材料在本目录：五档源码opponents/、96个隐藏种子的seeds.json、正式实力值baselines.json、evaluate.py、judge_core.py、cycles.json。满分100，本题在性能评分队列中整题串行测量。

## 测量与计分

先按题面编译提交。编译器固定为 `C:\msys64\ucrt64\bin\g++.exe`，运行时其目录也应在PATH中：

```
g++ -O2 -std=c++20 -I数据 -o bot.exe 数据\main.cpp bot.cpp
python E:\Project\AI_OneShot_Bench\Grading\算法对抗\攻城略地\evaluate.py --bot <bot.exe> --report <报告.json>
```

evaluate自动编译对手，读取正式五档实力值和96张隐藏图。按种子文件中的顺序编号1–96，每图对每档各一局；奇数图提交为甲方，偶数图提交为乙方。每档96局（48甲、48乙），共480局。所有提交使用同一地图及座位安排。8局并行、逻辑处理器0–15，每个选手进程独占一个逻辑处理器。

只跑这一次，不重跑对局，不剔除失败局。每局胜1、平0.5、负0；超时、欠时、连续超时、5秒墙钟、退出及1GB内存判罚全部按题面，双方同回合都触发判负条件记平局。

实力值r满足各局预期得分之和等于实际总得分，预期为 `1/(1+10**((R-r)/400))`。r约束在 `[R1-200,R5+200]`，全胜/全负取对应边界。

分数锚点：R1-200对应0分，R1/R2/R3/R4/R5分别对应10/20/40/60/80分，R5+200对应100分。在相邻锚点间线性插值；不高于R1-200得0分，达到R5+200得100分。保留一位小数。与最强档实力相当为80分，明显更强才满分。

95%区间：按地图整块、有放回重抽样1000次，每次抽96张图，带上被抽中图上对五档的全部5局和原座位，重求r和分数。取分数样本2.5%及97.5%分位。区间仅说明可信度，不改分数。

以evaluate.py的score为准。报告包含score、score_ci95、r、by_opponent各档胜平负、cpu_timeout_turns、forfeit_losses。双方同时判罚而记平的局单列，不算实际判负损失。

## 记0分与错误

提交编译失败，或违反题面第八节1–6条，记0分。源文件名或位置与题面略有出入的从宽；必须能与官方main.cpp编译，实现decide接口，遵守标准库、单线程、文件/联网/进程及计时规则。规则判断仍由评分执行者按题面原文做，不由脚本自动审查源码。

对手编译失败、裁判或环境异常属于评测错误，报告error且没有score/r，不得当作受测0分。联系指挥处理，不能自行剔除个别局或补跑。

## 输出

得分和95%区间；实力值r；对五档各自胜平负；超时回合数和判负局数；报告路径。baselines.json版本为siege-baselines-v2，五个对手的score为10/20/40/60/80，0分锚点R1-200和满分锚点R5+200由脚本自动计算，不是额外的对手。
