# 鲁班锁拆解 · 评分指南

- 评分版本：一律评作答结束时工作目录中的内容，不看 git 提交。

- 材料：受测作答目录里的题面 `鲁班锁拆解.md`、`鲁班锁拆解\01.json`–`08.json` 和 `答案\第01题.json`–`第08题.json`；出题端参考路线见本目录 `标准解答/`，来源与基准说明见 `参考答案.md` 和 `references.json`。
- 判定：用本目录的 `check.py` 和出题端原始题目检查整棵拆解树，接受任何合法路线。完整拆开按步数计分；没拆完的按从初态起合法完成的分离计部分分。
- 路线要靠推理找出。先读受测会话记录：运行题目自带的 `鲁班锁拆解/工具/check.py`（路线检查器）和 `鲁班锁拆解/工具/positions.py`（位置记账）是允许的；自己编写或运行程序来搜索路线、模拟移动、计算碰撞，使用求解器，或改动这两个工具，都算违规，这样的作答记 0 分，在 notes 写明依据。几何检查器只判断路线，不能代替对工具使用的检查。

## 计分

w 为该题分值。每题的基准步数 B 是 `references.json` 中该题的 `best_moves`，取参考解的完整步数，01—08 依次为 8、10、14、12、14、15、42、27，固定不变。

- 完整拆开：路线合法并把全部零件拆开，总步数 N，得 `w × max(0.6, min(1, B / N))`。步数等于 B 得满分，比 B 少也只得满分；绕得再远也有 60% 保底。
- 没拆完：从初态起按 `check.py` 的深度优先顺序（本组件、`removed` 分支、`remaining` 分支）逐步检查，到第一处碰撞、记号错误或没拆完的分支（写 `null`、缺分支、本段没有 `out`）为止，合法完成了 k 次分离，得 `w × 0.5 × S_k / S_total`，每完成一次分离都加分。S 是 `references.json` 的 `reference_stage_moves`，即参考解用同一 `check.py` 校验得到、按同样顺序排列的各阶段步数；S_k 为前 k 项之和，S_total 为全部之和。01—08 依次为 4+2+2、6+2+2、6+7+1、8+4、10+1+1+1+1、11+1+3、19+12+5+6、20+2+5。
- 一次分离都没完成（含缺文件、JSON 无法解析、第一步就碰撞）记 0 分。

部分分最高 50%，完整拆开最低 60%，拆完一定比没拆完分高。分项保留两位小数，总分用未舍入的分项求和后保留两位小数。

计步按题面规则：同一组零件沿同一轴、同一方向连续移动计一步，距离不限；接着沿同方向移出到无限远合并计一步；分开后的两个组件分别计步。同形件编号按数据判定，框架也要拆开。不另按首次分离、解释文字或代码给分。

## 运行

`grade.py` 可以一次评一个或多个作答目录，目录是包含 `答案/` 的题目工作目录，输出各题是否完整合法、步数、已完成的分离数 `separations`、没拆完时的阶段比例 `partial_ratio` 和断点 `reason`、得分和总分：

```powershell
python grade.py <作答目录> --output 评分.json
```

缺失某题只影响该题。文件名略有出入时可以人工找到对应答案后再检查：把文件改成规范名后用 `grade.py` 评，核心内容按题面协议。结果文件的 items 用“第01题”至“第08题”作分项名，max 填该题分值。
