# 数字电路仿真器加速：测试数据

本目录是题目《数字电路仿真器加速》的测试数据和出题工具。3 类电路写在题面里；`performance/` 的输入和标准答案，以及题面旁材料目录中的 `grader.cpp`、`check.py` 和编译好的基线程序 `reference.exe`，作答时复制给被测模型（作答目录的 `数据\`）。正确性输入、基线源码和生成器**不能让被测模型接触**。

## 目录内容

| 路径 | 说明 |
|---|---|
| `performance/inputs/input_01.txt` – `input_09.txt` | 9 个性能输入，每个约 9 MB：3 类电路结构，每类 3 个实例 |
| `performance/expected/expected_01.txt` – `expected_09.txt` | 对应的标准答案（评测程序的标准输出），由基线算出 |
| `generator/gen_hidden.cpp` | 隐藏输入生成器 |
| `grader/grader.cpp` | 官方评测程序，与题面第五节中的代码逐字节一致 |
| `baselines/reference_solution.cpp` | 基线：出题人写的通用优化解法，每次评测重新运行，其用时 $R_i$ 是加速比的分子 |
| `correctness/inputs/`、`correctness/expected/` | 7 个正确性输入及独立参考答案，每个占本题得分的 1/7，失败一个就去掉那一份 |
| `validation.json` | 每个性能输入所属的类别，`evaluate.py` 报告用 |

所有文件都使用 LF 换行。

## 九个电路

全部满足题面第七节的规模：$I=64$，$F=8192$，$G=500000$，$O=64$，$M=4096$，$T=512$。电路规模固定，同一类的 3 个实例通过结构参数区分。第 $k$ 类占编号 $3k-2$、$3k-1$、$3k$；保留原 24 个输入中的第 1、2、3、7、8、9、16、17、18 组，按此顺序重新编号，文件内容逐字节未变。组合深度为最长的门链长度（主输入、触发器和常量的深度为 0）。

| 编号 | 结构 | 实例 | 生成参数 | 组合深度 | 占比最高的门类型 |
|---|---|---|---|---|---|
| 01 | 深链 | 输入取自最近 64 个门 | `deep 6151827736420917` | 191780 | 八种门均匀混合 |
| 02 | 深链 | 输入取自最近 12 个门 | `deep 2759812512721406 12` | 302859 | 八种门均匀混合 |
| 03 | 深链 | 输入取自最近 600 个门 | `deep 4568780409149191 600` | 89112 | 八种门均匀混合 |
| 04 | 阵列乘法器 | 16×16 位 | `multiplier 7302619945813557` | 11484 | AND 46.6%，XOR 33.0% |
| 05 | 阵列乘法器 | 8×8 位 | `multiplier 8632251898087916 8` | 5370 | AND 46.9%，XOR 33.1% |
| 06 | 阵列乘法器 | 32×32 位 | `multiplier 2679306875770113 32` | 9742 | AND 46.5%，XOR 33.0% |
| 07 | 寄存器堆 | 128 个 32 位寄存器，16 个写口 | `regfile 1278460039915783` | 9280 | MUX 67.6% |
| 08 | 寄存器堆 | 64 个 64 位寄存器，8 个写口 | `regfile 2162772007449421 6 8` | 12117 | MUX 61.4% |
| 09 | 寄存器堆 | 256 个 16 位寄存器，24 个写口 | `regfile 5872924447304816 8 24` | 2356 | MUX 73.3% |


各类结构与参数含义（生成器第 3 个及之后的参数；省略时取方括号中的默认值，与上一版输出逐字节相同）：

- **深链**：每个门的输入大多来自最近生成的若干个门，依赖链极长。参数为取输入的窗口大小 [64]；窗口越小，链越深。
- **阵列乘法器**：大量阵列乘法器，部分乘积再经加法器累加。参数为乘数位宽 [16]。
- **寄存器堆**：4096 个触发器组成 $2^a$ 个 $4096/2^a$ 位寄存器，64 个读口，外加胶合逻辑。参数为地址位数 $a$ [7] 和写口数 [16]。

所有电路都满足：每个门在结构上均可到达某个触发器或主输出，每个触发器都经异或折叠接到主输出。这不等于经过布尔化简后每个门都不可删除。

## 正确性输入

| 用例 | 覆盖内容 |
|---|---|
| `01_ff_forward` | 触发器按正向编号直接依赖，检查同时更新 |
| `02_ff_reverse` | 反向编号的触发器依赖，检查反向原地更新 |
| `03_direct_sources` | 常量、主输入、触发器的直接连接与直接输出、自反馈、无关门 |
| `04_shuffled_dag` | 八种门、重复输入、乱序 DAG、小规模组合与时序混合 |
| `05_shuffled_dag` | 257 组激励，覆盖向量批次与尾部处理 |
| `06_shuffled_dag` | 另一组固定随机 DAG 与不同周期数 |
| `07_fullsize_ff_snapshot` | 与性能输入同规模的双向触发器延迟链，检查大规模路径的同时更新 |

前六例由逐激励、逐周期的 Python 标量仿真器生成答案；第七例的门均为不被观察的 `NOT(0)`，输出只观察四个触发器和常量，由独立推导的周期波形计算摘要。全部可用上一级 `gen_correctness.py` 重建。

## 基线

`check.py` 使用随题提供的 `reference.exe`，在每个输入上现场交错运行基线和提交，各运行 3 次并各取中位数，给出所跑输入的平均分，注明不是总分（未检查 7 个隐藏正确性输入）。该程序由题面旁材料目录的 `grader.cpp` 和本目录的 `baselines/reference_solution.cpp` 按题面第八节的命令编译；运行时与提交一样需要 `C:\msys64\ucrt64\bin` 在 PATH 中。正式评分仍从源码重新编译基线，由 `evaluate.py` 在同一次评测中测量，不使用随题提供的程序。

- **基线**：只保留能影响输出的门；在深度优先序和按层序中选需要存储位置更少的一种，并复用已不再使用的存储位置；软件预取；AVX2 一次处理 256 组激励；门计算无分支；用 64×64 位矩阵转置生成主输入、计算摘要。
- 每个性能输入按题面锚点在 $\ln s_i$ 上分段插值，深链和阵列乘法器（输入 1–6）与基线持平得 12 分、12 倍起满分，寄存器堆（输入 7–9）与基线持平得 15 分、8 倍起满分；9 个输入等权平均后乘以 7 个正确性输入的通过比例。
- 提交在某个输入上的 $s_i\le0.1$（不到基线速度的十分之一）时，该输入得 0 分；题面第十节另规定每次运行的整个进程不超过 60 秒，`evaluate.py` 对超过 60 秒的运行判为失败。

## 评测时

在本目录的上一级运行统一工具，基线可执行文件必需：

```powershell
python evaluate.py --task circuit --exe grader.exe --reference reference.exe --report result.json
```

工具先运行提交的 7 个正确性输入（失败一个，本题得分去掉 1/7，后面照常运行）；再在每个性能输入上让基线和提交各运行 3 次（奇数输入先基线后提交，偶数输入先提交后基线，取各自中位数），按题面评分标准输出 $R_i$、$C_i$、$s_i$、各输入得分、作参考的 $G$ 和本题得分。基线本身运行失败时这次评测作废。具体说明见上一级 README。

由生成参数重新生成输入：

```
g++ -O2 -std=c++20 -march=native -o gen_hidden.exe gen_hidden.cpp
gen_hidden.exe deep 6151827736420917 > input_01.txt
gen_hidden.exe regfile 5872924447304816 8 24 > input_09.txt
```
