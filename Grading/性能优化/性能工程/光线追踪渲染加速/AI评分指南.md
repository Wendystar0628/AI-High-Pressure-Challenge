## 测量与计分

在本目录运行一次：

```
python evaluate.py --source "<提交的 solution.cu>" --output "<报告目录>"
```

- 入口用题面第七节的固定 nvcc 命令从源码分别编译提交和基线，不用作答材料中的 `reference.exe` 或预存的基线用时。编译含 `-O3 -std=c++17 -arch=sm_89` 和主机选项 `/O2 /utf-8 /Zc:preprocessor`；完整命令见题面和生成的 `compile.json`。
- 基线与提交各运行 5 次，独立进程、交错、各取最小值，按 $s=R/C$ 计算加速比。计时含本次场景的预处理、建树、分配、传输、渲染和末尾同步；每次都按题面第九节的容差判画面。12 个隐藏输入各运行 1 次，不计时；公开边界只核对、不计分。
- 速度分 $q$ 按题面锚点在 $\ln s$ 上分段插值：1、2、4、6、8、10 倍分别为 0、22、50、70、87、100 分；$s\le1$ 为 0，$s\ge10$ 为 100。
- 每次画面通过、略超差、不通过／失败／超时分别记 1、0.5、0。5 次计时判定取平均为 $c$；12 个隐藏判定取平均为 $h$。本题得分 $qch$，以 `results.json` 的 `score` 为准，使用未舍入数值计算，表中保留一位小数。公开自测不含 $h$，不能代替正式得分。
- 提交编译失败记 0 分。运行失败或超时按该次判定记 0，不直接把其他成功运行清零。基线任何一次失败或画面不通过时整次测量作废，保留 `invalid.json` 并来信说明，排除环境问题后重跑。
- 源文件名或位置的小出入从宽；接口、可用库和计算范围仍以题面为准。

## 规则核对

- 以题面第一、八、十节的约束为准，确认实质性违规的实现整题记 0，并列出源码位置和证据。不另设扣分项；仅有扫描命中不能判违规。
- 重点核对：没有少采样、换序列、复用其他像素或截断非零反射贡献；射线和像素计算确由 GPU 完成；没有现成光追库、硬件光追接口、CUDA Driver API、文件／网络／其他进程访问、预存图像、跨调用场景缓存或干扰计时、绑核、优先级的行为。给定头文件、C++ 标准库和 Toolkit 免链接头文件可用。
- 求交公式、内部精度、树、遍历、内核组织不限；按规模选实现、复用与场景无关的资源、GPU 回传少量控制信息均允许。不能把这些当作违规。
- `evaluate.py` 保存的扫描只标可疑行；需要时按 README 用 Nsight Systems 核对数据流和工作范围，再读源码认定。
