# 性能工程评测数据与工具

## 数据

- 电路题有 9 个性能输入和 7 个隐藏正确性输入。性能输入分 3 类，每类 3 个参数不同的实例，按类连续编号（`input_01`–`input_03` 为第 1 类，依此类推），类别写在题面里，输入、标准答案和编译好的基线程序 `数据\reference.exe` 作答时复制给模型。`check.py` 现场交错测量基线和提交，各运行 3 次取中位数，给出所跑输入的平均分（不是含正确性系数的总分）；正式评分仍从源码编译基线并由 `evaluate.py` 重新测量。正确性输入是 6 个小规模用例和 1 个完整规模的同步语义用例。
- 个数以 `performance/inputs` 中的实际文件为准。
- `baselines/reference_solution.*` 是基线。生成参数见各题目录的 `README.md`。
- 答案逐字节比较。

## 使用方法

按题面的编译命令，把 `grader/grader.cpp` 分别与提交、基线编译成两个可执行文件（编译失败直接记 0 分，脚本不负责编译），再在本目录用 Python 3.12 运行：

```powershell
python evaluate.py --task circuit --exe grader.exe --reference reference.exe --report result.json
```

## 一次评测会话

- 所有进程顺序运行，不同会话不能同时进行；每个进程以高优先级、亲和掩码 `0xffff` 和 `OMP_NUM_THREADS=16` 启动，超过 60 秒判为失败。
- 先跑 7 个正确性输入，记下通过个数 $k$，失败不影响后续步骤。
- 再逐个跑性能输入：基线和提交各运行 3 次，交错进行（奇数编号先跑基线，偶数编号先跑提交，每跑完一对交换先后），各取中位数记为 $R_i$、$C_i$。

## 计分

- $s_i=R_i/C_i$。提交在某个输入上答案错误、崩溃、超时或计时无效，3 次中任一次失败即算失败，该输入不再运行提交。
- 每个性能输入按 $\ln s_i$ 在题面锚点表上分段插值得 0–100 分（深链和阵列乘法器输入 1–6 与基线持平得 12 分、12 倍起满分；寄存器堆输入 7–9 与基线持平得 15 分、8 倍起满分），两端封顶，保留一位小数，失败的输入记 0 分。`performance_score` 是 9 个输入得分的平均，`score` = `performance_score` × $k/7$（用未舍入的平均计算），保留一位小数；$G$ 只作参考。
- 提交计时低于 0.001 ms 时按 0.001 ms 计；基线本身运行失败时会话作废，`score` 为 `null`，排查环境后重测。

## 报告

- `summary` 每个性能输入一行：`case`、`family`（取自 `validation.json`）、`R_i_ms`、`C_i_ms`、`s_i`、`points_i`、`status`（`PASS` 为通过）。`performance` 记每次运行的原始结果和顺序；`score`、`G` 等在顶层。

## 退出码

- 0 得分大于 0；1 记 0 分；2 会话作废。

## 重新生成正确性输入

`python gen_correctness.py` 重建电路题的正确性输入及答案，答案由脚本内独立的串行求解器算出。
