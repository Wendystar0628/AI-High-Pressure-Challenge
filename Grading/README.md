# Grading：评分资料

本目录是题集 `AI_OneShot_Bench` 的评分部分，存放评分需要的全部资料：标准答案、隐藏测试数据、基线、评测脚本和各题的 AI 评分指南。受测模型作答期间不能接触本目录：给受测模型复制题面时不要带上本目录，也不要把它的路径告诉受测模型。

## 目录结构

目录与题集一一对应，题集中的每道题在这里都有一个同名文件夹，里面都有一份 `AI评分指南.md`；标准评判题只有 `评分表_6.1Sol.md`，主动设计题另有 `评分表_Opus5.5.md`（下面的目录树中省略）。

## 题目文件夹里的文件

| 文件 | 内容 |
|---|---|
| `AI评分指南.md` | 评分要点（在题面评分标准的基础上稍作扩充）、要看的材料、输出的内容 |
| `评分表_Opus5.5.md`、`评分表_6.1Sol.md` | 按题型配置的空白评分表（标准评判题只用 Sol，设计题主体用两位），记录分项得分：列出各分项的评分要点和本题的计分公式，留出得分、总分和一段 50 字左右的简评（锐评，不端水，一针见血地指出本题结果中最有说明价值的内容）。分项理由写在评分结果里。评分开始时复制到受测模型的作答目录，由评分员填写 |
| `参考答案.md` | 两道证明题的出处与解答：形式化证明题附纸面证明思路，完整的 Lean 参考证明在 `参考证明/`；数学竞赛原创试题附标准解答和每题的 7 分评分要点；鲁班锁拆解附题源、分档依据和参考路线的步数；工程图纸三维还原附新二十五题零件说明、尺寸完整性及逐张核对结论 |
| `check.py`、`grade.py` | 鲁班锁拆解：检查整棵拆解树是否合法、完整拆开并计步，没拆完时报告从初态起合法完成的分离；`grade.py` 一次评一个或多个作答目录，按基准步数和参考解阶段步数算分 |
| `标准解答/`、`references.json`、`test_grading.py` | 鲁班锁拆解：八题的参考路线；每题的题源、档次、分值、参考步数、基准步数 B（`best_moves`，取参考步数）和参考解各阶段步数（`reference_stage_moves`）；评分脚本的测试 |
| `参考答案/`、`grade.py`、`references.json` | 工程图纸三维还原：二十五题参考零件的建模描述；`grade.py` 把作答描述生成实体，与参考零件比较表面吻合度 F 并算分；各题档次、分值和计分参数。出图程序、出图规格、私有图纸几何与出题端比对工具、回放数据导出和测试见该目录的 `README.md` |

性能题另有性能输入和标准答案（作答时复制给模型）、基线和输入生成器，电路题还有 7 个隐藏的正确性输入，深链和阵列乘法器输入 1–6 每个 12 倍起满分，寄存器堆输入 7–9 每个 8 倍起满分，9 个输入按对数锚点单独计分、等权平均后乘以正确性通过比例，说明见 `性能优化/性能工程/README.md` 和各题目录下的 `README.md`。攻城略地有五档基线、96个隐藏种子、循环赛拟合实力值的 `baselines.json`、以及在0–15同时跑8局、共480局的 `evaluate.py`；每图一局，按种子顺序奇数图提交为甲、偶数图为乙。五档对应0/20/40/60/80分，比最强档高200实力值才100分。单招测试程序仅用于开发，不参与计分；公开结算引擎、主程序、地图生成器、本地对局工具、示例及陪练在 `算法对抗/攻城略地/`，本地arena仍每图换边两局。

## 评分分工

- 评分版本：一律评作答结束时工作目录中的内容，不看 git 提交。
- 作答目录不建立 Git 仓库；评分直接读取或复制工作目录中的文件。

- 评分 AI 是 Claude Opus 5.5 和 GPT 6.1 Sol，从管理员账户的 Claude Code 和 Codex 发起，用管理员账户自己的登录；不是从受测模型运行所用的普通账户发起，那个账户读不到本目录。推理强度：评数学竞赛原创试题和形式化证明题用 `xhigh`，其余（含设计题、鲁班锁、工程图纸三维还原、攻城略地和全部性能部分）用 `high`。
- 评分 AI 按各题的 `AI评分指南.md` 打分，主观部分由它自行判断，分数可以打小数（保留一位小数）；评分时能看到模型代号。
- 评分时打开网页、测试交互功能，一律用本机的无窗口（headless）Chrome，禁止占用出题人的电脑桌面：不开有窗口的浏览器等桌面程序，不用控制或截取桌面的工具。操作系统嵌套是桌面项目，只开作品自身的窗口，通过调试端口操作和截图。
- 评分员的具体步骤和可用工具（Chrome 的启动参数与驱动方式、本地网页服务器、系统读数、ffmpeg、Lean、各题脚本）写在评分员提示词 `orchestrator\grader-prompt.txt` 里，每次评分随任务下发。
- 六道主动设计题主体由 Claude Opus 5.5 和 GPT 6.1 Sol 独立评分；数学推理、性能优化、算法对抗、空间推理、识图建模的七道标准评判题整题及所有性能部分只由 Sol 评分。评分 AI 只给出本人负责的一份。
- 共 19 对题目与评分员、19 个会话。主体共 16 个会话并行评分（设计题 6×2，加形式化、数学竞赛、鲁班锁、工程图纸三维还原各 1 个 Sol 会话）；全部结束后，性能共 3 个 Sol 会话按题目表顺序独占机器串行评分：光线追踪、电路、攻城略地整题排入性能队列，得分由各自的 `evaluate.py` 按题面公式计算（攻城略地跑 480 局对局，按冻结的基线实力值换算）。物理整题 4 个方向、24 个分项由两位评分员各一次评完。
- 鲁班锁拆解按指南的步数公式计分：完整拆开的每题 w × max(0.6, min(1, B/N))，w 为 8、12 或 18，N 为合法完整路线的步数，B 是每题固定的基准步数，取参考解的完整步数（8、10、14、12、14、15、42、27）；没拆完的从初态起按 `check.py` 的深度优先顺序检查到第一处断点，合法完成 k 次分离，得 w × 0.5 × S_k/S_total，S 为参考解各阶段步数，每完成一次分离都加分；一次分离都没完成记 0 分。
- 工程图纸三维还原25题，01—08各3.5分、09—15各4分、16—25各4.4分，总分100。 每档先按作答面积P、参考面等权R求F；0.2mm先求整题平移，2mm沿用。F综合=0.8F(0.2mm)+0.2F(2mm)，每题w×min(1,F综合/0.99)，宽档只占20%。 装配各档汇总全部面积与参考面，缺件面记0，不平均零件F；显示整理JSON目录允许，计算尺寸/几何和批量预览禁止。
- 题面“规定”一节的执行情况不在评分范围内，由出题人处理；鲁班锁拆解和工程图纸三维还原例外：评分员先读会话记录，鲁班锁自编程序搜索、模拟、算碰撞，用求解器或改动题目工具的，工程图纸三维还原自编程序解析图纸、算几何、重建或比对形状，用 CAD 软件或几何内核，批量调用或改动题目工具的，作答记 0 分。

## 计分与总分

- 每道题都折算为 0–100 分：原始分 ÷ 满分 × 100。例如数学竞赛原创试题满分 168（24 题各 7 分），按 ×100/168 折算；其余各题满分都是 100。
- 标准评判题直接采用 Sol 的折算分。设计题各分项取有效评分员的平均，只有一位有效时用该位，相加后折算为 0–100 分。设计题各分项由评分员在分值内直接打分，要根据这一点完成的质量考虑，满分代表你认为这一点质量优秀，相加为总分，不扣分。
- 偶发故障按段最多重试一次；设计题主体一位失败时依另一位。单评分员的段重试仍失败，该段没有分数，列入“评分失败”缺口；缺少必需段的题没有本题得分，不按剩余分项放大，模型汇总暂按 0 分计。
- 模型总分是各题得分的加权平均，十个类别各占 10 分，类别内各题平分，权重如下：

| 类别 | 类别权重 | 题目与权重 |
|---|---|---|
| 数学推理 | 10% | 形式化证明题 5%，数学竞赛原创试题 5% |
| 性能优化 | 10% | 光线追踪渲染加速、数字电路仿真器加速，各 5% |
| 算法对抗 | 10% | 攻城略地 10% |
| 空间推理 | 10% | 鲁班锁拆解 10% |
| 识图建模 | 10% | 工程图纸三维还原 10% |
| 复杂交互应用 | 10% | AE风味动效设计编辑器 10% |
| 游戏设计与开发 | 10% | 动态路由塔防 10% |
| 物理模拟 | 10% | 果冻冲击与造浪水槽 10% |
| 视觉设计与渲染 | 10% | 太阳雨渔港3D渲染 5%，星际战舰编队 5% |
| 系统架构与实现 | 10% | 操作系统嵌套 10% |
