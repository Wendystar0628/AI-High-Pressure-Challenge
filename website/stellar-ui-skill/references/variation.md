# 变体：哪些不能变，哪些应该变

同一个 skill 会被很多人拿去做很多产品。目标是：**一眼认得出是这套风格，但看得出是不同的产品**。做法是把"固定规则"和"外观"分开：固定规则每个产品都一样，外观按产品定一次，然后整套界面统一用它。

`stellar.css` 和 `assets/tokens.json` 的 `variant` 都按这一篇来。样张：`examples/web/variants-showcase.jpg`、`examples/web/variants-console.jpg`（同一个页面，四组预设）。

## 不能变的：固定规则

| 规则 | 为什么 |
| --- | --- |
| 淡紫灰的纸加夜空色的墨，浅色为主；深色是另一套完整主题 | 观测笔记的底子 |
| **两种主题色固定**：紫 `#9859FF` 只表示当前位置，荧光绿 `#D1FF57` 只表示可以按、要看一眼 | 颜色少、各管一件事，才有意义；换掉它们就不是这套风格 |
| 紫色做线、色条、括弧和大字，不做小字的底；荧光绿只做填充，上面写墨字 | 紫在白底上 4.03:1，荧光绿 1.16:1（见 `tokens.md`） |
| 红色只给删除 | 告警用荧光绿和墨线，红色一出现就是不可撤销 |
| 切掉一个小角 = 可以按；不可点的东西是直角；圆角一律为 0 | 形状本身就是交互提示 |
| 宽体大写英文小字配粗体中文，`//` 眉标 | 像观测记录一样有编号、有层级 |
| 编号、日期、计数都是真实字段，用宽体等宽数字排 | 不编造技术感 |
| 细线分区，不堆卡片；不用投影、发光、渐变 | 星图式的克制 |
| 底纹只在两角、极淡、永远在内容下面 | 质感，不是背景图 |
| 动效短、硬、机械，三条曲线三档时长；"减少动态效果"时全部关闭 | 仪器的手感 |

## 应该变的：五个维度

每个产品在开工前把下面五项各定一个值。在 `<html>` 上写 `data-st-*` 属性，或者用 `assets/variant.js` 从地址读。

| 维度 | 选项 | 写法 | 约束 |
| --- | --- | --- | --- |
| **纸色** paper | `neutral`（默认，淡紫灰）、`cool` 偏蓝灰、`dusk` 偏暮色粉紫 | `data-st-paper` | 只微调纸、板、细线和浅填充；墨色、次要文字和两种主题色不变。三种纸色下所有文字组合都在 5.3:1 以上，紫色当线都在 3.5:1 以上（浅色）、4.6:1 以上（深色） |
| **切角** cut | `tight`（×0.6）、`standard`、`wide`（×1.6） | `data-st-cut`，背后是 `--st-cut-k` | 所有切角一起缩放，含义不变；切角旁的留白跟着缩放（标签、筛选块、按钮、导航项的右侧内边距都是固定值加切角），字永远不压进切角 |
| **底纹** ground | `stars` 星图（默认）、`chart` 星图圆弧、`hatch` 斜线纹、`plain` 无 | `data-st-ground`（`<body>` 上要有 `.st-stars`） | 都极淡；也可以用 `assets/stars/draw-stars.mjs` 换种子，画出自己的一片星空 |
| **密度** density | `compact`、`standard`、`roomy` | `data-st-density`（整体缩放 0.94 / 1 / 1.06） | 可点区域仍然不小于 32px |
| **动效** motion | `full`（默认）、`calm` | `data-st-motion` | `calm` 去掉打开页面时的入场，保留回应操作和进出；给整天在用的工具 |

各纸色的对比度（墨 / 次要墨在纸上，紫在纸上）：

| | neutral | cool | dusk |
| --- | --- | --- | --- |
| 浅色：墨在纸上 | 15.65:1 | 15.53:1 | 15.48:1 |
| 浅色：次要墨在浅填充上（最低的一组） | 5.38:1 | 5.36:1 | 5.35:1 |
| 浅色：紫在纸上 | 3.59:1 | 3.56:1 | 3.55:1 |
| 深色：墨在纸上 | 15.83:1 | 15.73:1 | 15.80:1 |
| 深色：紫在板上 | 4.33:1 | 4.27:1 | 4.31:1 |

自己调纸色时照这张表算一遍：文字组合不低于 4.5:1，紫色当线不低于 3:1。

**还有两样不在属性里，但最能拉开差别：**

- **主视觉**。首屏和控制台中间放什么，要从产品自己的内容里来：观测类产品放自己的星图或器材照片，课程产品放课表的大编号，个人站放自己的字标。星盘只在数据本来就分成几块时才用。模板里的 LYRA 字标和行星仪线稿只是占位。
- **字体**。拉丁字体可以换成别的宽体几何字体（Exo 2、Chakra Petch；Michroma 只做标题），中文可以换成别的能做粗字重的黑体（思源黑体、HarmonyOS Sans SC、MiSans，注意各自的许可证）。一个产品只用一种拉丁字体，宽度照 `tokens.md` 的规定拉开。

## 四组预设

拿不准时从预设里挑一组，再按需改一两项。用 `data-st-variant` 或地址里的 `?variant=`。

| 预设 | 适合 | 纸 | 切角 | 底纹 | 密度 | 动效 |
| --- | --- | --- | --- | --- | --- | --- |
| `zenith` 天顶 | 个人站、内容站、作品集 | neutral | standard | stars | standard | full |
| `observatory` 观测站 | 数据、监控、科研工具，冷静精确 | cool | tight | chart | standard | calm |
| `nebula` 星云 | 活动页、创作类产品，舒展一些 | dusk | wide | stars | roomy | full |
| `midnight` 子夜 | 运维、长时间盯屏，默认深色 | neutral | standard | plain | compact | calm |

`assets/tokens.json` 的 `variant.presets` 是同一张表。

## 怎么定、写在哪

1. 先看产品是做什么的、谁在用、在什么环境下用，从预设里挑一组，或者逐项定值。
2. 把结果写成一张"变体卡"，放在交付说明的最前面（也可以写成 `<html>` 上的属性注释），让后来改界面的人照着做：

   ```text
   变体：观测站（cool / tight / chart / standard / calm）
   主视觉：本季观测目标的星图，目标编号来自真实清单
   页面类型：首页展示，其余阅读，后台控制台
   ```

3. 只在一个地方设置：写在 `<html>` 上。不要在单个部件上各写各的颜色。

## 不要照抄模板

`templates/` 是部件怎么写、怎么组合的参考，不是版式。

- 版式由内容决定：先列出这一页要回答的问题和要放的真实数据，再选部件，最后排位置。
- 模板里的占位全部换掉：LYRA 字标、行星仪线稿、"示例"文案、虚构的编号和数字。
- 控制台的星盘、展示页的超大字标都是"可以用"，不是"必须有"。
- 交付前对照最接近的模板，至少说得出三处为这个产品做的不同：主视觉、版式、部件组合或变体。

## 新部件怎么推

套件里没有的部件，按下面的顺序从固定规则里推出来，不要另起一套样式：

1. **它表示什么状态？** 当前、选中、进行到哪：淡紫底加紫条，或者一条紫线。能按、要看一眼：荧光绿填充加墨字。完成：墨色实心。空闲：浅填充 `chip`。删除才用红。
2. **能不能按？** 能按的切一个小角，大小用 `--st-cut`；不能按的是直角。切角那一侧的内边距写成 `calc(固定值 + var(--st-cut))`，`wide` 下字也不碰切角。
3. **有没有编号、日期、计数？** 有就用宽体字段排出来，和中文标签成对。
4. **边界在哪里？** 用 1px 细线；标出当前位置的线用 `--st-orbit`。引线、分隔线的端点用星点（7px 小圆）。
5. **怎么动？** 从三条曲线和三档时长里挑：移动用 mech 280ms，出现用 snap，退出约为进入的 2/3。
6. **检查一遍**：深色主题、减少动效、键盘焦点、读屏能读出当前项，四组预设下都成立。

例子：一个**步骤条**。每一步是一格，格里写宽体编号 `01`、`02` 和中文步骤名。当前步用淡紫底，底边一条 3px 紫条，字加粗；已完成的步用墨色实心、编号反白；没到的步用 `chip`。能回去的步切一个小角，不能点的是直角。步与步之间连一条 1px 细线，已走过的一段画成紫线，每个节点是一个星点。前进时紫条移到下一格，280ms mech。当前步加 `aria-current="step"`。

推不出来时，先问"它表示什么状态"，再到 `SKILL.md` 的部件速查里找含义相同的部件，借它的形状。
