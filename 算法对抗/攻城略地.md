# 题目

## 目标总览

本题是算法对抗题：用 C++ 写一个双人对战程序。双方在一张平面地图上争夺节点，每回合同时从己方节点向其他节点派兵，兵力随占有的节点增长。你的程序与出题方准备的五档对手在隐藏地图上对战，按全部对局的胜负估出实力值。目标是明显强于最强一档对手：与它实力相当得80分，比它高200实力值得满分，详见第十一节。

战胜示例程序和两个陪练不等于完成：正式对手中最强的一档强于强陪练，满分还要明显强于这一档，须继续提高程序的实力、向目标推进。设计的重心是寻找启发式算法：把功夫下在设计和尝试不同的启发式算法上，用对局比较哪一种确实更强；与启发式算法适配的搜索是辅助。不要只在同一套算法上反复调参数。觉得没什么可改了，就换一个思路再试。

## 一、游戏规则

**节点**：地图上有 $N$ 个节点，编号 $0,\ldots,N-1$。节点 $i$ 有整数坐标 $(x_i,y_i)$、归属、兵力和增长率。归属为中立、甲方或乙方之一；兵力是非负整数；增长率是正整数，整局不变。节点的位置和数量整局不变。

**路程**：节点 $i$ 到节点 $j$ 的路程 $d(i,j)$ 是两点直线距离向上取整，即满足 $d^2\ge(x_i-x_j)^2+(y_i-y_j)^2$ 的最小非负整数 $d$。

**部队**：派出的兵组成一支部队，记录归属、兵力、出发节点、目标节点和剩余路程。部队出发后不能改变目标，不能停下，也不能与其他部队合并；路上的部队之间不交战。

**回合**：一局最多 200 个回合，编号 $1,\ldots,200$。每个回合开始时，双方各自拿到当前局面，同时给出本回合的命令列表；一方的命令不影响另一方本回合看到的局面。每条命令写明“从哪个节点、派多少兵、去哪个节点”。随后按下面三步依次结算：

1. **出发**：按第二节处理双方的命令。每条有效命令从出发节点减去派出的兵力，生成一支部队，剩余路程为两节点的路程 $d$。
2. **推进**：所有路上的部队（含本回合刚出发的）剩余路程减 1。属于甲方或乙方的节点兵力加上各自的增长率；中立节点不增长。
3. **到达结算**：剩余路程变为 0 的部队到达目标节点。对每个有部队到达的节点，把节点上原有的兵力和所有到达的部队按归属分组求和，节点原归属的一方计入节点上的兵力（为 0 也算参与）：
   - 兵力和最多的一方占有这个节点，节点兵力变为最多减去第二多；只有一方参与时，节点兵力就是这一方的兵力和。
   - 最多的两方兵力和相等时，节点归属不变（即使原归属方不在这两方之中），兵力变为 0。
   - 到达己方节点的部队就是增援：同一方的兵力合在一起计算，结果等于相加。

因此，第 $t$ 回合派出、路程为 $d$ 的部队，在第 $t+d-1$ 回合的到达结算中到达，第 $t+d$ 回合开始时的局面里已经计入。

**胜负**：每回合到达结算之后判定：

- 一方既没有节点、也没有路上的部队时，这一方被消灭，另一方获胜，对局立即停止。双方在同一回合同时被消灭为平局。
- 第 200 回合结算完仍未分出胜负时，比较双方总兵力（己方所有节点上的兵力加上己方所有路上部队的兵力），多者胜，相等为平局。

节点兵力为 0 但仍有归属时，这一方没有失去这个节点。

**视角**：双方程序都把自己看成同一号玩家。程序拿到的局面中，归属 1 表示自己，2 表示对手，0 表示中立；节点编号对双方相同。

**地图**：

- $N$ 为 16 到 24 之间的偶数。
- 地图关于原点中心对称：节点 $2k+1$ 是节点 $2k$ 关于原点的对称点，坐标为 $(-x_{2k},-y_{2k})$，初始兵力和增长率相同，初始归属对调（中立仍为中立）。
- 甲方的起始节点是节点 0，乙方的起始节点是节点 1，各有初始兵力 100、增长率 5。其余节点初始为中立，初始兵力 5–60，增长率 1–5。
- 所有节点的坐标满足 $|x|,|y|\le10$，到原点的距离不超过 10；任意两个不同节点之间的路程在 2 到 20 之间。

## 二、命令的处理

一条命令是三元组 $(\mathit{from},\mathit{to},\mathit{troops})$。出发阶段先处理甲方的命令，再处理乙方的命令；双方只能从己方节点派兵，所以先后顺序不影响结果。同一方的命令按列表顺序逐条处理，每条都以处理到它时的局面检查。下列情形的命令无效，只丢弃这一条，其余命令照常处理：

- $\mathit{from}$ 或 $\mathit{to}$ 不是合法的节点编号；
- $\mathit{from}$ 不是本方节点；
- $\mathit{to}=\mathit{from}$；
- $\mathit{troops}\le0$；
- $\mathit{troops}$ 大于 $\mathit{from}$ 当前的兵力。这里的当前兵力已经扣除了本回合排在前面的命令从该节点派出的兵；整条丢弃，不按现有兵力截断。

其他情形都有效：

- 同一回合可以从同一节点发出多条命令，也可以向同一目标发出多条命令，每条有效命令各自生成一支部队。
- 可以派出节点上的全部兵力；节点兵力变为 0，归属不变。
- 目标可以是任意节点，包括己方节点。

每回合最多处理列表中的前 1000 条命令，其余丢弃。

## 三、接口

提交的 `bot.cpp` 中实现函数 `decide()`。下面的结构体由 `数据\engine.hpp` 定义，`bot.cpp` 用 `#include "engine.hpp"` 引用，不要自己重新定义：

```cpp
#include <vector>

struct Node {
    int x, y;     // 坐标
    int owner;    // 0 中立，1 自己，2 对手
    int troops;   // 当前兵力
    int growth;   // 增长率
};

struct Fleet {
    int owner;       // 1 自己，2 对手
    int troops;      // 兵力
    int from, to;    // 出发节点和目标节点的编号
    int turns_left;  // 剩余路程：为 k 时，在本回合起的第 k 个回合（本回合为第 1 个）的到达结算中到达
};

struct State {
    int turn;                            // 当前回合，1–200
    int max_turns;                       // 回合上限，200
    std::vector<Node> nodes;             // 下标即节点编号
    std::vector<Fleet> fleets;           // 路上的全部部队
    std::vector<std::vector<int>> dist;  // dist[i][j] 为节点 i 到节点 j 的路程
};

struct Order {
    int from, to, troops;
};

std::vector<Order> decide(const State& s);
```

- 每个回合开始时，主程序调用一次 `decide()`，传入本回合开始时的局面，返回本回合的命令列表，可以为空。
- 每局对局启动一个新的程序进程，整局常驻，直到对局停止。全局变量和静态变量在回合之间保留，可以用来保存跨回合的信息，例如对手前面的行为。
- `engine.hpp` 与裁判使用的是同一份结算代码，除上面的结构体外还提供：
  - `int distance(int x1, int y1, int x2, int y2)`：按第一节计算路程；
  - `State step(const State& s, const std::vector<Order>& mine, const std::vector<Order>& theirs)`：以 `s` 的视角结算一整个回合（`mine` 是归属 1 一方的命令，`theirs` 是归属 2 一方的命令），返回下一回合开始时的局面，`turn` 加 1；
  - `State flip(const State& s)`：交换局面中的归属 1 和 2，得到对手视角的局面；
  - `int result(const State& s)`：判定局面，0 为未分胜负，1 为自己胜，2 为对手胜，3 为平局。

## 四、给出的材料

作答目录的 `数据\` 文件夹里有下面这些文件：

- `engine.hpp`：结算引擎，即第三节所说的头文件。
- `main.cpp`：主程序，负责和裁判通信、调用 `decide()`。评测用的就是这一份。
- `mapgen.py`：地图生成器，按给定的种子生成一张符合第一节的地图。
- `arena.py`：本地对局工具，让两个编译好的程序在指定地图上对战，每张地图换边各打一局，输出每局的胜负、回合数、双方的总兵力和每回合用时的最大值，并可以保存逐回合日志。
- `使用说明.md`：`arena.py` 的用法，包括同时打多局、保存日志和指定处理器的参数。
- `referee_core.py`、`winproc.py`、`engine_bridge.cpp`：`arena.py` 的配套文件，和它放在同一文件夹，不需要改动。
- `日志格式说明.md`：逐回合日志的格式。日志记录了一局中每个回合双方的命令、结算过程和结算后的局面。
- `sample_bot.cpp`：一个示例程序，可以用来熟悉接口，也可以编译后当作练习对手。
- `sparring_weak.exe`、`sparring_strong.exe`：两个编译好的陪练程序，由另一套代码实现。弱陪练的实力约等于正式对手的第 2 档，强陪练介于第 4 档和第 5 档之间。正式对手的打法与它们不同。

正式评分的对手程序和地图种子不公开。评分地图由同一个地图生成器用不公开的随机种子生成，生成规则与你拿到的生成器完全相同。

用第五节的命令编译出 `bot.exe` 和示例程序后，可以这样对局：

```
python 数据\arena.py .\bot.exe .\sample_bot.exe --seeds 1-20
python 数据\arena.py .\bot.exe 数据\sparring_strong.exe --seeds 1-20
```

练习对局请在性能核（逻辑处理器 0–15）上进行，`--cpus` 只在 0–15 里选；能效核（16–27）上同样的程序耗时更长，和正式评分不一致。

## 六、时限

- 每回合从主程序收到局面到交出命令，程序进程消耗的 CPU 时间（用户态加内核态）不超过 50 毫秒；第 1 回合不超过 1 秒，包括进程启动和全局初始化。
- 某回合超时，这一回合视为没有下命令，之后才交出的命令一律丢弃，对局照常继续。
- 超出的 CPU 时间记到下一回合：某回合用了 80 毫秒，超出 30 毫秒，下一回合可用的只剩 20 毫秒；欠下的时间一直顺延扣除，直到扣完。
- 连续 3 个回合超时，这一局判负。
- 程序崩溃、异常退出，或某回合 5 秒墙钟时间内没有交出命令，这一局判负。
- 双方在同一回合都被判负时，这一局记平局。
- 非法命令按第二节只丢弃那一条。
- 整个进程的内存不超过 1 GB。

## 十一、评分标准

评分对提交格式很宽容，格式上的小出入不用担心；但评测必需的内容仍按题面：`bot.cpp` 能用第五节的命令与主程序一起编译，`decide()` 的接口与第三节一致，并遵守第八节的规则。

满分 100 分，按实力值计分，实力值用 Elo 尺度：实力强 10 倍记高 400。

**对手的实力值**：开测前，五档对手在同样的96张地图上两两循环对打，每对在每张地图上各打一局；按地图编号轮换座位，奇数张图较低档为甲方，偶数张图较低档为乙方。用Bradley–Terry模型拟合出各自的实力值 $R_1<R_2<R_3<R_4<R_5$，冻结后对所有提交不变。具体数值由出题端冻结，在评分材料中给出。

**你的实力值**：设你的程序在 480 局中的第 $j$ 局对手实力值为 $R_{(j)}$、得分为 $s_j$（胜 1、平 0.5、负 0）。实力值为 $r$ 时，这一局的预期得分为

$$
E_j(r)=\frac{1}{1+10^{(R_{(j)}-r)/400}}
$$

取使预期总得分等于实际总得分的 $r$，即最大似然估计：

$$
\sum_{j=1}^{480}E_j(r)=\sum_{j=1}^{480}s_j
$$

$r$ 限制在 $[R_1-200,\ R_5+200]$ 内，全胜或全负时取相应的边界。

**换算成分数**：实力值等于 $R_1-200$、$R_1$、$R_2$、$R_3$、$R_4$、$R_5$、$R_5+200$ 时分别得0、10、20、40、60、80、100分，相邻两点之间按实力值线性插值。$r\le R_1-200$ 时得0分，$r\ge R_5+200$ 时得100分。本题得分保留一位小数。与最强一档实力相当得80分，比它高200实力值才得满分。

需要结束进程时，只按 PID 结束你在本会话中启动的进程；不得结束其他进程，不按进程名批量结束。
