# 逐回合日志的格式

`arena.py` 加 `--log-dir <目录>` 后，每局保存一个 UTF-8 的 `.jsonl` 文件：每行一个完整的 JSON 对象，依次是一个 `header`、若干个 `turn`、一个 `result`。兵力、坐标、回合、节点编号都是整数，毫秒数可以是小数。没有 `result` 结尾的文件说明这一局被中途打断。

## 视角、节点、部队和局面

整个日志固定用甲方视角：`owner` 为 0 是中立，1 是甲方，2 是乙方。节点编号对双方相同。（程序自己收到的局面里 1 永远是自己，日志里不是这样。）

- 节点：`{"x":8,"y":0,"owner":1,"troops":100,"growth":5}`。`nodes` 数组的下标就是节点编号。
- 部队：`{"owner":1,"troops":50,"from":0,"to":2,"turns_left":3,"total_distance":5,"id":"t1-p1-o0"}`。`turns_left` 是剩余路程，`total_distance` 是起终点之间的总路程。`id` 整局唯一，形如 `t<出发回合>-p<归属>-o<命令在列表中的下标，从 0 起>`。
- 局面：`{"turn":1,"max_turns":200,"nodes":[...],"fleets":[...]}`。`turn` 是即将执行的回合，所以第 t 回合结算后的局面里 `turn` 是 t+1。`fleets` 只含还没到达的部队。

## header

| 字段 | 含义 |
|---|---|
| `type` | 固定为 `header` |
| `schema` | `siege-replay-v1` |
| `seed`、`map_generator` | 地图种子和生成器版本 |
| `name` | 调用时给的对局名称，默认为空 |
| `players` | 两个对象，按甲、乙顺序：`seat` 为 1 或 2，`label` 是程序身份 A 或 B，`display_name` 是显示名（`--name-a`、`--name-b` 设置，默认是可执行文件名），`executable` 是程序路径，`cpu` 是绑定的逻辑处理器编号，`cycles_per_ms` 是本局用来把处理器周期数换算成毫秒的系数 |
| `rules` | 本局使用的限制：`max_turns`、`first_cpu_ms`、`cpu_ms`、`wall_ms`、`memory_bytes`、`command_limit`、`cpu_time_scale`（CPU 预算的倍率，默认 1）、`simultaneous_forfeit`（值为 `draw`：同一回合双方都被判负时记平局） |
| `initial_state` | 完整的初始局面 |

## turn

`turn` 是本回合的回合号。`players` 数组按甲、乙顺序，每项有：

| 字段 | 含义 |
|---|---|
| `commands` | 程序交出的完整命令列表，每条是 `[from,to,troops]`，保持原顺序，包括无效的命令 |
| `applied` | 交给引擎逐条检查的列表。这一方 CPU 超时或被判负时为空，否则等于 `commands` |
| `discard_all` | `null` 表示没有整回合作废；`cpu_timeout` 表示因 CPU 超时整回合作废；其他值是这一方被判负的原因 |
| `timing` | 用时和判罚，见下表 |

`timing` 的主要字段：

| 字段 | 含义 |
|---|---|
| `cpu_ms` | 本回合计入的 CPU 用时。第 1 回合包括进程启动和全局初始化；之后每回合从上一次交出命令时算起 |
| `wall_ms` | 从发出局面到收到完整命令的墙钟时间 |
| `nominal_budget_ms` | 本回合的 CPU 预算：第 1 回合 1000，其余 50 |
| `debt_before_ms`、`available_ms`、`debt_after_ms` | 回合开始时欠下的时间、本回合实际可用的时间、回合结束后仍欠的时间 |
| `cpu_timeout` | 本回合是否 CPU 超时（原欠时加本次用时超过预算）。超时则本回合全部命令作废 |
| `consecutive_timeouts` | 连续 CPU 超时的回合数，达到 3 判负 |
| `failure` | `null`，或判负原因：`three_cpu_timeouts`、`wall_timeout`、`process_exit`、`memory_limit`、`protocol_error` |
| `exit_code`、`detail` | 进程退出码和出错说明，没有时为 `null` 或不出现 |

其余字段（`cpu_cycles`、`delta_cycles`、`process_setup_wall_ms`、`process_creation_wall_ms`、`memory_limit_bytes`）是计时的原始数据和进程启动耗时，不影响胜负判定。

`settled` 为 `true` 的回合按出发、推进和增长、到达三个阶段记录了全部结算过程：

1. `orders`：甲方的命令在前、乙方在后，各自保持原顺序。每项形如 `{"owner":1,"index":0,"order":[0,2,50],"reason":"accepted","fleet_id":"t1-p1-o0"}`。命令被丢弃时 `fleet_id` 为 `null`。`reason` 的取值见下表。
2. `departures`：有效命令生成的部队，此时 `turns_left` 等于总路程。
3. `movement`：每支在途部队一项，形如 `{"id":"...","before":3,"after":2,"arrived":false}`。`after` 为 0 的部队在本回合到达。
4. `growth`：每个非中立节点一项，形如 `{"node":0,"owner":1,"troops_added":5}`。
5. `arrivals`：按目标节点编号从小到大，每个有部队到达的节点一项，见下文。
6. `state`：本回合结算完成后的完整局面。

`settled` 为 `false` 表示这一回合因为判负而终止，没有结算，上面的事件数组都为空，`state` 是上一回合结算后的局面。

命令的 `reason`：

| 值 | 含义 |
|---|---|
| `accepted` | 有效，生成了部队 |
| `command_limit` | 这一方的第 1001 条及以后的命令 |
| `invalid_node` | `from` 或 `to` 不是合法的节点编号 |
| `not_owned` | 出发节点不属于下令的一方 |
| `same_node` | 起点和终点相同 |
| `nonpositive` | 派兵数不大于 0 |
| `insufficient` | 派兵数超过处理到这条命令时出发节点剩余的兵力 |

一条命令同时违反多条时，按上表的顺序记第一个原因。

到达对象的例子（三方兵力里 30 最多、20 第二，所以甲方占有，剩 10）：

```json
{"node":2,"old_owner":0,"old_troops":10,"sums":[10,30,20],"participates":[true,true,true],"fleets":[{"id":"t4-p1-o0","owner":1,"troops":30,"from":0,"to":2,"turns_left":0,"total_distance":4},{"id":"t3-p2-o1","owner":2,"troops":20,"from":1,"to":2,"turns_left":0,"total_distance":5}],"owner":1,"troops":10,"tie":false}
```

`old_owner`、`old_troops` 是到达之前（出发已扣兵、增长已加兵）的归属和兵力。`sums` 和 `participates` 是长度为 3 的数组，下标 0、1、2 分别是中立、甲方、乙方的兵力和、是否参与。`fleets` 是这次到达的全部部队。`owner`、`troops` 是结算后的归属和兵力。`tie` 为 `true` 表示最多的两方兵力相等，节点归属不变、兵力为 0。

## result

| 字段 | 含义 |
|---|---|
| `type` | 固定为 `result` |
| `seed`、`name`、`labels`、`display_names` | 本局的种子、名称，甲、乙的程序身份和显示名 |
| `winner` | 1 甲方胜，2 乙方胜，3 平局 |
| `winner_label` | 获胜程序的身份 A 或 B，平局为 `null` |
| `score` | 甲、乙的得分：`[1,0]`、`[0,1]` 或 `[0.5,0.5]` |
| `reason` | `elimination`（一方被消灭）、`turn_limit`（打满 200 回合比总兵力）、`forfeit`（因判负终止） |
| `turns` | 已完成结算的回合数 |
| `failure_turn` | 判负发生的回合，没有则为 `null` |
| `totals` | 甲、乙的总兵力（各自节点上的兵力加各自在途部队的兵力） |
| `max_turn_cpu_ms` | 甲、乙每回合 CPU 用时的最大值，包括第 1 回合 |
| `cpu_timeouts` | 甲、乙的 CPU 超时回合数 |
| `forfeits` | 甲、乙的判负原因，没有则为 `null` |
| `cpus`、`log` | 甲、乙绑定的逻辑处理器编号，日志文件的路径 |
