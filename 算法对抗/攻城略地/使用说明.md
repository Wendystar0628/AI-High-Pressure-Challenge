# 本地使用

这个文件夹复制为 `数据\` 后可以独立使用。Python 仅使用标准库；编译器固定为 `C:\msys64\ucrt64\bin\g++.exe`。无需管理员权限、联网或安装包。请在自己的作答目录执行，缓存和日志都写在当前目录或你显式指定的位置。

```powershell
& 'C:\msys64\ucrt64\bin\g++.exe' -O2 -std=c++20 -I数据 -o sample_bot.exe 数据\main.cpp 数据\sample_bot.cpp
& 'C:\msys64\ucrt64\bin\g++.exe' -O2 -std=c++20 -I数据 -o bot.exe 数据\main.cpp bot.cpp
python 数据\arena.py .\bot.exe .\sample_bot.exe --seeds 1-20 --log-dir logs --report report.json
```

每个种子换边打两局。输出 `seats=A/B` 表示甲为第一个程序、乙为第二个；`seats=B/A` 表示反过来。`troops`、`max_cpu_ms` 均按甲/乙顺序。`winner` 是程序身份 A/B 或 draw，`turns` 是已结算回合数。首回合CPU上限为1000毫秒，最大值包含首回合。日志显示名可用 `--name-a 模型名 --name-b 第2档对手` 设置，默认使用可执行文件名。部队日志带 `total_distance` 总路程。交令墙钟从本方发送局面起算，仍为5秒；创建进程的系统等待另记首回合准备时间，不把另一方启动慢算成本方超时。

首次运行会在当前目录的 `.arena_cache\` 编译 `engine_bridge.exe` 并校准所用逻辑处理器的周期换算系数，保存在 `.arena_cache\cycles.json`。以后固定读取这个系数。更换电脑后应执行 `python 数据\arena.py --calibrate --cpus 0-1` 重新测量；`--calibration 路径` 可以显式选择系数文件。校准用三个约 500 毫秒的忙循环，以 `GetProcessTimes` 的用户态加内核态 CPU 时间为参照，取“周期数/CPU毫秒”的中位数。

默认一次打一局，双方各绑当前进程可用的前两个逻辑处理器。可以用 `--cpus 0-15 --jobs 8` 同时打 8 局，每个进程独占一个逻辑处理器；CPU 数量至少为并行局数两倍，不允许重复。`--cpus` 请只在性能核 0–15 里选：能效核 16–27 上同样的程序耗时更长，和正式评分不一致。`--build-dir 路径` 改变编译缓存位置；`--time-scale 10` 仅供开发时放宽 CPU 时限，正式时限使用默认值 1，墙钟仍为 5 秒。

`referee_core.py`、`winproc.py` 和 `engine_bridge.cpp` 是 `arena.py` 的配套文件，请保持在同一文件夹。桥接程序直接包含本文件夹的 `engine.hpp`，逐回合结算与选手可调用的 `step()` 共用实现。进程会在执行第一条用户指令前绑核并加入 1 GB 内存限制的 Windows Job Object。

地图可单独生成：`python 数据\mapgen.py 100000 --output map.json`。相同整数种子总是生成同一张地图，不依赖 Python 的随机库版本。
